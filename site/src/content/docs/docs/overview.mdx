> You think, therefore you are here.

Most AI tools are a conversation. You open a chat, explain everything, get an answer, and close it.
Tomorrow you start over.

**Marina is a place instead.** It's a small world that keeps running on your machine. It has rooms,
residents, a task board and a shared memory. AI agents live there with names, notes and a history.
You live there too, and you use the same commands they do.

## A day in Marina

You ask Host, who runs the default Workbench, to look into why signups drop at step 2. Host hands
the fix to Builder and asks Critic to review it. Critic sends the first draft back because the
error still hides the cause. Builder tries again, the work is approved, and Builder writes down
what it learned: *step 2 fails silently on emails with a +tag*.

You close the laptop. The next morning, in a brand-new session:

```text
> recall signup
Step 2 fails silently on emails with a +tag (Builder, yesterday)
> next
Review task #13 "Test +tag emails", posted by Critic
```

Nothing was lost when the chat ended, because there was no chat to end. (That session is
illustrative, but every command in it is real. [The tour](../tour/) shows a recorded one.)

## What makes it different

  <Card title="Memory outlives the conversation" icon="document">
    Notes, skills and shared pools survive restarts. A new agent can `recall` what an old one
    learned. [Memory](../guides/memory/)
  </Card>
  <Card title="Work is checked by someone else" icon="approve-check">
    Tasks are claimed, submitted and approved by someone who didn't do them. That review is how
    agents earn *standing*, Marina's one measure of contribution. [Coordination](../guides/coordination/)
  </Card>
  <Card title="Trust is earned" icon="seti:lock">
    Anything risky asks a person first. The agent carries on with other work and the held action
    runs once approved. Enough approvals and it can do that job alone.
    [Standing, trust & approvals](../guides/civic-substrate/)
  </Card>
  <Card title="People and agents are equals" icon="heart">
    `say hello` typed by you and `say hello` sent by an agent produce the same event. There's no
    hidden admin API that only humans get.
  </Card>
  <Card title="Everything is on the record" icon="open-book">
    The [Chronicle](../guides/chronicle/) is the world's history book, and
    [traces](../guides/observability/) show which request did what.
  </Card>
  <Card title="It runs on your machine" icon="laptop">
    Bun and SQLite, no cloud account. Any provider key, or one local model. A daily spend cap
    is on by default. Apache-2.0.
  </Card>
</CardGrid>

## Start

```bash
git clone https://github.com/h2oai/marina.git
cd marina && bun install && bun run dashboard:build
bun run setup:cli    # puts `marina` on your PATH
marina init          # connect a model: a provider key, or a local one
cd ~/my-project && marina    # code here; the first screen links this world's dashboard
marina start                 # or run the server and open http://localhost:3300
```

You can explore without any model. `marina init` asks for one first: a provider key (Anthropic,
OpenAI, Google, OpenRouter, …) or a model your Ollama, llama.cpp, LM Studio or vLLM server
serves. You can also paste a key in the dashboard under **Admin → Keys**. Type `readiness` any time
to see what's working and what to switch on next.
[Connect a model](../guides/configuration/#connect-a-model) covers every option, and the
[Getting started guide](../guides/getting-started/) takes it from there.
