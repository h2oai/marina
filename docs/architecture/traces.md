# Execution Traces and Adaptive Routing

**When to read this:** you are emitting or consuming trace spans, changing the `trace` command or `/api/traces`, the judgments ledger, OTLP export, or the adaptive load-balance strategy. `CLAUDE.md` → "Execution Traces & Adaptive Routing" states the invariants; this page is the full coverage map.

- **Causal tracing end-to-end**: model-API requests mint `{runId, traceId, spanId}` (`requestTrace()` in `src/net/model-api.ts`) embedded in `model_request` payloads and emitted as `model_request_lifecycle` events (received/routed/completed/failed). `LeanAgentAdapter` extracts one unambiguous trace parent per prompt (and links every other request it serves — see span links below); `AgentExecutionTracer` (`src/agent/execution-trace.ts`) stamps `agent_turn_start/end`, `agent_tool_call/result` with `runId/traceId/spanId/parentSpanId` (optional fields on the `EngineEvent` union in `src/types.ts`). Events persist in the existing `event_log`; `projectTraces` (`src/engine/trace-projection.ts`) rebuilds span trees for every consumer.
- **Span links (2026-10-02)**: a span may serve more requests than its parent, so agent spans carry optional `links: [{ traceId, spanId }]` (OpenTelemetry-style; `TraceLink` in `src/types.ts`). A link is never a parent: `projectTraces` keeps the span in its own trace's tree and only lists `links` on it.
  - **One prompt, several requests:** a prompt built from several traced perceptions has no parent (`unambiguousTraceParent`), but links every one of them (`traceLinksFor`).
  - **Steered mid-run:** a request steered into a running prompt (priority ≥ 80) is linked to the turns that follow. It is marked delivered, so it never becomes the next prompt's parent.
  - **Handoffs:** while a prompt runs, the adapter's commands carry its traces (`trace_links` on the WebSocket command, `MarinaClient.setTraceLinksProvider`). The command executes inside `runWithTraceLinks` (`src/engine/trace-context.ts`), and every perception it delivers to ANOTHER entity — a tell, a crew post, a task notice — is stamped with `data.traceLinks` in `ConnectionManager.sendToEntity`. The recipient's prompt links them in turn, so propagation is transitive.
  - **Bounded claims:** an entity may only propagate a trace Marina delivered to it, either a `model_request` carrying it or a perception already stamped with it (512 most recent per entity). A forged link is dropped, and untrusted (gateway-relayed) content never seeds a link.
  - **Consumers:** benchmark participant attribution reads the links (`getTurnEndsLinkingTraceIds`; see [Persistence](persistence.md) → participants). OTLP export and `trace show` stay per-trace.
- **Coverage**: single-agent routing (`/v1/chat/completions` agents mode, `/v1/responses`, Ollama routes), the verified fast path, and open/panel fan-out (per-target spans under one shared trace). Passthru mode, passthru fallbacks, and inbound `/v1/messages` (Anthropic Messages) all emit `received/routed/completed/failed` spans, tagged with the resolved passthru `entityId` for per-identity attribution. Every response returns its traced id in `x-request-id` — the id for `trace show <id>`.
- **`trace` command** (rank 0): `list/find/show/stats/compare/dataset [verify]/advise/eval/judge/judgments/otel`. `trace dataset verify` round-trips the eval-json export and replays `replayTraceDataset`, reporting schema validity + counts + drift. `GET /api/traces` (authenticated) supports bounded filters, stable cursor pagination, and formats `native`, `eval-json` (`marina.trace.dataset.v1`), and `otlp-json`. Opt-in OTLP/HTTP JSON collector push is isolated from execution and reports delivery health through `trace otel` and the dashboard. Dashboard Admin → Traces tab (`dashboard/src/components/TraceExplorer.tsx`).
- **Prompt-budget metrics on turns (2026-09-22)**: `agent_turn_start` may carry `promptBytes`, `promptSections: [{ name, bytes, deferred }]` (assembly order; `deferred` = re-queued past `CONTINUATION_PROMPT_BUDGET_BYTES`, never dropped), `systemPromptBytes` and `residentSchemaBytes` — sizes only, never text. `projectTraces` copies them onto the `agent_turn` span attributes (`promptSections` as compact JSON, the rest as numbers). `analyzeTraces` adds `promptTurnsSampled` and `promptSections: [{ name, turns, meanBytes, p95Bytes, deferralRate, share }]` (`aggregatePromptSections` in `trace-analytics.ts`): byte statistics cover the appearances that reached the prompt (non-deferred — a deferred section's size is what it would have cost), `deferralRate` counts every appearance, `share` divides by the window's total prompt bytes (`promptBytes` per turn, else that turn's sent section bytes), largest share first. `trace stats` prints a "Prompt sections" block; `trace show <id>` lists a turn's sections (`name=bytes [deferred]`) with the fixed system/schema sizes. The same aggregate over the last 24 h of the event log is `prompt.sections` + `prompt.turnsSampled` on `GET /api/ops/overview`, scoped like the agent rows, and the Admin → Traces span card renders the per-turn list under a turn.
- **Judgments ledger**: migration 71 `trace_judgments` — append-only human/agent verdicts on traces (`trace judge`), surfaced in `/api/traces` and the command.
- **Adaptive routing** (opt-in): load-balance strategy `adaptive` (`X-Load-Balance` header on single-agent routes, else the operator-configured endpoint strategy) selects route targets from trace mechanics via `adviseTraceRouting` (`src/engine/trace-routing-advice.ts`, weight-free shadow advice); falls back to least-busy on insufficient evidence. The routing hot path skips judgment fetches by design.
- **Benchmark evidence** (`trace advise evidence <benchmark[,benchmark]> [min-n] [role:<role>]`): measured accuracy per model and per participant from the benchmark ledger (`benchmark_items`), with n, the Wilson 95 % interval and cost per item, ranked by lower bound. It also shows the routing objective (`MARINA_ROUTE_EVIDENCE_OBJECTIVE=lcb|value|budget`) with its tolerance or budget, the evidence level used (role, else model), and why each candidate was picked, rejected or ineligible.
  - **Counted:** only traced attribution (the agent whose turns carry the item's request trace) and direct-model runs. Window evidence counts only with `MARINA_ROUTE_EVIDENCE_WINDOW=true`, and shared evidence never.
  - **Routing:** shows what the configured `model:route` candidates would pick. The same evidence feeds spawn-time routing: recorded under `MARINA_ROUTE_EVIDENCE=observe` (the default), applied only under `on` (see decisions.md).
