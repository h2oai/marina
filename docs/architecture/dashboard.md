# Dashboard Live-Visualization Stack, Canvas Intents, and Memory Observability

**When to read this:** you are changing the dashboard's live layers (WORLD/CANVAS/GRAPH/FEED/MEMORY), the WebSocket event taxonomy that feeds them, the canvas intent system, the Admin → Memory tab, or the `/api/memory/*` observability API. `CLAUDE.md` → "Dashboard, Canvas, and Memory Observability" states the invariants; this page is the implementation reference. The user-facing walkthrough (what you see, layouts, web chat, log viewer, the "Memory Observability API" route table) is [`docs/guides/dashboard.md`](../guides/dashboard.md) — link to it rather than duplicating route tables here.

## Canvas intent system
- **Intents**: work requests attached to canvas nodes — humans set them (double-click node in dashboard), agents discover and fulfill
- **Lifecycle**: pending → active (claimed) → done/failed. Active intents timeout after 5 min back to pending
- **Agent commands**: `canvas intent list [canvas]`, `canvas intent claim <node_id>`, `canvas intent complete <node_id> [--type <type>] <result>`, `canvas intent complete-rich <node_id> <a2ui_json>`, `canvas intent fail <node_id> [reason]`
- **Discovery**: brief compass shows "N pending intents", `brief full` lists actual intents, `canvas-watcher` trait in general role
- **Conversations**: every node supports threaded dialogue — messages create child nodes with edges, agents reply via `canvas publish text <asset> <canvas> reply:<node_id>`
- **Feed**: intent lifecycle events auto-publish to the feed canvas via `FeedPublisher`
- **Frontend**: IntentBadge (status overlay), NodeActionBar (hover wand icon), ContextMenu (right-click), SearchBar intent filter, dynamic edge colors (emerald=intent result, violet=conversation, cyan=default)
- Intent data is stored in the node's `data` JSON field as `{ intent: { prompt, status, claimedBy?, claimedAt?, result?, failReason? } }` — no schema changes needed

## Live-visualization stack (Phases 0-8)
- **WebSocket event taxonomy** (src/types.ts `EngineEvent` union): `note_created`, `note_deleted`, `note_link_created`, `note_link_deleted`, `recall_trace`, `feed_event`, `canvas_edge_created`, `canvas_edge_deleted`. Every mutation at the DB write site emits one; dashboard stores subscribe via `use-graph-state`, `use-feed-state`, and the world-state eventFeed.
- **New tables**: `feed_events` (migration 34, trimmed 7-day on startup) and `canvas_edges` (migration 35, first-class typed edges with UNIQUE(canvas, source, target, relationship)).
- **New commands**: `feed`, `canvas visit <self|entity|name>`, `canvas connect/disconnect/edges`, `note unlink`, `market forecast`. All additive — no command-space expansion beyond these.
- **New dashboard overlays** (dashboard/src/unified/): `GraphNoteNode`, `GraphLinkEdge`, `TimelineStrip`, `Legend`, `WelcomeTour`, `EdgeContextMenu`, force-directed note layout.
- **Layer toggles**: WORLD/CANVAS/GRAPH/FEED/MEMORY chips top-left, keys 1-5 from anywhere, shift-click/shift-key to solo (`applyLayerKey`). Per-layer state persists in localStorage (`uc:hide-memory` for the fifth); all layers default visible.

## MEMORY layer, Admin → Memory tab, and the memory observability API
- **MEMORY layer (key 5, 2026-09-14)** (`dashboard/src/unified/lib/memory-map-*.ts`, `hooks/use-memory-map.ts`, `nodes/MemoryMapNode.tsx`, `edges/MemoryMapEdge.tsx`, `panels/MemoryContext.tsx`): overlays the GRAPH layer's legacy notes with the durable side and the curator loop from `GET /api/memory/graph?entity=` — `record` hexagons docked beside their twin note, `job` rings colored by state (pending amber / running cyan / answered emerald / abstained slate / cancelled rose) with role letter, H/A/S marker badge and a remaining-ops arc driven by a motion value, dashed `proposal` that turns solid on adoption (`layoutId` hand-off), `resolution` diamonds (LWW/EVW/WAIT/BOTH; `resolves` to the winner, `superseded_by` drawn as a closed interval from losers), institutional `space` hulls with `in_space` membership bands, `helper` discs orbiting the space they serve. Layout is deterministic (FNV-hashed angles, order-independent): twins pinned, jobs ring their requester's notes, spaces are peripheral gravity wells. Live: the layer attaches its own listener to the dashboard `wsRef` (use-websocket only routes the `event` envelope) — `memory_job` events patch node state in place with a pulse; `memory_service_event` kinds `memory.resolved|assistance.adopted|memory.created` trigger a ≥ 2 s debounced refetch. Legend has a MEMORY tab with the glyphs, job states, memory edges and the five unified tier colors. The inspector's only action dispatches the cancelable `marina:open-admin` window event (`detail: { tab: "memory", jobId?|recordId?|spaceId?|resolutionId? }`); receivers `preventDefault()` to claim it (both the grid `AdminPanel` and the unified `CommandBar` Memory tab do), otherwise the inspector shows an inline hint.
- **Admin → Memory tab** (`dashboard/src/components/MemoryOpsTab.tsx` + `memory-ops/`; also the `Memory` admin tab of the unified `CommandBar`): seven GlassPanel sections — Posture (trust profile chip, autonomy, cache hit rate, 24 h dispatch counts, open jobs), Jobs (live table: state chip, role, marker badge, worker → requester, space, age, remaining ops / deadline countdown, citations, adopted badge; expand for task + answer when scoped in; Cancel = optimistic POST then reconcile; filters; cursor paging; `focusJobId` deep link pins and expands a job by id), Resolutions & ratifications, Standing credits, Receipts (tier bars by bytes; "open trace" routes to the Traces tab), Hygiene (parsed `[hygiene]` mini-stats), Institutional spaces. Overview refreshes via `useInvalidateOnEvent` (2 s debounce) on `memory_job` and the three service-event kinds; jobs patch in place from `useWorldState.eventFeed`. Section headers deliberately do NOT use the GlassPanel `title` prop (that header is the react-grid-layout drag handle). `TraceExplorer` renders a Memory block from a span's `attributes.memoryReceipt`.
- **Memory observability API** (`src/net/memory-observability.ts`, contract `src/net/memory-observability-types.ts`, re-exported type-only — not mirrored — by `dashboard/src/lib/memory-observability-types.ts` and `dashboard/src/unified/lib/memory-map-types.ts`, with `dashboard/src/__tests__/memory-observability-contract.test.ts` pinning the derived aliases and visual vocabulary): `GET /api/memory/overview|jobs|jobs/:id|graph`, `POST /api/memory/jobs/:id/cancel` (runs `assist_cancel` through the REQUESTER's resident binding so the repo's owner check and audit event stay authoritative; refuses the dev-open sentinel). Scoping is server-side via `memoryObserverScope` (privileged = operator / sovereign / desktop token / `MARINA_OPEN_API`; a resident sees only jobs it requested or works, its own credits/receipts/hygiene, and legacy notes the access predicate allows; institutional previews ≤ 160 chars are public). Live: `pollMemoryEvents(engine)` runs from the engine tick about every 2 s (`seq > lastSeq LIMIT 200` on `memory_service_events`, sync, primes the cursor on first call) and emits `EngineEvent`s `memory_job` (a `MemoryJobView` WITHOUT task/answer/citations) and `memory_service_event` (kind/ids/names/seq only); `dashboard-ws` broadcasts both to every authenticated client, bypassing the per-principal `memoryObserver().event()` default because they carry no content — content is always fetched per-principal over REST. `response-cache.ts` exports `responseCacheCounters` for the overview. **Continuous-hygiene ratios** (`src/memory/hygiene-ratios.ts`, `MemoryOverview.ratios`, also alone at `GET /api/memory/hygiene`; Admin → Memory "Continuous hygiene" section): redundancy (exact case-folded duplicates across fact-like legacy notes + active records, twins excluded), contradiction rate (competing now ∪ settled in window / claimed records — uses the exported `COMPETING_RECORD_PREDICATE` from db-memory-review.ts so it counts exactly what `review kind:competing` shows), unresolved-contradiction rate, provenance coverage (records/notes with ≥1 EVIDENCE source — the same self-derived exclusion as `evidence_weighted`: `legacy-notes` captures, assistance envelopes, `marina-memory://`), staleness, unsafe-served rate (receipts in the window that cited a record superseded / forgotten / past `valid_until` / below its then-current version at serve time), reflection repetition, consolidation ROI (inputs per adopted reflector lesson — an average), repair success (hygiene/shared-write-review evaluator jobs answered AND followed by an adoption or resolution / final-state jobs), leakage (`memoryLeakageCounters.crossScopeAttempts` — refused cross-scope job reads/cancels; cache cross-hits are 0 by construction), storage vs admission budget per owner (`memoryStorageUsage`; `null` limit = unlimited under `local`), cost (receipts, avg injected bytes, cache hit rate). Every ratio carries numerator/denominator; 0/0 ⇒ `value: null` rendered "n/a". Window 24 h; memoized 30 s per scope (`resetMemoryHygieneRatiosMemoForTests`). **History (migration 115 `memory_hygiene_snapshots`)**: the hourly hygiene run (`runEngineMemoryHygiene`, phase 2700) records one `scope=all` snapshot (`recordHygieneSnapshot`, 30-day prune); `GET /api/memory/hygiene/history?hours=168|≤720` (privileged only) returns samples oldest→newest, `POST /api/memory/hygiene/snapshot` takes one now; the Memory tab draws inline-SVG sparklines under each ratio card. **Per-space health** (`computeSpaceHealth` → `MemoryOverview.spaces.shared`, `MemorySpaceHealth`): per institutional or multi-writer space — records, ratified, distinct writers, fresh writers (standing < `SYBIL_STANDING_FLOOR`) and their share, competing records (same predicate as `review kind:competing`), resolutions 24 h, unresolved-contradiction rate, last write; the dashboard flags freshWriterShare ≥ 0.5 with ≥ 3 writers as a Sybil-shaped signal. Guide: `docs/guides/dashboard.md` → "Memory Observability API".

## Tour, per-entity canvas, edge picker
- **Welcome tour**: ambient corner card, non-blocking, scoped per-instance via `uc:tour-seen:{instanceName}`. Replay link lives in the Legend panel.
- **Per-entity canvas**: every entity gets a workspace on first access via `canvas visit <name>`. Lazy-created with collision-safe naming (`"alice's canvas"` → id-qualified fallback).
- **Edge right-click picker**: change a typed edge's relationship or delete it; works on both graph links and canvas edges.

## Ops tab, header badges, theme, accessibility, performance (2026-09-22)

- **Admin → Ops** (`dashboard/src/components/ops/*`, fed by `useOpsOverview()` every 10 s and on `agent_*` events): Agents (tokens, cost total/last hour, consecutive errors, last error + age, pause reason/resume-in, next tick; Stop with cascade confirmation), Spend (caps vs last hour, per-agent bars), Retention (policy table, last pass counts, never-pruned list), Prompt budget (system prompt bytes vs cap, resident schema bytes per profile, deferred tools), Providers (last probe incl. tool-call ok), Security posture. The former alerts/readiness/productivity tab is `health`; `resolveAdminTab` maps `readiness`/`operations` → `health`.
- **Header**: `HealthBadge` (readiness ok/degraded/off with remediation popover → Admin readiness) and `SpendChip` (last-hour USD, red at ≥ 80 % of a cap → Admin → Ops). `EntityRoster`/`AgentLaunchPanel` show per-agent cost and paused badges.
- **Theme**: every theme declares `scheme`; a designed `light` theme (ground `#f4f6fa`, all text/accent tokens ≥ 4.5:1 on bg/card/hover, asserted in `theme-resolution.test.tsx`); `useTheme` keeps `choice` (`system` when never chosen) and resolves via `prefers-color-scheme` with a live listener; `ThemeSwitcher` has a System option and is a `listbox`.
- **Accessibility**: every icon-only button has an `aria-label` (glyphs `aria-hidden`); color-only dots carry `.visually-hidden` text; layer chips are a `toolbar` with `aria-pressed`; the help overlay is a labelled modal dialog; `:focus-visible` outline restored globally. `a11y-button-names.test.tsx` renders the large panels and fails on any unnamed button.
- **Performance**: `UnifiedCanvas` and `CommandBar` no longer subscribe reactively to `eventFeed` — `use-event-feed-bridge.ts` uses `getState()` + `subscribe` with rAF batching and ref comparison (a 25-event burst: 25 renders → 0, `event-feed-render-count.test.tsx`, plus a static fence). `LogExplorer` is windowed by `VirtualList`. `UnifiedCanvas` 2944 → 2589 lines (overlays in `unified/overlays/*`), `CommandBar` 3252 → 1057 (tabs in `unified/panels/command-bar/*`).
- **Single-sourced contracts**: `/who` types re-export `src/net/entity-profile-types.ts`; the orchestration pattern list comes from `GET /api/orchestration/patterns` (`src/net/orchestration-api.ts`, authenticated) with the hand-copied array kept only as a marked loading fallback.
