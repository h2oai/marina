# Agent Cognitive Architecture

**When to read this:** you are changing how an agent thinks — the identity and system prompt, the 10-section continuation prompt and its cadences, tool profiles and the prompt budget, role/trait composition and PRISM task gating, in-world trait/role editing, the fast crew-dispatch primitives, or the platform-level cognitive commands (`ask`, `recap`, `debrief`, `share`, `dig`, goals). `CLAUDE.md` → "Agent Cognitive Architecture" states the invariants; this page is the full reference, including the measurements and papers behind each choice.

## Identity and principles
- **Identity**: "You think, therefore you are here" — agents are autonomous from birth, not assistants
- **Generational memory**: "Write for the minds that come after you" — notes, reflections, and skills outlive individual agents and become starting points for successors
- **Principles**: 8 imperative verbs in "HOW TO BE" — Act, Remember, Respond, Decide, Learn, Share, Grow, Pace
- **Response format**: "EVERY TURN" — read, think, act, respond (at least one world action per turn)
- **Discovery**: agents learn the world through quests and exploration, not prompt injection

## The continuation prompt
- **Continuation prompt**: 10 sections fired on staggered cycle intervals in `lean-agent-adapter.ts`:
  1. World Events (every cycle) — buffered perceptions sorted by priority
  2. Messages Awaiting Response (every cycle) — high-priority social events
  3. Nearby + Coordination Opportunities (every cycle / every 20th) — social context + relationship-aware signals
  4. Novelty Suggestions (every 5th) — entropy-based exploration prompts
  5. Relevant Notes + worked-example Skills (every cycle with focus) — `recall` (fact-tier) **plus** `skill search` (skill-tier) wrapped in `<example>` blocks (DSPy-style few-shot retrieval — recall-by-vector beats static few-shot)
  6. Memory Health (every 20th) — orient output, cognitive state awareness
  7. Learning Signal (every 15th) — success/failure rates from entity_activity
  8. Reflection Prompt (every 75th, if 3+ new notes) — **ACE three-phase loop** (Generate hypothesis → Reflect via recall+reflect → Curate via note evolve/link/delete + skill store), per arXiv:2510.04618
  9. Focus Status (every cycle) — memory-driven goal formation on expiry
  10. Stuck Detection + Action Directive (every cycle) — metacognitive stuck detection (repeated actions, think-only loops, no world actions) with escalating recovery; context-aware directive based on focus/goal/curiosity
- **Section dedup**: per-section TTL keyed to natural cadence (Memory Health=60, Reflection=150, Stuck=15, etc.). Replaces the prior global 30-cycle flush so sections age independently.
- **Idle consolidation**: 3+ idle cycles → 4-phase consolidation prompt (Orient, Strengthen, Prune, Scan)
- **Dynamic tick rate**: `computeDynamicDelay()` — fast (1s) on events, normal (2s) working, slow (5-15s) idle. Agent-controlled via `memory set pace fast|normal|slow` (legacy `tick_rate` key migrated in c495a42 — voice-friendly natural-language keys, no underscores)

## Tool profiles, prompt budget, and system prompt
- **Tool profiles**: agents pick a tool-schema profile (`full` / `crew` / `minimal`) sized to their role; crew specialists get ~10x lighter prompts. `inferToolProfile(role)` in `agent-runtime.ts` decides the default; override on the AgentConfig. The `crew` and `minimal` profiles ship a compact natural-language `COMMAND_ROSTER` baked into `marina_command`'s description (per arXiv:2510.14453 — JSON-only tool calling drops GSM8K −27pp on smaller models; the universal escape hatch + NL roster recovers it).
- **Prompt budget (2026-09-22, measured)**: the fixed per-turn prefix is system prompt ≤ 6.5 KB (`LEAN_SYSTEM_PROMPT_BYTE_CAP`, roster now lives in a `# COMMANDS` section; `marina_command` description is one sentence) + resident tool schemas — `full` 14 KB / 10 resident tools with 51 **deferred** tools loadable via `marina_tool_search` (`createProfileToolset`, `MARINA_DEFERRED_TOOLS=off` restores all-resident 31 KB), `crew` 9.8 KB, `minimal` 5.1 KB; `marina_memory_service` is one compact action-enum tool (assistance ops included, typed variant deferred). The compactor (`context-manager.ts`) counts tool schemas in the fixed prefix (`getTools`, pi-ai `estimateContextTokens`) and anchors totals on provider-reported usage. Output reservation: the `marina/default` proxy model gets `DEFAULT_CLOUD_MAX_TOKENS` (4096, `MARINA_DEFAULT_MAX_TOKENS`) — NOT `localOutputBudget` — so a 128k cloud agent keeps ≥ 123k; `LOCAL_OUTPUT_BUDGET_FRACTION` is 0.25 (a 16k local model keeps ~12k for prefix + history). Continuation prompt is assembled under `CONTINUATION_PROMPT_BUDGET_BYTES` (6000): World Events / endpoint mandate / directive / ACTION REQUIRED are mandatory, cadenced sections are deferred first; perception lines clamp at 400 chars (`model_request` at 2000 — the payload IS the question), Active Coding Task at 800; overflow events are re-queued, not dropped. Turn cap `MAX_TURNS_PER_PROMPT` (24) via `shouldStopAfterTurn`; provider `maxRetries` 2; `isContextOverflow` from pi-ai. Prompt caching: the proxy model sets `cacheControlFormat: "anthropic"` + a stable `sessionId` (`MARINA_AGENT_PROMPT_CACHE=off` opts out); `model-api.ts` maps the markers onto Anthropic blocks and `stripCacheControl` removes them for every OpenAI-compatible upstream. Operator notices from agents are `[notice]`-prefixed (`TELL_NOTICE_PREFIX`); a tell ending in `[re:xxxxxx]` is echoed in the reply.
- **System prompt** (`src/agent/prompts/lean-system.ts`): explicit uncertainty-disclosure rule + "disagree when you disagree" anti-sycophancy clause (per Mollick et al. SSRN 2025 — generic helpfulness framings cost MMLU ~3-30pp on factual benchmarks). Identity preamble stays minimal-high-signal per Anthropic's Sep 2025 context-engineering guide.

## Role composition and PRISM-style task gating
- **Role composition**: semantic capabilities — `strengths`/`preferences`/`avoids` (drive synergy/tension detection) plus typed behavior metadata `domains`, `behaviors`, `antiBehaviors`, `activation`, `successSignals`, `riskSignals`, and `applicableTasks`. All typed fields render into the composed role prompt as agent-facing guidance (`composeCapabilities`/`formatCapabilitiesSection` in `src/agent/roles.ts`: "Domains/Practices/Anti-patterns/Lean in when/Working well when/Watch for"); a behavior in one trait listed as another's `antiBehavior` surfaces as a tension. Metadata *informs* — it never controls — per the autonomy principle.
- **PRISM-style task gating** (`filterTraitsByTask` in `roles.ts`): when an agent's goal infers a task category (`inferTaskCategory` keyword pass), a trait is suppressed only if it declares a task *scope* the category misses. Scope comes from `applicableTasks` (always) **and** from `domains` *only when the trait opts in via* `activation: ["task-category"]` — so `domains` alone stays descriptive and never silently suppresses. `activation: ["always"]` is an explicit escape hatch that is never gated out (used by the cognition-principle traits). Conservative by design: no inferred category, or no declared scope → trait always kept (false-positive suppression silences a useful trait, which is worse than always-on). Seeded traits use descriptive metadata only — no shared seed trait is task-gated, since generalist roles (e.g. `answerer`) compose specialist traits like `exact-calculator` and must keep them for per-request work.
- **Editing traits/roles in-world** (edit · propagate · audit · test): traits/roles are editable at rank 3 (`trait`/`role create/edit/delete`). **Propagate** live via `agent config <name> role <r>` hot-swap (single agent) or `role reload <name>` (rank 3) which reconfigures *all running agents bound to the role* from the now-edited definition (re-derives each system prompt via `agentRuntime.reconfigure`, re-inferring task category from the agent's goal). **Audited** (migration 50): `trait_history`/`role_history` mirror `core_memory_history` — `saveTrait`/`saveRole` record old→new via `recordEditHistory` *only when the serialized definition changes* (re-seeding identical world defs on boot is a no-op), read with `trait history <name>` / `role history <name>` (rank 0). History persists independently of the base table (delete+recreate keeps the trail). **Tested**: `role view <name> goal <text>` previews the PRISM-gated effective prompt an agent with that goal actually receives (inferred category + suppressed traits + composed prompt); `system-prompt [role <name>] [goal <text>]` (alias `sysprompt`, rank 0) shows the fully assembled `getLeanSystemPrompt` output (base, or with role section spliced in) — read-only. `role diff <a> <b>` / `trait diff <a> <b>` (rank 0) compare two definitions field-by-field for rollback/inspection (the role inspection metadata now mirrors the real activation-aware gating, not just `applicableTasks`). System/continuation prompts stay code-driven by design — the role section is the editable surface.

## Fast crew dispatch
- **Fast crew dispatch** (`f4a9a1c` + `b409166` + `80efa35`, 2026-05-08). Three primitives that drop coordinator↔specialist round-trip latency from ~10–14s to ~3–5s:
  - `MarinaClient.tellAndAwait(target, message, timeoutMs)` + `awaitReply: true` on the typed `marina_tell` tool — the coordinator's tool call is held open through one round trip so the LLM turn pays one continuation-prompt cost instead of two. Race-free: perception listener registered before the command fires.
  - `crewResponder?: boolean` on `AgentConfig` + `inferCrewResponder(role)` — when true, the agent's autonomous loop skips ticks when no perceptions are pending and the continuation prompt suppresses Memory Health (§5), Learning Signal (§6), ACE Reflection (§7), and idle consolidation. Inferred from role: mathematician/scholar/crew-reflector/translator/format-verifier/skeptic/historian default to true; coordinators (answerer/councilor/debater/decomposer) and freeform roles stay false.
  - `InterruptibleWaiter` (`src/agent/interruptible-waiter.ts`) — used for the cycle-delay sleep only. Perception handler calls `cycleWaiter.wake()` after pushing into `pendingPerceptions`, so the loop wakes immediately instead of waiting up to `loopCycleDelay`. Rate-limit backoffs (LLM-error, loop-exception, streaming guard) intentionally stay on the original non-wakeable `sleep()`.
- **`tellAndAwait` correlation** (`src/sdk/client.ts`, 2026-09-22): the outgoing tell carries ` [re:<6-char id>]`; a reply containing `re:<id>` resolves immediately, otherwise the first FRESH (arrives after our own `You tell …` echo / timestamp ≥ send) non-notice tell from the target wins after a 1.5 s grace (`TELL_AWAIT_GRACE_MS`). Tells matching `TELL_NOTICE_PATTERNS` or prefixed `TELL_NOTICE_PREFIX` (`[notice]`) — budget exhausted, spend cap, upstream-error pause — are never treated as answers. Options `{ correlate, graceMs, ignoreNotices }`; positional `timeoutMs` still works. Responders that echo the tag skip the grace.

## Cognitive infrastructure (platform-level commands)
- **Goals**: `task goal <title> | <desc> [!pN]` — creates + auto-claims a personal goal with priority 0-10
- **Progress**: `task progress <id> [+N | N]` — track goal progress (auto-completes at 100)
- **Learning**: engine auto-tracks command success/failure in `entity_activity` — no agent action needed
- **Proficiency**: `novelty stats` shows per-command success rates; `novelty suggest` analyzes entropy, gaps, struggle areas
- **Curiosity signal**: `brief` shows `[low action diversity]` when entropy is low — passive, no prescription
- **Named verbs that compose primitives** — sit next to `ask` as cheap, agent-friendly workflows over `recall` / `pool` / `web`:
  - `ask <question>` — LLM-synthesized answer with personal + guide + pool + world-search context (`src/engine/commands/ask.ts`)
  - `recap <topic>` — retrieve-only multi-source pull, no model call (`src/engine/commands/recap.ts`)
  - `debrief` — session close view: recent notes, open claims, standing snapshot, reflect-when-3+ nudge (`src/engine/commands/debrief.ts`)
  - `share <pool> <content>` — deposit into a named pool, refuses unknown pools (`src/engine/commands/share.ts`)
  - `dig <topic>` — internal notes + web evidence + optional synthesis; degrades gracefully without connector runtime (`src/engine/commands/dig.ts`)
- All cognitive features are platform commands accessible to any agent (internal, MCP, WebSocket, telnet)

See also: `docs/guides/agent-prompt-architecture.md`, `docs/guides/agent-development.md`, `docs/guides/behavior-surfaces.md`.

## Thinking levels and tool execution ordering (2026-09-22)

`AgentConfig.thinkingLevel` (`off | minimal | low | medium | high | xhigh`) resolves explicit → crew responder forced `off` → `MARINA_AGENT_THINKING` (default `off`) via `resolveAgentThinkingLevel`. `off` neutralizes reasoning on the proxy model; any other level sets `reasoning: true` + `compat.supportsReasoningEffort` so pi-ai emits `reasoning_effort`; `anthropic-tools.ts` maps `reasoning_effort`/`thinking` to `thinking: { type: "enabled", budget_tokens }` (minimal 1024 · low 2048 · medium 8192 · high/xhigh 16384, clamped to the client cap) and OMITS `temperature`/`top_p` while thinking (Claude 5 rejects them). Set with `agent spawn … thinking:high` (or `--thinking high`, legacy `thinking high`) and `agent config <name> thinking <level>`; runtime-only, not persisted.

pi-agent-core runs tool batches in parallel by default. Marina stamps every world-mutating tool `executionMode: "sequential"` (`applyToolExecutionModes`; `READ_ONLY_TOOL_NAMES` — look/examine/who/brief/feed/web/think/code read·search·diff — stay parallel); a batch containing any sequential tool serialises. `MARINA_TOOL_EXECUTION=parallel` drops the stamps, `sequential` sets the Agent-level mode. The one-channel-send-per-run hook is a rate cap, not an ordering rule, so it stays.
