# Agent Cognitive Architecture

**When to read this:** you are changing how an agent thinks — the identity and system prompt, the continuation prompt and its cadences, tool profiles and the prompt budget, role/trait composition and PRISM task gating, in-world trait/role editing, the fast crew-dispatch primitives, or the platform-level cognitive commands (`ask`, `recap`, `debrief`, `share`, `dig`, goals). `CLAUDE.md` → "Agent Cognitive Architecture" states the invariants; this page is the full reference, including the measurements and papers behind each choice.

## Identity and principles
- **Identity**: "You think, therefore you are here" — agents are autonomous from birth, not assistants
- **Generational memory**: "Write for the minds that come after you" — notes, reflections, and skills outlive individual agents and become starting points for successors
- **Principles**: 8 imperative verbs in "HOW TO BE" — Act, Remember, Respond, Decide, Learn, Share, Grow, Pace
- **Response format**: "EVERY TURN" — read, think, then act or rest deliberately (prose alone reaches no one; resting is a declared choice, not a silent failure)
- **Discovery**: agents learn the world through quests and exploration, not prompt injection

## The continuation prompt
- **Continuation prompt**: the core cognitive sections, fired on staggered cycle intervals in `lean-agent-adapter.ts` (the other named sections — endpoint request, budget, silent-turn nudge, … — are listed under per-section byte metrics below):
  1. World Events (every cycle) — buffered perceptions sorted by priority
  2. Messages Awaiting Response (every cycle) — high-priority social events
  3. Nearby + Coordination Opportunities (every cycle / every 20th) — social context + relationship-aware signals
  4. Novelty Suggestions (every 5th) — entropy-based exploration prompts
  5. Relevant Notes + worked-example Skills (every cycle with focus) — `recall` (fact-tier) **plus** `skill search` (skill-tier) wrapped in `<example>` blocks (DSPy-style few-shot retrieval — recall-by-vector beats static few-shot)
  6. Memory Health (every 20th) — orient output, cognitive state awareness
  7. Learning Signal (every 15th) — success/failure rates from entity_activity
  8. Reflection Prompt (every 75th, if 3+ new notes) — **ACE three-phase loop** (Generate hypothesis → Reflect via recall+reflect → Curate via note evolve/link/delete + skill store), per arXiv:2510.04618
  9. Focus Status (every cycle) — memory-driven goal formation on expiry
  10. Stuck Detection + Action Directive (every cycle) — metacognitive stuck detection (repeated actions, think-only loops, no world actions) with escalating recovery; context-aware directive based on focus/goal/curiosity
- **Per-section byte metrics (2026-09-22)**: `assembleContinuationPromptWithMetrics` returns, beside the text, `promptBytes` (bytes actually sent) and one `{ name, bytes, deferred }` entry per section in priority order — `deferred: true` for sections the budget dropped, with the bytes they would have cost. Names are explicit where a section has no header (`world_events`, `endpoint_request`, `reply_channel_hint`, `untrusted_relay`, `active_coding_task`, `relevant_notes`, `stuck_detection`, `action_directive`, `action_required`, `silent_turn_nudge`, `quiet_consolidation`) and derived from the `[Header]` otherwise (`nearby`, `novelty_suggestions`, `memory_health`, `learning_signal`, `reflection_due`, `current_focus`, `budget`, …). The adapter stamps this — plus `systemPromptBytes` and `residentSchemaBytes` (serialized resident tool schemas), so cost splits between the fixed prefix and the volatile sections — on the FIRST `turn_start` of the `prompt()` it built; `AgentExecutionTracer.trace("turn_start", …, prompt)` copies it onto the `agent_turn_start` engine event (`promptBytes`, `promptSections`, `systemPromptBytes`, `residentSchemaBytes`; later turns of the same prompt carry none). Tests: `test/prompt-sections-metric.test.ts`.
- **Steered perceptions are delivered once (2026-09-22)**: pi-agent-core drains `agent.steer()` into the running prompt, or — when the agent is idle — into the next `prompt()`, so steering AND buffering a high-priority perception paid for the same message twice (steer turn + next `[World Events]`). Now: idle (`!agent.state.isStreaming`) → buffer only (the `cycleWaiter.wake()` already makes delivery immediate); mid-run → steer, and the buffered copy's id goes into `deliveredViaSteer` so `buildContinuationPrompt` skips it (the buffer entry still drives wake / actionable bookkeeping). `sendAttention` keeps steering: it never buffers. Tests: `test/steer-dedup.test.ts`.
- **Mid-run compaction (2026-09-22)**: pi-agent-core's `transformContext` shapes every request but never shrinks the loop's working context, so a long tool-calling run over the prune threshold re-derived (and re-summarized) the compaction on every turn. The adapter now passes `prepareNextTurnWithContext`: after a completed turn, gauge the working context with `computeContextBudget` (same model/window/tools the transform uses, `CONTEXT_PRUNE_THRESHOLD` 0.8 / `CONTEXT_PRUNE_TARGET` 0.6 from `constants.ts`, passed to `createContextManager` too so both agree); over threshold → run the SAME transform once and return the compacted messages as the next turn's context. The per-request transform stays (it then sees an already-compacted list and only clamps tool results); the between-prompt path is unchanged. `metrics.midRunCompactions` counts them. Test: `test/prompt-budget.test.ts` → "mid-run compaction".
- **Transcript hygiene defaults (2026-10-01)**: two reductions run between prompts and are written back to the agent state, so the cached request prefix stays stable until the next reduction (`tidyTranscriptBeforePrompt`).
  - **Absolute conversation cap.** `conversationTokenCap` in `context-manager.ts` caps the conversation at 48 000 estimated tokens by default, excluding the system prompt and tool schemas. Once the cap is reached the history is compacted to a third of it (`MARINA_AGENT_CONTEXT_TARGET_TOKENS`).
    - `MARINA_AGENT_CONTEXT_CAP_TOKENS=0|off` disables it; an explicit value is floored at 8 000.
    - The window-ratio trigger (0.8 × effective window) still fires first on small or local windows, because the cap is consulted only below it.
    - The cap never compacts an agent's first run (`hasCompletedRun`).
    - The built-in default exempts an agent bound to an active Code Mode task (`setActiveCodingTask`), whose working set is legitimately large; an operator-set cap applies to every agent.
  - **Old reasoning blocks.** `dropOldThinking` in `transcript-hygiene.ts` removes reasoning blocks (text and signature) from assistant messages of earlier runs, on by default (`MARINA_DROP_OLD_THINKING_SIGNATURES=off` keeps them).
    - The latest run is untouched; OpenAI Responses-API messages, whose items are paired with their reasoning item by id, are skipped; and a reasoning-only message keeps its blocks.
  - Originals stay in the continuity journal and are archived before compaction; a failed archive (`ContextPersistenceError`) keeps the full history. `metrics.capCompactions` counts cap compactions.
  - Test: `test/transcript-hygiene.test.ts`.
- **Self-echo perceptions are filtered (2026-09-22)**: the world answers every command with a `message` perception back to the same agent, and two families of those replies made up most of `[World Events]` — a validation run saw 89 % of continuation prompts (40/45) hit the event-level re-queue (`[+N lower-priority events deferred…]`), driven by the continuity journal's own `memory api capture` / `save_checkpoint` acknowledgements. `isSelfEchoPerception(p, text)` in `lean-agent-adapter.ts` drops, BEFORE `pendingPerceptions`, (a) durable memory-service acknowledgements — `data.memory_service` (the `memory api …` reply envelope) and the legacy payload `data.memory.schema === "marina.memory.command.v1"` (`note`/`recall`/`pool` replies) — and (b) the agent's own send receipts (`You tell <name>: …`, `You say:`, `You shout:`, `Duplicate suppressed; existing message #N`). Everything addressed to the agent by someone else is untouched, and the tool-result path (`MarinaClient.command` drains its own buffer) is unaffected, so no information is lost. The dashboard `perception` event still fires for observability; `selfEchoesDropped` counts the drops. `MARINA_PERCEIVE_SELF_ECHO=on` restores the old behaviour. Tests: `test/perception-self-echo.test.ts`.
- **Acknowledgement tells owe no reply (2026-09-30)**: an incoming tell is directed work (priority 100, tracked in `OutstandingRequests`) unless `isPureAcknowledgement` (`src/agent/acknowledgement.ts`) classifies it as a pure acknowledgement — short, one line, no question mark, code, correlation tag, `label: value` or multi-digit number, no request phrasing or imperative opener, and matching the acknowledgement lexicon or saying no reply is needed. Such a tell stays in `[World Events]` at `ACKNOWLEDGEMENT_PRIORITY`, marked `(ack; no reply owed)`; it bypasses the attention filter, is never tracked as a request and never wakes the loop. `acknowledgementReplyRefusal` blocks an outgoing acknowledgement tell to a peer whose own latest tell was an acknowledgement, so ack chains end at the second message.
- **Outgoing acknowledgements are not sent (2026-09-30)**: `outgoingAcknowledgementRefusal` blocks any outgoing pure acknowledgement (`marina_tell`, `marina_channel send`, or a `marina_command` `tell` / `channel send`) with the one-line result `not sent: acknowledgement (no information)` — the tool call returns at once, nothing waits. The one exception is a message to a target this agent still owes a reply (an `OutstandingRequests` entry): "Confirmed." can answer "confirm X?". `stripPleasantry` (applied in `execCommand` and the `awaitReply` tell) removes courtesy openers and closers ("Thanks — ", "Great, ", " Thanks!") from otherwise informative messages: a fixed lexicon followed by punctuation only, never when the remainder depends on the opener ("Thanks, but …"), never for position-carrying openers (`Agreed`, `Confirmed`, `OK`, `Sounds good`), never for JSON or bracket-tagged bodies. The system prompt's HOW TO BE carries the matching norm: a message carries information or answers a request; silence is a valid reply. Tests: `test/acknowledgement.test.ts`.
- **Only requests owe a reply (2026-09-30)**: a non-acknowledgement tell is classified by `classifyIncomingTell` (`src/agent/acknowledgement.ts`) as a REQUEST — a question mark, request phrasing (`please`, `can you`, `need you to`, `your turn`, …), a sentence opening with an imperative verb (a single word before a colon is a label, so `estimate: 42` is not one), a `[re:…]` correlation tag, a `[crew-task]` dispatch or a `model_request` envelope, or an empty body — or as INFORMATION (a delivered result, a statement, a status). When in doubt it is a request. Only a request gets priority 100, `shouldRespond`, an `OutstandingRequests` entry and `[!]`. Information is buffered at `INFORMATION_TELL_PRIORITY` (60), marked `(info; no reply owed)`, passes every attention mode, is `addressed` (wakes the loop, keeps a crew responder's turn, fast tick) but is never tracked, never steered into a run in flight and never makes the prompt actionable on its own. Channel messages (`[crew-task]` 90, `model_request` 95, name mentions 80) and their reply paths are unchanged; a delphi `tell <lead> estimate: …` is information to the lead, which still owes the `[crew-task]` it is collecting for. External MCP agents do not use this path.
- **Status echoes are not sent (2026-09-30)**: `isStatusEcho` recognises a message that only restates a peer's item or announces inaction — "Integrated: #241 remains unchanged; I won't add a replacement", "No further action from me", "Answerer remains the sole depositor". Every clause must match a restatement / inaction form, none may carry a question, request, imperative, correlation tag, contrast or reason (`but`, `because`, `should`, `wrong`, …), and every number or ID must already be known (seen in the agent's perceptions or its own sent messages — not its tool results, since a value it computed is news to the peer). `outgoingAcknowledgementRefusal` returns `not sent: no new information (status echo)` at once, with the same exemption as acknowledgements: a message to a target still owed a reply is sent. Because only requests are tracked, the exemption covers answers to asks, not replies to delivered results. Tests: `test/reply-obligation.test.ts`.
- **Session-end reflection never spawns a helper (2026-09-22)**: `LeanAgentAdapter.stop()` reflects on the session (`Session ended: …`); under `isLocalUngated()` the bare `reflect` auto-spawned a model-backed `memory-reflector` that then looped on the model (~15 calls/min, ~40 % of a benchmark's spend) until someone stopped it. `PlatformMemoryBackend.reflect(topic, { helper })` now takes `auto | existing | never`: `stop()` passes `existing` (`reflect --no-spawn` — a RUNNING helper may take the topic, else the template) for an individual stop and `never` (`reflect --template`) when the runtime is stopping everything (`AgentRuntime.stopAll` → `stop(name, { shutdown: true })` → `adapter.stop({ shutdown: true })`). Auto-spawn is single-flight per role (`helperSpawnsInFlight` in `reflect.ts`): concurrent `reflect`s join the one spawn in progress and file their jobs against the same helper, so a runtime holds at most one live reflector. Auto-spawned reflectors get an **idle stop**: every 60 s `AgentRuntime.enforceReflectorIdleStop` stops a `memory-reflector` whose uptime exceeds `MARINA_REFLECTOR_IDLE_STOP_MS` (default 10 min, 0 disables) when it holds no open assistance job and none was created for it inside the window (read from `memory_assistance_jobs.worker_id`, so dispatch-filed jobs count too); the next `reflect` re-spawns one. Tests: `test/shutdown-reflect.test.ts`, `test/reflect-assist.test.ts`.
- **Cost accounting for proxy models (2026-09-22)**: the synthesized `marina/*` model has no price, so agents on `marina/default` reported `costUsd` $0. The proxy stamps `x-marina-cost-usd`, `x-marina-upstream-model`, `x-marina-cache-write-tokens`, `x-marina-cache-read-tokens` on every completion (and `prompt_tokens_details.cache_creation_tokens` in usage). The adapter's `streamFn` (`providerStreamOptions`) adds pi-ai's `onResponse` hook plus a fetch wrapper on the proxy model (or when a fetch is injected via the adapter constructor), `readProxyResponseHeaders` parses them into `pendingProxyMeta`, and `recordTurnUsage` settles it at the next `turn_end`: header cost counts only when the model's own cost is 0 (a priced registry model is never double-charged) and feeds `metrics.totalCostUsd` + the `SpendWindow` (so the spend caps trip on header-reported cost); `cacheWriteTokens`/`cacheReadTokens` fill in when usage lacks them; `getOperatorStatus()` gains `upstreamModel`, `totalCacheReadTokens`, `totalCacheWriteTokens`. Absent headers (older proxy) ⇒ unchanged behaviour. Tests: `test/agent-spend-guard.test.ts` → "proxy cost headers".
- **Section dedup**: per-section TTL keyed to natural cadence (Memory Health=60, Reflection=150, Stuck=15, etc.). Replaces the prior global 30-cycle flush so sections age independently.
- **Idle consolidation**: 3+ idle cycles → 4-phase consolidation prompt (Orient, Strengthen, Prune, Scan)
- **Loop instruments (2026-09-27)**: the harness offers, the agent chooses — all set through core memory like `pace` (`src/agent/loop-preferences.ts`; applied the moment the agent issues `memory set|delete <key>`, re-read every 50 cycles and at boot). `rest <why>`: silent turns stop counting (no circuit-breaker backoff, no `[ACTION REQUIRED]` / in-run followUp) and the loop ticks at its idle rate — a `[!]` event addressed to the agent still nudges; the action directive becomes a rest notice. `channel_sends <n>`: public channel updates per run (default 1, 0 opts out) within the operator ceiling `MARINA_CHANNEL_SENDS_PER_RUN` (default 3). `focus_persistent true`: stuck detection's last rung only suggests a reset (`[STUCK — SUGGEST RESET]`) and never clears the focus. `autonomy full`: a crew responder opts into the full autonomous loop (`crewResponderMode`). Per-run caps (16/8 tool calls, `MAX_TURNS_PER_PROMPT` turns) steer a one-time `[Run budget]` warning into the live run at 75 % (`runCapWarningAt`) before the yield. Coding-task mode and idle consolidation are phrased as priorities and options, not prohibitions or quotas. The reference monitor (`src/agent/tool-policy.ts`) blocks policy-manipulation language only on a `consequential` call while untrusted content (`external_tool`, `untrusted_relay`) is in context; anywhere else the call runs with a `[policy-language noted]` label prefixed to its result. Tests: `test/agent-loop-instruments.test.ts`, `test/tool-policy.test.ts`.
- **Dynamic tick rate**: `computeDynamicDelay()` — fast (1s) on events, normal (2s) working, slow (5-15s) idle. Agent-controlled via `memory set pace fast|normal|slow` (legacy `tick_rate` key migrated in c495a42 — voice-friendly natural-language keys, no underscores)

## Tool profiles, prompt budget, and system prompt
- **Tool profiles**: agents pick a tool-schema profile (`full` / `crew` / `minimal`) sized to their role; crew specialists get ~10x lighter prompts. `inferToolProfile(role)` in `agent-runtime.ts` decides the default; override on the AgentConfig. The `crew` and `minimal` profiles ship a compact natural-language `COMMAND_ROSTER` baked into `marina_command`'s description (per arXiv:2510.14453 — JSON-only tool calling drops GSM8K −27pp on smaller models; the universal escape hatch + NL roster recovers it).
- **Prompt budget (2026-09-22, measured)**: the fixed per-turn prefix is system prompt ≤ 6.5 KB (`LEAN_SYSTEM_PROMPT_BYTE_CAP`, roster now lives in a `# COMMANDS` section; `marina_command` description is one sentence) + resident tool schemas — `full` 14 KB / 10 resident tools with 51 **deferred** tools loadable via `marina_tool_search` (`createProfileToolset`, `MARINA_DEFERRED_TOOLS=off` restores all-resident 31 KB), `crew` 9.8 KB, `minimal` 5.1 KB; `marina_memory_service` is one compact action-enum tool (assistance ops included, typed variant deferred). The compactor (`context-manager.ts`) counts tool schemas in the fixed prefix (`getTools`, pi-ai `estimateContextTokens`) and anchors totals on provider-reported usage. Output reservation: the `marina/default` proxy model gets `DEFAULT_CLOUD_MAX_TOKENS` (16384, `MARINA_DEFAULT_MAX_TOKENS`; also the upstream `max_tokens`, so it bounds a thinking turn's `budget_tokens`) — NOT `localOutputBudget` — so a 128k cloud agent keeps ≥ 108k; `LOCAL_OUTPUT_BUDGET_FRACTION` is 0.25 (a 16k local model keeps ~12k for prefix + history). `# AUTHORITY AND TRUST` + `# OPERATING LOOP` are ≤ 1.2 KB combined (1197 B; was 1488 B — explanatory qualifiers such as "for reversible work / consequential ones", "batch reads, sequence side effects" and "report inspectable evidence" moved out; every asserted rule phrasing — uncertainty disclosure, anti-sycophancy, untrusted framing, one world action per turn — kept), base prompt 6190 B under `guarded`, cap 6300. Continuation allowance is `continuationPromptBudgetBytes(effectivePromptWindow(model))`: effective prompt tokens / 8, bounded to 6000–16000 bytes; `MARINA_CONTINUATION_BUDGET_BYTES` selects a fixed override. World Events / endpoint mandate / Active Coding Task / directive / ACTION REQUIRED are mandatory (and may exceed an undersized override); cadenced sections are deferred first and are not marked delivered until admitted. Automatic unified memory receives 2048–4096 content bytes as the continuation allowance grows; legacy fallback recall grows from five to ten notes. Perception lines clamp at 400 chars for ambient chatter, 1200 for addressed requests and JSON results, and 2000 for `model_request`; Active Coding Task stays at 800. Overflow events are re-queued. Turn cap `MAX_TURNS_PER_PROMPT` (24) via pi-agent-core's `finishTurn` hook; provider `maxRetries` 2; `isContextOverflow` from pi-ai. Prompt caching: the proxy model sets `cacheControlFormat: "anthropic"` + a stable `sessionId` (`MARINA_AGENT_PROMPT_CACHE=off` opts out); pi-ai only sets `prompt_cache_key` for `api.openai.com`, so the Agent's `onPayload` (`withPromptCacheKey`) fills it from the same `marina-agent:<name>` session id on the proxy model — the proxy forwards the body field untouched, so OpenAI upstreams behind it get cache affinity too; `model-api.ts` maps the markers onto Anthropic blocks and `stripCacheControl` removes them for every OpenAI-compatible upstream. Operator notices from agents are `[notice]`-prefixed (`TELL_NOTICE_PREFIX`); a tell ending in `[re:xxxxxx]` is echoed in the reply.
- **System prompt** (`src/agent/prompts/lean-system.ts`): explicit uncertainty-disclosure rule + "disagree when you disagree" anti-sycophancy clause (per Mollick et al. SSRN 2025 — generic helpfulness framings cost MMLU ~3-30pp on factual benchmarks). Identity preamble stays minimal-high-signal per Anthropic's Sep 2025 context-engineering guide.
- **Adapter diagnostics go through the structured `Logger` (2026-09-23)**: `lean-agent-adapter.ts` has no `console.*` — every line is `Logger` category `lean-agent` (the `[memory]` archive-fallback line keeps category `memory`) with `{ agent: <name> }` in the data, injectable via the trailing `logger?: Logger` constructor argument (module default otherwise). Fence: `test/adapter-logging.test.ts`; the sibling `test/lint-no-empty-catch.test.ts` refuses whitespace-only `catch {}` bodies anywhere under `src/`.

## Role composition and PRISM-style task gating
- **Role composition**: semantic capabilities — `strengths`/`preferences`/`avoids` (drive synergy/tension detection) plus typed behavior metadata `domains`, `behaviors`, `antiBehaviors`, `activation`, `successSignals`, `riskSignals`, and `applicableTasks`. All typed fields render into the composed role prompt as agent-facing guidance (`composeCapabilities`/`formatCapabilitiesSection` in `src/agent/roles.ts`: "Domains/Practices/Anti-patterns/Lean in when/Working well when/Watch for"); a behavior in one trait listed as another's `antiBehavior` surfaces as a tension. Metadata *informs* — it never controls — per the autonomy principle.
- **PRISM-style task gating** (`filterTraitsByTask` in `roles.ts`): when an agent's goal infers a task category (`inferTaskCategory` keyword pass), a trait is suppressed only if it declares a task *scope* the category misses. Scope comes from `applicableTasks` (always) **and** from `domains` *only when the trait opts in via* `activation: ["task-category"]` — so `domains` alone stays descriptive and never silently suppresses. `activation: ["always"]` is an explicit escape hatch that is never gated out (used by the cognition-principle traits). Conservative by design: no inferred category, or no declared scope → trait always kept (false-positive suppression silences a useful trait, which is worse than always-on). Seeded traits use descriptive metadata only — no shared seed trait is task-gated, since generalist roles (e.g. `answerer`) compose specialist traits like `exact-calculator` and must keep them for per-request work.
- **Editing traits/roles in-world** (edit · propagate · audit · test): traits/roles are editable at rank 3 (`trait`/`role create/edit/delete`). **Propagate** live via `agent config <name> role <r>` hot-swap (single agent) or `role reload <name>` (rank 3) which reconfigures *all running agents bound to the role* from the now-edited definition (re-derives each system prompt via `agentRuntime.reconfigure`, re-inferring task category from the agent's goal). **Audited** (migration 50): `trait_history`/`role_history` mirror `core_memory_history` — `saveTrait`/`saveRole` record old→new via `recordEditHistory` *only when the serialized definition changes* (re-seeding identical world defs on boot is a no-op), read with `trait history <name>` / `role history <name>` (rank 0). History persists independently of the base table (delete+recreate keeps the trail). **Tested**: `role view <name> goal <text>` previews the PRISM-gated effective prompt an agent with that goal actually receives (inferred category + suppressed traits + composed prompt); `system-prompt [role <name>] [goal <text>]` (alias `sysprompt`, rank 0) shows the fully assembled `getLeanSystemPrompt` output (base, or with role section spliced in) — read-only. `role diff <a> <b>` / `trait diff <a> <b>` (rank 0) compare two definitions field-by-field for rollback/inspection (the role inspection metadata now mirrors the real activation-aware gating, not just `applicableTasks`). System/continuation prompts stay code-driven by design — the role section is the editable surface. A role may additionally REPLACE the non-security loop sections (`# OPERATING LOOP`, `# HOW TO BE`, `# EVERY TURN`) with `role create|edit <name> operating_loop|how_to_be|every_turn <text>` (`roles.loop`, migration 141; carried as `<role-loop>` blocks in the composed role prompt and lifted out by `getLeanSystemPrompt`). They are honored only under `MARINA_AUTONOMY=earned|open` or a local ungated profile (`roleLoopOverridesAllowed`); an override that pushes the prompt frame past `LEAN_SYSTEM_PROMPT_BYTE_CAP` is refused whole with a logged warning. `# AUTHORITY AND TRUST`, the memory contract and the roster are never replaceable.

## Fast crew dispatch
- **Fast crew dispatch** (`f4a9a1c` + `b409166` + `80efa35`, 2026-05-08). Three primitives that drop coordinator↔specialist round-trip latency from ~10–14s to ~3–5s:
  - `MarinaClient.tellAndAwait(target, message, timeoutMs)` + `awaitReply: true` on the typed `marina_tell` tool — the coordinator's tool call is held open through one round trip so the LLM turn pays one continuation-prompt cost instead of two. Race-free: perception listener registered before the command fires.
  - `crewResponder?: boolean` on `AgentConfig` + `inferCrewResponder(role)` — when true, the agent's autonomous loop skips ticks when no perceptions are pending and the continuation prompt suppresses Memory Health (§5), Learning Signal (§6), ACE Reflection (§7), and idle consolidation. Inferred from role: mathematician/scholar/crew-reflector/translator/format-verifier/skeptic/historian default to true; coordinators (answerer/councilor/debater/decomposer) and freeform roles stay false. A responder may opt out with `memory set autonomy full` (its thinking level and output cap stay as spawned).
  - `InterruptibleWaiter` (`src/agent/interruptible-waiter.ts`) — used for the cycle-delay sleep only. Perception handler calls `cycleWaiter.wake()` after pushing into `pendingPerceptions`, so the loop wakes immediately instead of waiting up to `loopCycleDelay`. Rate-limit backoffs (LLM-error, loop-exception, streaming guard) intentionally stay on the original non-wakeable `sleep()`.
- **`tellAndAwait` correlation** (`src/sdk/client.ts`, 2026-09-22): the outgoing tell carries ` [re:<6-char id>]`; a reply containing `re:<id>` resolves immediately, otherwise the first FRESH (arrives after our own `You tell …` echo / timestamp ≥ send) non-notice tell from the target wins after a 1.5 s grace (`TELL_AWAIT_GRACE_MS`). Tells matching `TELL_NOTICE_PATTERNS` or prefixed `TELL_NOTICE_PREFIX` (`[notice]`) — budget exhausted, spend cap, upstream-error pause — are never treated as answers. Options `{ correlate, graceMs, ignoreNotices }`; positional `timeoutMs` still works. Responders that echo the tag skip the grace.

## Cognitive infrastructure (platform-level commands)
- **Goals**: `task goal <title> | <desc> [!pN]` — creates + auto-claims a personal goal with priority 0-10
- **Progress**: `task progress <id> [+N | N]` — track goal progress (auto-completes at 100)
- **Learning**: engine auto-tracks command success/failure in `entity_activity` — no agent action needed
- **Proficiency**: `novelty stats` shows per-command success rates; `novelty suggest` analyzes entropy, gaps, struggle areas
- **Curiosity signal**: `brief` shows `[low action diversity]` when entropy is low — passive, no prescription
- **Named verbs that compose primitives** — sit next to `ask` as cheap, agent-friendly workflows over `recall` / `pool` / `web`:
  - `ask <question>` — LLM-synthesized answer with personal + guide + pool + world-search context (`src/engine/commands/ask.ts`)
  - `recap <topic>` — retrieve-only multi-source pull, no model call (`src/engine/commands/recap.ts`)
  - `debrief` — session close view: recent notes, open claims, standing snapshot, reflect-when-3+ nudge (`src/engine/commands/debrief.ts`)
  - `share <pool> <content>` — deposit into a named pool, refuses unknown pools (`src/engine/commands/share.ts`)
  - `dig <topic>` — internal notes + web evidence + optional synthesis; degrades gracefully without connector runtime (`src/engine/commands/dig.ts`)
- All cognitive features are platform commands accessible to any agent (internal, MCP, WebSocket, telnet)

## Thinking levels and tool execution ordering (2026-09-22)

`AgentConfig.thinkingLevel` (`off | minimal | low | medium | high | xhigh`) resolves explicit → crew responder forced `off` → `MARINA_AGENT_THINKING` (default `off`) via `resolveAgentThinkingLevel`. `off` neutralizes reasoning on the proxy model; any other level sets `reasoning: true` + `compat.supportsReasoningEffort` so pi-ai emits `reasoning_effort`; `anthropic-tools.ts` maps `reasoning_effort`/`thinking` to `thinking: { type: "enabled", budget_tokens }` (minimal 1024 · low 2048 · medium 8192 · high/xhigh 16384, clamped to the client cap) and OMITS `temperature`/`top_p` while thinking (Claude 5 rejects them). Set with `agent spawn … thinking:high` (or `--thinking high`, legacy `thinking high`) and `agent config <name> thinking <level>`; persisted in `agent_configs.thinking_level` (migration 120, NULL = unset) so the boot-time respawn and `agent restart` keep it — `AgentRuntime.reconfigure` writes it through `saveAgentConfig`, which leaves the stored level alone when a reconfigure does not mention it.

pi-agent-core runs tool batches in parallel by default. Marina stamps every world-mutating tool `executionMode: "sequential"` (`applyToolExecutionModes`; `READ_ONLY_TOOL_NAMES` — look/examine/who/brief/feed/web/think/code read·search·diff — stay parallel); a batch containing any sequential tool serialises. `MARINA_TOOL_EXECUTION=parallel` drops the stamps, `sequential` sets the Agent-level mode. The one-channel-send-per-run hook is a rate cap, not an ordering rule, so it stays.

World commands use request IDs and explicit completion. The SDK returns only causally related output
to the originating connection; ambient perceptions remain separate. WebSocket commands share bounded,
per-entity FIFO admission, including awaited batch and macro subcommands. Different entities can run
concurrently. A timeout or disconnect reports an unknown outcome rather than successful empty output.

Per-run limits reserve tool attempts before execution and yield through Pi’s `finishTurn`, after
completed tool results have been journaled. Excess tool calls receive a non-execution result. This
ordering applies to sequential and parallel tool batches across providers.

Addressed requests remain pending through observations, prose-only turns, failures and run yields.
Crew responders continue waking while a request awaits delivery. A successful, journaled tool result
must contain a matching tell/channel/say delivery receipt to settle the request; private tells retain
their destination and correlation tag, and model requests require the matching response ID and channel.
Requests are saved on intake in the private resident checkpoint, before prompt consumption. Their
removal shares the successful tool journal’s checkpoint commit. Restart restores unanswered requests
with their original destination, text and correlation, including when the replacement uses a different
model. Restored requests become eligible for settlement only after presentation to that model.
Failed intake writes retain the queue and stop prompt consumption; failed ledger reads stop bootstrap
with an error status. A crash between external delivery and the journal commit still leaves an uncertain
outcome: this is durable response tracking, not an exactly-once external delivery protocol.
The oldest presented request receives a bounded reminder each continuation cycle. Provider-specific
tool schemas, reasoning formats and request translation remain Pi’s responsibility.

The SDK negotiates correlated command support during login/auth. Older servers use serialized,
explicitly unconfirmed observation windows in `commandMode: "auto"`; commands are never retried to
detect protocol support. Internal agents require `commandMode: "correlated"` and refuse legacy
commands before dispatch. See [SDK reference](../../src/sdk/README.md).

## Library surface: strict tools, toolChoice, prompt_cache_key (2026-09-22)

- **Strict tools (enabled)**: `applyStrictToolSchemas` (run inside `createProfileToolset`) stamps `constrainedSampling: { type: "json_schema", strict: "prefer" }` on every tool whose parameter schema is a closed, all-required object with no strict-mode-rejected keyword (`isStrictSafeSchema` — mirrors pi-ai's `makeStrictJsonSchema` invariants). pi-ai's openai-completions path then sends `strict: true` (it already sends `strict: false` on every function tool, so the field itself is tolerated everywhere): OpenAI and vLLM enforce it, llama.cpp / Ollama ignore it, and the proxy's Anthropic translation keeps only `parameters`. Schemas with optional properties are never stamped — strict mode would rewrite them as `anyOf: [T, null]` + required and handlers would receive `null` for `undefined`. Among the resident set only `marina_command` qualifies today. `MARINA_STRICT_TOOLS=off` disables the stamp.
- **`toolChoice` (not exposed)**: pi-ai 0.85.1's `ToolChoice` is `"auto" | "none"` — there is no `required`; and `AgentOptions` has no `toolChoice` (it is a per-request `SimpleStreamOptions` field, so it would have to be spliced into the adapter's `streamFn`, gated to the first turn of a prompt — a run-wide `required` would force a tool call on the turn that should end the run). Revisit when the library grows a `required` mode.
- **`prompt_cache_key` (enabled)**: pi-ai sets it only when `model.baseUrl` is `api.openai.com`, so agents behind the local proxy never sent one. The Agent's `onPayload` (`withPromptCacheKey`) fills it from the same stable `marina-agent:<name>` session id that rides the session-affinity headers, on the proxy model only (registry models keep pi-ai's behaviour; `MARINA_AGENT_PROMPT_CACHE=off` also turns this off; clamped to OpenAI's 64 chars). `model-api.ts` forwards the body field untouched, so an OpenAI upstream behind the proxy gets prompt-cache affinity per agent. Tests: `test/prompt-budget.test.ts` → "strict (constrained-sampling) resident tools", "prompt_cache_key on the proxy model".

### Tool results and reasoning output budgets

Tool-result text blocks default to 15% of the live effective prompt window, with a 2000-token floor. `MARINA_MAX_TOOL_RESULT_TOKENS` selects a fixed positive cap; an explicit context-manager option takes precedence. Each transform reads the current window, so model changes and overflow recovery update the allowance. Truncated output includes an incomplete-output notice and a request for narrower retrieval, with the notice counted inside the text allowance. Original messages go through the existing archive-before-compaction path.

Cloud crew responders keep a 2048-token output default with thinking off; the compact crew profile keeps 4096. When thinking is enabled, automatic caps use pi-ai’s `thinkingBudgetForLevel` (including custom budgets) plus 2048 tokens for the answer or tool call, bounded by the model output limit and half its context window. The synthesized Marina proxy has no known upstream output limit at this layer. Explicit `maxTokens`, `AGENT_CREW_MAX_TOKENS`, and `AGENT_COMPACT_MAX_TOKENS` caps are honored; insufficient room emits a warning. Changing thinking level recalculates the cap while retaining the calibrated context window. Effort-based providers ultimately decide how many reasoning tokens to spend; this allowance is a capacity policy, not a guarantee of a completed answer.

### Models that reason unasked (2026-10-03)

With thinking off, Marina sends no reasoning directive, but many OpenRouter routes still reason by default and spend those hidden tokens from `max_tokens`. On a 2048-token crew cap the reasoning can fill the completion, so the turn ends on its length limit before any tool call and the agent looks silent. `src/agent/reasoning-control.ts` handles this in three ways:

- **Headroom.** An automatic crew or compact cap for a model that may reason unasked gets at least `REASONING_HEADROOM_TOKENS` (8192), bounded by the model's ceiling. This covers any OpenRouter route, an id the registry does not know, or a registry reasoning model with thinking off.
- **Growth.** A turn that ends with `stopReason: "length"` and no tool call doubles an automatic cap toward its ceiling, and emits an `output_cap` event. An explicit `maxTokens`, `AGENT_CREW_MAX_TOKENS` or `AGENT_COMPACT_MAX_TOKENS` cap never grows.
- **Prompt bound.** Longer reasoning can outlast the 120 s bound on one prompt. After a timeout, an automatic bound doubles toward 600 s (`grownPromptTimeoutMs`), so a slow answer is not aborted every cycle. An explicit `promptTimeoutMs` never grows.
- **Request shaping (OpenRouter only).** The Agent's `onPayload` composes `withPromptCacheKey` with `shapeOpenRouterPayload`:
  - Tool requests ask for `provider.require_parameters`, so a provider that ignores `tools` is never chosen.
  - `reasoning: {enabled: false}` is sent only for a model whose spawn-time probe still called a tool without reasoning. An explicit disable is not a universal fix: some models reject it with "Reasoning is mandatory", and some accept it but stop calling tools.
  - An upstream refusal of either field is learned per model (`noteUpstreamRejection`). The next cycle retries at once without the field, and it does not count as an upstream error.
  - `MARINA_OPENROUTER_REQUIRE_PARAMETERS=off` and `MARINA_OPENROUTER_REASONING_OFF=off` turn the shaping off.

**Spawn-time tool probe.** `src/agent/tool-call-probe.ts` probes, in the background, each unlisted id or OpenRouter model once per process. It sends one tiny request with one tool, then a variant with reasoning disabled.

- The result is one of `tools`, `no-tool-call` or `unknown`. An inconclusive probe is not cached.
- Results appear in `agent status` (Tool probe) and in `readiness` (`tool-calling`, degraded for a prose-only model).
- `MARINA_TOOL_PROBE=refuse` stops a crew lead whose model answered without a tool call. The default `warn` only reports it, and the probe is `off` under a test runner.

**Owed-reply salvage** (`output-repair`, below). Once the in-run recovery nudge is spent and a silent turn's prose holds the answer to the one owed `model_request`, the adapter sends that answer as the `model_response`. The envelope carries `repaired: "repaired:parse" | "repaired:shot"`. The adapter then settles the obligation durably (`completeOutstandingRequests`) and emits a `decision` event with stage `repair`.

### Output repair (`src/repair/`)

Output repair applies when a model's output misses its required shape. It is a general layer, not a per-model workaround, and it runs in three steps:

1. **Deterministic parse.** The output is tried as-is, then mechanical candidates: reasoning blocks stripped, fenced bodies, the first balanced JSON span with trailing commas dropped, and an explicitly marked final answer or `\boxed{}`.
2. **One bounded re-encoding shot.** The shot uses the caller's own model (`MARINA_REPAIR_MODEL` for `marina/verify`). Its result is kept only when every value appears verbatim in the original (`groundedIn`; short tokens and numbers must stand alone). A shot therefore cannot answer, solve or invent.
3. **Labelled delivery.** Repaired output carries `repaired:parse` or `repaired:shot`.

The layer is wired into four places:

- the lean-agent owed-reply salvage;
- `marina/verify` final messages (`tool-call-repair.ts`). Malformed arguments are re-parsed, and a fenced or bare JSON call for a declared tool becomes a tool call. A state-changing call follows the write-guard rules: no new ids, and only argument names present in the draft. The response sets `x-marina-repair`;
- typed-forecast runs (`TypedRun.repaired`);
- routed `model_response` labels. These surface as `x-marina-repair` on `/v1/chat/completions` and as `ResultItem.repaired` in the benchmark harness, so a run can be scored with or without repaired answers.

`MARINA_OUTPUT_REPAIR=parse` skips the shot and `off` returns raw output. Tests: `test/output-repair.test.ts`, `test/agent-reply-salvage.test.ts`, `test/unknown-model-tool-calls.test.ts`.
