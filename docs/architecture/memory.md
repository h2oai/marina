# Memory Architecture — Canonical Records and Compatibility

**When to read this:** you are touching memory code of any kind — legacy notes (`notes`, `recall`, `reflect`, `pool`, `skill`), the durable memory service (`/v1/memory`, `memory …`), the unified retrieval surface, numeric compatibility adapters, hygiene and dispatch ticks, adoption/ratification, reputation-weighted retrieval, contradiction `resolve`, the passthru gateway with receipts and response cache, retrieval quality and embeddings, or the memory benchmark family. `CLAUDE.md` → "Memory Architecture — Canonical Records and Compatibility" carries the must-follow invariants; this page is the complete design history and walkthrough, including phase dates and measured results.

## Canonical records and legacy compatibility
- **Numeric memory adapters** (`numeric_notes` view over canonical record versions, `src/persistence/db-notes.ts`, commands `note`/`recall`/`reflect`/`pool`/`skill`, REST `/mem/*`): tiered, FTS5-ranked, provenance-aware, owner-scoped via `src/memory/access.ts`. This is what the continuation prompt's "Relevant Notes" section reads (`recall <focus>` in two labeled tiers — `[trusted]` strict hits first, then `[unverified — own notes]`; `PlatformMemoryBackend.searchTiered`). `trusted` is strict everywhere: it never silently falls back.
- **Durable memory service** (`src/memory/service.ts`, `/v1/memory` on the world HTTP port, resident commands `memory remember|claim|relate|query|join|rule-*|graph|show|sources|review|reaffirm|usage|federation`, `marina_memory_service` tool in the full profile, TS client `src/sdk/memory-client.ts`, Python `src/sdk/marina_memory.py`): principal-bound spaces and grants, versioned records with CAS revisions, original sources with stable UTF-8 ranges, checkpoints, dependency-aware staleness (`review`/`reaffirm`), transitive forgetting, per-owner admission budgets (`MARINA_MEMORY_MAX_*`), pinned result cache, explicit federation mounts (`MARINA_MEMORY_FEDERATION_CONFIG`), portable bundles and staged transfers, import adapters. Guides: `docs/guides/memory-service.md`, `memory-interfaces.md`, `memory-extensions.md`.
- **Resident binding**: world commands bind to the durable **user** (`users.id` = the `human` principal id; `createUser` grants it, so internal room/crew agents qualify) and lazily create a private `resident` space (`src/memory/resident-service.ts`). Unknown names get `world_identity_required`.
- **Continuity contract** (`src/agent/durable-memory.ts`, `memory-platform.ts`): every completed message is journaled before the loop advances; every lossy context transform archives the original messages (manifest chain, SHA-256) before trimming, and a failed archive aborts compaction (`ContextPersistenceError`) rather than dropping history. The legacy `[compaction]` personal process note is no longer written; only the optional `compactionPool` summary is shared.

## Canonical storage and retrieval
- **Storage and access boundary**: migration 138 replaces duplicated fact-like bodies and asynchronous replay with numeric handles into one canonical history. Physical version rows remain inaccessible by numeric ID (`isServiceMemoryNote`); compatibility handles keep owner and pool ACLs. Their read-only view resolves current or pinned historical versions. Core/process memory is separate in meaning, not a duplicate fact store.
  - **One retrieval surface** — `buildUnifiedContext(db, entityName, query, opts)` in `src/memory/unified-context.ts` returns five fixed-order tiers within a byte budget. **Relevance gate (HISTORY §8, 2026-09-16)**: legacy recall runs FTS in OR mode, so one shared common word surfaces an unrelated note, and on free-form simple-qa those notes measurably misled Sonnet 5 (warm −9 / bm25 −14 net items vs bare). Seeds (skills, trusted/unverified) and durable `search` hits must share ≥ `minOverlap(terms)` distinct query terms with the content (1 for ≤ 2-term queries, else max(2, ⌈25 %⌉); word-prefix match so porter forms count) — `relevantToQuery`; graph-expanded neighbours are not gated. The header no longer asserts relevance (`UNIFIED_CONTEXT_HEADER` = "[Memory — retrieved by keyword match; use only items that answer the question, preserve provenance]"). **Validity filter**: durable `search` excludes records whose validity has ended (a `resolve` loser, a tombstone `revise` from `note delete` or a lesson retirement) at the query layer, before ranking, in both the lexical candidate query and the vector scan (`memoryValidityFilter` in `db-memory-service.ts`; one `now` per search) — so retired records neither surface nor take result slots (before this, a lesson query returned 49 retired hits out of 50). `valid_at` selects the records valid at an instant; `include_ended: true` is the explicit history read; `get(id, version)` reads every version unfiltered. `servableRecord` still drops a historical version (and anything ended) from the `[evidence]` tier as a second guard (the contradiction benchmark measured 48.5 % of conflicted facts reachable via unfiltered `search`). `query`/`graph` without `valid_at` remain unfiltered exact reads by design; task retrieval passes its `valid_at` to every step. Tiers: skills (`<example>`), `[trusted]` (legacy strict predicate), `[evidence]` (durable `search` records + `source_search` excerpts for the resident space), `[proposal]` (finished assistance jobs), `[unverified — own notes]`. Rendering: `renderUnifiedContext(result, { degraded })` — `true` = full `[degraded]` block (deliberate reads: `recall … all`, REST, MCP), `"compact"` = ONE grouped line (§4 continuation prompt and the benchmark harness; the full block was ~25 % of injected bytes on a one-fact corpus), `false` = none (passthru builds its own lines and puts `degraded` in the receipt). Consumed by the continuation prompt §4, `recall <q> all|evidence [budget N]` (structured `context` payload on `marina.memory.command.v1`), `GET /mem/context?q=`, the world MCP `think{action:"context"}` action, and passthru injection — same fixture ⇒ same tiers on every surface (`test/unified-context.test.ts`). Boot recovery includes the last archive summary from the journal manifest.
  - **Numeric verbs are synchronous adapters** (`src/persistence/db-memory-numeric.ts`): every fact-like write calls the canonical repository inside the originating transaction. No worker, queue or mirror body is involved. A numeric address is stable through native durable edits; `note correct|evolve` pins the old address and creates a new one for the same record's successor version. Failed canonical admission rolls the operation back.
  - **`reflect` is a reflector job**: files `assist_create` role reflector against the caller's space when a running `memory-reflector` exists (or `reflect via <helper>`), else template + spawn hint; `reflect adopt <job>` writes the cited proposal as one durable record with a numeric reflection-tier address with `part_of` links to cited records; `reflect --template` = deterministic; `reflect jobs`.
  - **Plain `recall` stays synchronous** (handler returns a Promise only for `all|evidence`): non-awaiting callers — quest tracker, cognitive-provenance capture, the SDK reply window — need the reply in the same tick. Query expansion uses the per-entity vocabulary cache (`expansionForEntityCached`, background refresh, 60 s TTL) — never a durable round-trip on the hot path.
  - **Teaching**: one `# MEMORY` block in the system prompt (`getMemoryContract()`, ≤220 tokens, profile-aware), one `Memory:` roster line, one `Memory` help category. Since HISTORY §7 (a model that cannot know a fact seeds memory with confident wrong notes) the block tells agents that own conclusions stay `[unverified]` until sourced (`note claim … source <url>`) or `note verify`d — the read side already labels them; the write side is taught not to launder guesses into facts.
  - **Hygiene tick** (`src/engine/memory-hygiene.ts`, hourly phase 2700): per online account, durable `review` stale/competing/pending counts + legacy `auditKnowledgeNotes` → one deduped `[hygiene] …` process note; at `HYGIENE_DISPATCH_THRESHOLD` (5, `stale+competing+pending`) a `local` profile auto-files ONE evaluator job (never two open), shared/public `tell`s the owner the exact `memory assist evaluator …` command. `orient` shows the latest line plus the latest `[accumulation]` receipt (`Accumulation: N notes about "<topic>" handed to reflector job <id>`; `formatAccumulationReceipt`/`parseAccumulationReceipt` in memory-dispatch.ts). It does NOT count open jobs — `work_open` depends on the async lease check, so a sync count would disagree with `memory jobs`.
  - **Dispatch triggers (Phase 3)** (`src/engine/memory-dispatch.ts`, shared job-filing helpers): hourly accumulation → reflector (`[accumulation]`, ≥ 8 same-topic fact-like legacy notes in 24 h, tick phase 900, durable receipt-note dedup, one open per account); `pool_note` from a writer with standing < 5 → evaluator review of the deposit filed in the WRITER's own space (`[shared-write-review]`, 1 h debounce per writer, silent, skipped under `local`). **Debounce stamps are durable**: both the 1 h per-writer and the once-per-day accumulation notification live in the existing `core_memory` KV under the system-owned row owner `memory:dispatch` (keys by entity NAME — ids re-mint per login; the `:` cannot collide with a login name), with the in-process maps as a read-through cache, so a restart cannot re-file or re-notify. Every automatic job is visible in `memory jobs` and cancellable. The three seeded helper roles carry curator duties — evaluator = Steward (proposes a `resolve` policy, never applies it), librarian = Auditor (sweeps for unsupported claims/duplicates/low-provenance clusters, cites, never deletes), reflector = Janitor (ONE consolidated cited lesson, append-and-link) — and re-seed by `[guidelines_version=N]` unless the role was operator-edited (`created_by !== "system"` or non-system `role_history`).
  - **Adoption + ratification (Phase 3)** (`src/persistence/db-memory-adopt.ts`, `src/memory/institutional.ts`): `adopt` (HTTP `/assistance/:id/adopt` or `/spaces/:space/adopt`, TS/Python `adopt`, world `memory adopt <JOB> [space <ID>] [confirm-abstention]`, MCP via the op list) writes an answered proposal as a versioned record with `adopted_from_job`, `derived_from`, pinned same-space citations; idempotent per (job, space). Institutional spaces (`memory_spaces.metadata.institutional`, migration 114 adds `metadata`; `read_public` for read scope) — `guide` seeded, tradition pools lazily — make adoption a **ratification**: `isLocalUngated()` → sovereign (rank ≥ 9) → standing ≥ `INSTITUTIONAL_RATIFY_MIN_STANDING` (15); `metadata.ratified_by` answers "why is this shared?". `pool guide add` under shared/public is a proposal (importance ≤ 4, unverified) until `pool guide ratify <noteId>`. Standing on adoption: `assistance_adopted` 1.0 to the helper (delegation: root 0.6, contributors share 0.4), `assistance_abstained_confirmed` 0.25 (explicit), `assistance_superseded` −0.5 via `repository.adopt.debitSuperseded` from `resolve`.

## Reputation, retrieval quality, and the gateway
- **Reputation-weighted shared retrieval (Phase 3.6)**: writer standing enters ranking for SHARED memory only — `recallPoolNotes` adds `REPUTATION_WEIGHT` (0.10) × clamp(writer standing/100) via `users ⋈ entity_standing_cache`; durable `search` on spaces the actor does not own applies `applyReputationRerank` (`src/persistence/db-memory-ranking.ts`) and reports it in `MemorySearchResult.ranking`. An entity's own notes are NEVER weighted by its own standing. Corroboration counts independent WRITERS (`INDEPENDENT_SOURCE_KEY`; twins excluded; `evidence_weighted` counts distinct (hash, author) pairs; ESTABLISHED writers (standing ≥ `SYBIL_STANDING_FLOOR` 5) add 0.05 + 0.95·clamp(standing/100) linearly, while all FRESH writers share one sublinear pool `min(SYBIL_POOL_CAP 0.15, 0.05·√n)` — so 10, 32 or 10 000 new accounts never outweigh one standing-40 writer with an independent source; the winner's `evidence_weights` records `sybil_writers`/`sybil_pool`, and the 32-`source_ids` admission cap per record is a second bound) — Sybil tests in `test/memory-resolve.test.ts`. Adopted summaries inherit the LOWEST authority of their inputs (`inheritedAuthority` in unified-context.ts; TMA-NM non-laundering). `reflect --share <pool>` deposits reflection-tier pool notes; `creditRecalledReflections` pays authors from `recall`, `pool recall`, recap/ask/dig, and the unified tiers. `benchmarks/memory/successor.ts` is the Tier-4 cold-start scaffold (stub only).
- **Retrieval quality**: migration 112 rebuilt `notes_fts` with `tokenize='porter unicode61'` (shared by numeric and durable retrieval); `buildFtsQuery` drops 63 English stop-words when ≥1 content token remains (all-stop-word queries pass through). Measured on the frozen 200-triple corpus (`benchmarks/paraphrase/`, `bun run qualify:paraphrase`): hit@3 79.5% → 89.0% (+expansion 91.0%). Embeddings in the world server are env-configured and OFF by default (`MARINA_MEMORY_EMBEDDINGS=none|local|ollama|openai`, `src/memory/embedding-config.ts`, provider loads lazily; `mode:"hybrid"` stays explicit); turning hybrid on by default is gated on that corpus.
- **Gateway (Phase 2, 2026-09-14)** — Marina as memory proxy for ANY client. One `preparePassthru` in `src/net/model-api.ts` resolves the passthru identity identically on `/v1/chat/completions`, `/v1/messages`, Ollama `/api/chat|generate`, and `/v1/responses`, and `applyInjection` puts the unified context in each protocol's native system slot (`openai | anthropic | ollama-generate | responses`). Ordering is byte-stable, stable-first (identity, skills, `[trusted]`, `[evidence]`) then volatile (`[proposal]`, `[unverified]`, pools/channels/chronicle) so provider prefix caches hit; budget = entity `passthruInjectBytes` → `MARINA_PASSTHRU_INJECT_BYTES` → 2048 bytes including framing. `X-Marina-Context: off` is honored for bound keys only (the old literal-marker suppression is gone). Transcript capture dedups by SHA-256 per entity within 24h. **Receipts** (`src/net/memory-receipt.ts`, `marina.memory.receipt.v1`; lifecycle events carry the PROTOCOL `surface` — `openai | anthropic | ollama-generate | responses` — stamped by `passthruTraceOptions(prep)` on every event incl. cache hits, so `MemoryReceiptView.surface` is the protocol, and passthru spans expose string attributes `memoryCacheHit` (sticky once any event targeted `response-cache`) and `memorySurface` beside `memoryReceipt`): every injected response carries `x-marina-memory-receipt` (≤2 KB header, else a stub; the full receipt rides the `model_request_lifecycle` events, `projectTraces` keeps it, `trace show` renders a Memory section, `/api/traces` native includes it). **Response cache** (`src/net/response-cache.ts`): opt-in per bound key (`passthruResponseCache` property, or `MARINA_PASSTHRU_RESPONSE_CACHE=on` under `local`), built on the durable `cache_put/cache_get` primitive with the receipt's evidence records/sources as pins (cache only when ≥1 pin), exact key = SHA-256 of the canonical post-injection request; hits return `x-marina-cache: hit`; never for streaming, tool calls, non-2xx, or shared identities. Semantic caching is deliberately out of scope. First repeat after a NEW exchange misses (captured transcript changes the effective request).

## Contradiction operators and record lifecycle
- **Contradiction operators (Phase 2.5)** — `resolve` (`src/persistence/db-memory-resolve.ts`, migration 113 `memory_resolutions` + members): typed write-time policies over the review queue — `last_writer_wins`, `evidence_weighted` (distinct independent source hashes; twins/`marina-memory://`/assistance envelopes excluded), `await_confirmation` (review kind `pending`), `keep_both` (irreducible; `qualified_by`). `last_writer_wins` / recency ordering (`byRecency`) compares the CURRENT version's note timestamp and breaks same-millisecond ties by write order — the current version's autoincrement `notes.id` (`currentWriteOrder`) — never by `version` (a twice-revised older record would beat a fresh one) or UUID (random); both were intermittent CI failures. Every resolution is an append-only audit row; idempotent per key; writers only (assistance leases refused); losers get `valid_time` closed and stay readable by id/`valid_at` — never deleted. Exposed on HTTP `/resolve`, TS `client.resolve`, Python `resolve`, world `memory resolve <ID> <policy> <JSON>`, MCP via the generic memory op. Bi-temporal questions: valid time via `query|graph valid_at`; transaction time via `get(id, version)`; no legacy note columns were added. The hygiene line reports `pending=N`.
- **Record lifecycle**: `note delete` retires the canonical record with a tombstone revision; explicit durable `forget` erases its history and invalidates dependent checkpoints. `note claim` and template/failure reflections use the same canonical write path. Numeric identity lookups use `memory_note_projections`; source URLs are historical provenance. `reflect` auto-spawns a `memory-reflector` under `isLocalUngated()` when the runtime is available (`spawnHelper` dep), else template + hint. `readiness` prints the trust profile.

## Workflows, retrieval defaults, durability
- **Task memory workflows** (`src/memory/workflows.ts`, typed client `client.workflows(space)`): explicit episodes use owner-private `marina.tasks:<corpus>` journals composed of canonical records/sources/checkpoints. Commit intent before reads; use CAS and stable retry keys. Resume rechecks evidence pins; export reauthorizes; import creates attributed observations without certifying prior execution. Recipes are versioned declarative data, explicitly selected, with live/offline evidence selection shared in `sdk/memory-recipes.ts`. Helpers charge each constituent retrieval read against their live root lease. Watches use private checkpoints and the authorized service-event cursor; acknowledge the poll's observed-time watermark, never launch work on notification. `retrieve_cached` requires explicit `valid_at` and live generation/pin validation. Human entrypoint: `memory guide`; API examples: `workflow {action:"help"}`; guide: `docs/guides/memory-workflows.md`.
- **Retrieval**: numeric and durable interfaces are lexical by default. Hybrid (FTS5 + cosine, RRF) is opt-in in the standalone server and in the world server through `MARINA_MEMORY_EMBEDDINGS`; `worldMemoryService` loads its configured provider lazily. MiniLM/ONNX live in `extensions/local-embeddings`, not the standard install. Turning hybrid on is evidence-gated (paraphrase hit@3 vs BM25 on both interfaces).
- **Durability**: `MARINA_DB_DURABILITY=full` (fsync per commit) is the world default; migrations 96–109 are append-only like all others.

## Compatibility writes and recovery

`/v1/memory` owns the record history. Commands, `/mem`, internal producers and
`ctx.notes.add` call synchronous numeric adapters into that repository. Sources,
verdicts, graph links, corrections and retirement commit with their originating
write; failure leaves neither a partial note nor deferred work. New assertions
are not captured again as self-evidence. External sources still retain original
provenance and credibility, including zero.

Migration 138 reuses existing canonical IDs/versions, converts unmapped notes,
finishes pending changes and removes the old queue and its triggers. Numeric IDs
remain stable. Older canonical rows are recognized by version membership even
when their author names predate the `memory:` convention. The conversion and schema
marker commit together; reopening does not repeat it. Suspended owners and server
namespaces retain their ownership. A later human registration cannot claim a
system-owned durable space by reusing its display name.

`memory_note_projections` records identity and optional historical version pins;
`numeric_notes` reads the corresponding body directly. Mutable text is forbidden
on bound handles. Native revisions therefore become visible without copying or
replay. Corrections invalidate previous verification. `note delete` retires the
record while explicit durable `forget` erases its history and numeric addresses.
Institutional publications remain independently authorized records.

Shutdown drains admitted command/HTTP work and existing embedding workers before
closing persistence. There is no memory compatibility worker to drain. Offline
`bun run memory:compatibility upgrade DB_PATH` opens the database under an exclusive
lease and performs pending migrations; `status` reports unconverted notes, broken
references and duplicate bodies without printing content. Old snapshot imports
convert their memory before committing as well.

## New feature write path and deprecations

New features write through the durable service. In-process features use
`residentMemoryOperation`; governed dynamic commands and installed extensions get
`durableMemory.run(request)` scoped to the current calling entity. It uses the same
authenticated service transport, space ACLs, version checks and receipts as
`/v1/memory`. These writes create canonical records directly, without legacy note
copies or outbox jobs. The binding rechecks the live caller and durable account for
each operation; it does not accept an owner name or expose a credential.

`/mem/*`, numeric-note authoring through `note`, and `ctx.notes.add` are deprecated
for new integrations. Existing users of these surfaces keep their IDs and behavior;
no sunset or data reset is imposed. Core key-value beliefs, process journals and
institutional publications are distinct semantics, not deprecated duplicates.

`legacy-projection.ts` contains read-only identity/provenance lookups used by
retrieval and observability. The old `legacy-bridge.ts`, compatibility wrappers,
queue API and retry tick job have been removed. In the combined context, a record
already represented by a numeric tier is not repeated in the evidence tier.

## Outcome lessons (`src/learning/`)

Every verdict on something Marina did becomes a candidate lesson:
- **Producers:**
  - a benchmark run filed (`POST /v1/benchmarks/runs`, the in-world runner, and `benchmark:import` by default; `--no-learn` opts out);
  - every valid ledger run filed before imports learned, once, through `bun run lessons backfill` (below);
  - a forecast settled by the `forecast-question` finder;
  - a Code Mode verification;
  - an arena round resolved (`learnFromResolutions`), and a crew round scored in an arena evaluation (`crewLessonOutcome`; a no-op unless learning is armed for that store).
- **Hand-off:** each producer calls `noteOutcome(db, outcome)`. That never blocks or throws, it queues, and it's a no-op unless `enableOutcomeLearning(db)` armed the database (`main.ts` does; tests and library code don't).

The loop:

| step | what happens |
|---|---|
| **Candidate** | The text is `[lesson:<domain>] <success\|failure> · <category> · rule: <rule> · score · detail`. The category, rule and `scope` come from the writer (`MARINA_LESSONS_WRITER`, default `marina/default` through this Marina's `/v1`). Without a writer, or when its rule fails the item check, the producer's own `rule` is used. A benchmark run supplies one (`benchmarkRunRule`). The writer prompt depends on scope. For a single case it is told to restate nothing from the case. For an aggregate outcome (`config`, `model`, `budget`, `calibration`) it writes a rule about method, configuration or model choice, with the conditions it applies under, and may cite aggregate numbers as evidence. Measurement notes (`measurement`) are shown to the writer and the judge as context, never as the finding. |
| **Scope, families, subjects** | Every lesson records what it is ABOUT, apart from where it came from: `scope` is one of `case`, `method`, `config`, `budget`, `calibration`, `retrieval`, `infra`, `model` (the writer names it; without one, a producer default: benchmark runs `config`, code and tools `method`, forecasts and arena rounds `case`). `families` are up to three task-family tags from the declared vocabulary in `src/learning/families.json` (data: a harness result's `config.families`, else the vocabulary's map of the benchmark name or the outcome's source). `subjects` are the formation and short model names of a ledger target (`targetSubjects`). All three are record metadata; no migration. |
| **Content rule** | An outcome carries only general fields. The case text (a question, an error excerpt) travels as `privateContext`: the writer may read it, it's never stored, and a mechanical check rejects any lesson that quotes it. Item content travels only as fingerprints in `caseGuard` (`src/learning/leak-guard.ts`): item ids, hashed 4–6-word shingles of item text, hashed answers, and a test against the ledger's keyed answer hashes whose key stays in a closure. `itemLeak` rejects a lesson that names an item id or an id-shaped token, quotes an item, or states an answer. Aggregate numbers and the outcome's own words are never matched. A mechanical rejection is stored without its text (`withheld · <reason>`). |
| **Judge** | The decision layer answers five `noul` questions: grounded, general, leak-free, consistent with the domain's current trusted lessons, and `transferable` (would it hold for a different task family or board?). `leak_free` means no benchmark ITEM content: no question text, answer, item id or instance-specific detail that would let a future run memorise answers. Aggregate scores, sample sizes, costs, model names and configuration descriptions are not leaks. The first four questions decide trust. A calibrated answer is held to per-question bars (grounded 0.6, general 0.55, leak-free 0.7, consistent 0.5); an uncalibrated one gets one cut at 0.5. What ANSWERED decides, as for the tool gate: a composite engine (`marina/auto`) is calibrated when its calibrated primary answered alone, and uncalibrated when an uncalibrated second opinion joined in. The engine's own static `calibrated: false` (any uncalibrated fallback makes it false) no longer forces the single cut. The single-model fallback (`MARINA_LESSONS_JUDGE_MODEL`) is always uncalibrated. `transferable` never decides trust; its bar (0.6 calibrated, 0.5 uncalibrated) only decides the meta mirror. The judge is labelled on the lesson. |
| **Admission hook** | `recordOutcome` calls `deps.admit(lesson, { outcome, verdict, target, sink })`, when given, after the judge and before each write (the lesson, then its mirror). It returns the lesson to write, `null` for none, or a decision (`{ lesson, action, mergedInto, afterWrite }`: `afterWrite(id)` runs after the write, for a supersession or a resolve case, and a failing follow-up never fails the write). Unset, every judged lesson is written as judged. Memory admission ranking (below) is this hook. |
| **Meta mirror** | A lesson that is `trusted`, whose scope is not `case` and that the judge found `transferable` is also written to `lessons:meta`: same text, judgement, judge and `resolvedAt` (so the time rule is unchanged), refs gaining `lesson:<original id>`, provenance `promoted_from: <domain>/<id>`, request key `lesson-meta:<id>` (a retry writes once). Retiring the original retires the mirror (`retireLessons` / `supersedeLesson` follow `lesson:` refs), and invalidating a run retires lessons citing it in every domain, mirrors included. `MARINA_LESSONS_META=on` (default) mirrors and serves; `observe` mirrors and records ids without injecting; `off` neither. |
| **Storage** | A canonical reflection-tier record (subject `lesson`) in the shared space `lessons:<domain>`, owned by the server account `marina:lessons`. Login can't produce that name, so no participant can claim or edit the pool. |
| **Trust** | `trusted` and `unverified` lessons are served; `rejected` ones are audit records recall never serves. No judge reachable ⇒ `unverified`: nothing is promoted without one. |
| **Recall** | `recallLessons(db, domain, query, { asOf })` is lexical, trusted first then newest (then, under `MARINA_MEMORY_RANKING=on`, by admission rank between the two), and byte-budgeted. A `contested` lesson is never served. It applies `visibleAt`: a lesson resolved at T is invisible to work whose cutoff precedes T. A retired lesson is never served (the search layer drops it; the sink re-checks `valid_time.until`). Recall needs no arming: without an armed sink it reads through `lessonRecallSinkFor`, which never creates the account or a space. |
| **Retirement** | `lessons retire <id>\|source:<s>\|match:<text> reason:<text>` and `lessons supersede <id> reason:<text> -- <replacement>` (`retireLessons` / `supersedeLesson` in `src/learning/service.ts`) revise the record through the memory service: same content, `valid_time.until` closed, `retired_reason` / `retired_at` / `retired_by` (durable account key) / `superseded_by` in metadata — the `note delete` tombstone shape, audited as a `memory.revised` event. Nothing is erased; `get(id, version)` reads the original. Both need `role.edit` (a lesson steers every agent it is recalled for); criteria retirements preview until `confirm:yes` and touch at most 200 lessons. A replacement keeps the original's domain, kind, category and `resolvedAt` and is `unverified`. |
| **Invalidated runs** | `benchmark invalidate` (and `benchmark:import --invalidate`) retires every current lesson, in every domain (meta mirrors included), whose refs cite the run (`bench:<id>`) through the same audited path (`retireLessonsForRun`, `src/learning/intake.ts`), and retires any legacy per-item outcome notes earlier runners left for it in the `benchmark:<name>` pool through `note delete`'s path (`retireOutcomeNotesForRun`, `src/engine/benchmark-runner.ts`; notes cite `bench:<id>`, older ones a 16-character id prefix that is retired only when no other run shares it). Revalidating does not restore either. The runner no longer writes item text to memory; `benchmark purge-content-notes` retires what remains ([benchmarks.md](benchmarks.md)). |
| **One system** | The forecaster's earlier unjudged store (subject `forecast-lesson`, a `Forecaster` world account) is retired: `migrateLegacyForecastLessons` (`src/learning/legacy-forecast.ts`) copies its records into `lessons:forecast` as `unverified` lessons with `provenance` metadata, keyed per record version (idempotent), leaves the originals readable, and renames a script-created account to the unloginable `marina:legacy-forecast-lessons`. |
| **Modes** | `MARINA_LESSONS=observe` recalls without injecting (the ablation arm); `off` disables both writing and recall, the meta pool and every opt-in surface included, so an install without lessons behaves exactly as before. |
| **Budget** | `MARINA_LESSONS_MAX_PER_HOUR` bounds writer and judge calls. Judge spend is recorded as `decision`, writer spend through `modelComplete`. |

Where lessons are recalled. Every work site goes through `recallForWork(db, domains, query, { asOf, limit, maxBytes, eval, families })`: its own producer domains, merged under one budget (`recallAcross`), plus the cross-board `meta` pool within at most a third of the budget (count and bytes, `META_BUDGET_SHARE`). Meta lessons are served trusted only, after the site's own lessons, labelled `(cross-board <scope>)` by `formatLesson`; a mirror whose original is already served is dropped. With no meta lesson the site gets exactly its old recall. Every site records which lessons it used:

| site | domains (+ meta) | budget | how it shows |
|---|---|---|---|
| every forecasting surface (`forecastLessonsFor`: `forecast` command, `/v1/forecast`, FutureX, Metaculus, ForecastBench, `select`, the arena crew) | `forecast`, `arena` | 6 lessons / 1,500 B | the answer's `lessons` field (`observedLessons` under `observe`) |
| the arena crew (`crewForecastRound`) | through `forecastLessonsFor`, at the round's lock | 4 / 800 B | beside its own series notes in the analyst's and skeptic's `LESSONS` |
| `marina/verify:` (proposer and checker) | `tools`, `code` | 4 / 800 B | one system message after the caller's; the checker's prompt; `x-marina-lessons` header |
| `marina:<crew>` requests | `tools`, `code`, `forecast` | 3 / 600 B | a `lessons` field on the `model_request` payload; `x-marina-lessons` header |
| failed `code verify` | `code` | default | appended to the failure summary; ids in the event metadata |
| plain `/v1/chat/completions` passthru, opt-in: model `marina/lessons:<model>` or header `x-marina-lessons: on` | `tools`, `code` | 4 / 800 B | one labelled system block after the caller's context; `x-marina-lessons` header. Without the opt-in the request is byte-identical to before |
| resident agents, opt-in: `MARINA_LESSONS_RESIDENT=on` (`observe` logs ids; default `off`) | all, via `lessons <focus>` | 600 B, every tenth cycle | a `[Lessons]` continuation section for the agent's focus |
| `lessons <topic>` command | all, `meta` included | 8 / 2,400 B | listing (`retire` / `supersede` curate, above) |

Recall never creates the `marina:lessons` account or its spaces as a side effect; on a database with no pool it returns nothing. The `x-marina-lessons` response header lists the injected ids, then `observe:`-prefixed ids recalled but not injected, `;`-separated (`0` when none); `parseLessonsHeader` reads it.

**Leakage rules.** Rule 1 (time) holds on every sink: a lesson resolved at T is invisible to work whose cutoff precedes T; a meta mirror keeps its original's `resolvedAt`, and a benchmark run's outcome compares it only with runs completed by its own completion. Rule 2 (self-exclusion for measurement): a request carrying `x-marina-eval: benchmark=<name>; slice=<hash>; mode=measure` never recalls a lesson whose provenance names that board — its `source` (`benchmark:<name>`, `<name>`, or a producer label `<p>:…` where the board is `<p>` or `<p>-…`) or a `bench:<run>` ref whose ledger run is of that benchmark (`evalExclusion`, `src/learning/eval-context.ts`). Lessons from every other board still flow, so a measured score means general Marina applied to the board. `mode=live` lifts rule 2 (live outcomes are genuinely future); `mode` defaults to `measure`. verify, crew routing and opted-in passthru read the header; `forecastLessonsFor` takes the same context as `eval`. Rule 3 (case text) is unchanged: the mechanical quote check and the judge's `leak_free`.

**Backfill.** `DB_PATH=<db> bun run lessons backfill [--dry-run] [--limit N] [--relearn-rejected]` (`backfillLedgerLessons`, `src/learning/backfill.ts`) feeds every valid, scored ledger run with no lesson yet through the loop, oldest first, one at a time: ids, scores, counts, cost per item, judge label, families and subjects, never item text (the ledger holds none). `resolvedAt` is the run's completion. A run whose own lesson (first ref `bench:<id>`, any trust) exists is skipped, so a second pass writes nothing; invalid, failed, unscored and empty runs are skipped. A retirement is a decision: a run whose lesson was retired (operator `retireLessons`, supersession, a resolve loser) counts as taught and is never learned again, with or without `--relearn-rejected` (the store's `findRetired` reads each lesson's latest version with its validity closed; the report prints `retired (not re-learned) N`). The exception is a lesson retired because a run it cites was invalidated (`retireLessonsForRun`, reason `benchmark run <id> invalidated: …`): once `benchmark revalidate` makes the run valid again, the next pass learns it anew. Trusted, transferable lessons are mirrored as on any write. Writer and judge are the server's. A run the judge cannot decide (outage, spend cap) is deferred: nothing is written, so a later pass learns it, instead of an `unverified` lesson being left behind. The pass also stops before the next run once `dailyCapRefusal` reports the cap. `--relearn-rejected` re-learns a run whose current lessons are all `rejected` and were all written by an earlier learner (a `provenance.learner` other than `BENCHMARK_LEARNER`, `bench-rule-v2`, or none). The old rejections stay as audit records. The new lesson carries the current learner, so a second pass skips the run whatever its verdict. Back up the database first; `--dry-run` writes nothing (not even the lessons account).

## Memory admission ranking (`src/memory/admission.ts`)

Curated writes are compared with ALL of their pool, not judged alone: duplicates merge instead of piling up, a refinement replaces what it refines, a contradiction of trusted memory is a case rather than two lessons coexisting silently, and recall can prefer the records with the highest expected value. Low-ranked records stay recorded and searchable; they are served last.

`MARINA_MEMORY_RANKING=off|observe|on` (default `off`):

| mode | writes | serving |
|---|---|---|
| `off` | today's: no comparison, no rank | today's |
| `observe` | as today, each carrying its `rank` and the PROPOSED action (`admission.applied: false`) | today's |
| `on` | the action is applied (table below) | trust, then rank (records below the 0.25 floor last; unranked records at 0.5), then recency; `contested` records never |

What is admitted today: every lesson and its `lessons:meta` mirror (the `admit` hook above). The step is general (`admitMemoryWrite(candidate, { neighbours, provider, weights })`, candidate kind `lesson` / `meta` / …); skills, conventions and imports plug into the same function in a later phase. Raw outcomes (ledger items, forecast answers, arena rounds) and ordinary `remember` / `note` writes are not ranked.

Per write:

1. **Neighbours.** The top 8 valid records nearest the candidate through the memory service `search` (`searchNeighbourRecords`): its own pool (`lessons:<domain>`, actionable) plus, for a producer lesson, up to two `lessons:meta` records shown as context only. Lexical by default; hybrid (weighted RRF over the vector index) when `MARINA_MEMORY_EMBEDDINGS` is configured, with `allow_degraded` so a missing provider or index answers lexically and is labelled (`rank.search`, `rank.degraded`), never an error. A mirror never meets its own original; rejected audit records are never neighbours.
2. **Mechanical pre-screen** (`admission-policy.ts`, no model). An exact or normalised-text duplicate, or token Jaccard ≥ 0.9 against a neighbour of the same scope and families, merges with no decision call. No neighbour clearing the lexical relevance gate (`relevantToQuery`) ⇒ novel by construction: only the value questions are asked.
3. **One decision request**, numbers only: `relation` (`choice`: `new`, `same_as_Ni`, `refines_Ni`, `contradicts_Ni`; at most 25 options), `novelty` (0–3), `generality` (0–3), `evidence_fit` (0–2), `value` (0–4). The state is the candidate and the neighbours `N1…N8` (≤ 300 characters each, trust, rank, evidence), all framed as data. Evidence strength `E_m` ∈ [0, 1] is mechanical (`evidenceStrength`): supports, replicated ledger runs, interval width (else item count), confirmations, scaled by the share of `bench:` refs not invalidated.
4. **Policy** (pure; a calibrated judge needs p ≥ 0.6, an uncalibrated one gets one cut at 0.5):

| relation | `on` action |
|---|---|
| `same_as` (uncalibrated: also Jaccard ≥ 0.6), or a mechanical duplicate | **merge**: the neighbour is revised (`support + 1`, refs ∪ (≤ 12), a `merged` provenance entry); nothing new is written and `resolvedAt` is unchanged. A higher-trust candidate supersedes instead |
| `refines` (never a higher-trust neighbour) | **supersede**: the candidate is written with `resolvedAt` = the later of the two (the time rule holds) and the neighbour retired with `superseded_by` through the audited retirement path |
| `contradicts` a TRUSTED neighbour | **contest**: the candidate is written `contested` (held: never served, never mirrored) and a resolve case is opened (`memory_resolutions`, `await_confirmation`; both records carry the claim `lesson` / `admission-conflict:<neighbour id>`). It is released as soon as the lesson it contests is no longer current (the case resolved for it, or the lesson retired). A calibrated judge, a trusted candidate and an evidence gap `E_m(candidate) − E_m(neighbour)` ≥ 0.3 resolve it at once (`last_writer_wins`, one audit row) |
| `new`, an unsure relation, or a relation to a context-only record | **new**, with its rank |

5. **Rank** (`rank_method: v1`): `rank = trust_w × (0.35·value + 0.2·generality + 0.15·novelty + 0.2·E_m + 0.1·evidence_fit)`, each answer a level expectation in [0, 1]; `trust_w` is 1 trusted, 0.6 imported, 0.4 unverified. The weights are a promoted default: slot `memory-ranking:weights` through `resolveDefault` (built-in `v1` until a measured win promotes others).
6. **Stored with the record** (metadata, no migration): `rank` = `score`, `components` (each expectation, its level distribution and confidence when reported), `method`, `judge` (`kind:model`), `calibrated`, `neighbours` (`id@version`), `space_generation`, `ranked_at`, `weights`, `search`; `admission` = mode, action, applied, target, reason, relation, mechanical, similarity, and for a contest `state` / `contests`.

**Degraded modes.** No decision backend configured (`MARINA_DECISIONS` / `MARINA_DECISION_ENGINE`; the one-model lesson-judge fallback does not count) ⇒ no hook: exactly `off`. A backend outage, an incomplete answer or the daily spend cap ⇒ that write proceeds as `off` would, labelled `admission.skipped` (`judge_unavailable`, `spend_cap`). A rejected lesson is written unranked as before. An uncalibrated backend (a chat model as classifier) is labelled `calibrated: false`, merges also need mechanical similarity, and contradictions are never auto-resolved.

**Spend.** One decision call per write (none for mechanical duplicates), recorded where it leaves Marina: the metered decision provider (`recordSpend("decision")`) or, for a classifier engine, this Marina's `/v1` passthru; a hybrid query embedding through the embedding provider (`recordSpend("search")`). Admission checks `dailyCapRefusal` before asking and never blocks a write at the cap.

**Measuring it.** `DB_PATH=<db> bun run lessons rank [--domain d] [--limit N] [--out rows.jsonl]` is the observe pass over an existing pool: every current lesson is admitted against the lessons of its pool written before it (by `resolvedAt`), one decision call each; it writes nothing and reports merges (mechanical and judged), supersedes, contradictions of trusted lessons (and how many a calibrated judge could auto-resolve), new and below-floor counts. `bun run lessons replay --ranks rows.jsonl [--cutoff ISO]` (`src/learning/replay.ts`) freezes the pool at a cutoff (default the 70th percentile of `resolvedAt`), takes the lessons resolved after it on the hashed `memory-ranking` holdout split as tasks (each recalled with its category just before its outcome was known), and recalls the same pool under two arms — today's order, and ranked serving without the merged, superseded and contested lessons — reporting distractor rate (mechanical proxy: no category relevance or a family/scope mismatch; a fixed judge's labels can replace it), duplicate rate within a served set, contradiction exposure, useful-hit rate (relevant and of the same kind as the task's outcome, a proxy), bytes per useful hit, and pool size vs unique clusters. Ranked serving becomes a default per surface only through an earned slot `memory-ranking:<surface>`, like any default.

## Relevance gate and hybrid context search (`src/memory/relevance-gate.ts`)

Keyword retrieval surfaces items that share words with a question without bearing on it, and a reader treats whatever it is shown as evidence, so irrelevant hits turn into confident wrong answers and accepted false premises. The overlap filter (`relevantToQuery`) removes one-shared-word hits; the relevance gate is the optional second step that judges the rest.

`MARINA_MEMORY_RELEVANCE_GATE=off|observe|on` (default `off`) applies inside `buildUnifiedContext`, so the continuation prompt, `recall <q> all|evidence`, `GET /mem/context`, MCP `think{action:"context"}` and passthru injection all serve the same gated tiers (`test/memory-relevance-gate.test.ts` holds the parity). The per-call option `relevanceGate: { mode, maxItems, backend: "mechanical" }` overrides the environment; the effective setting is part of the context-cache key.

1. **Candidates.** After fetching, each tier is cut to its `perTier` cap exactly as budgeting would (sorted, legacy duplicates removed), so the gate never judges an item the caps would drop anyway.
2. **Exempt.** `core` memory (note tier or record tier) and pinned items are never sent to the judge and never dropped.
3. **Backend**, first available: the decision layer (`harnessDecisionProvider`: `MARINA_DECISIONS` / `MARINA_DECISION_ENGINE`); else ONE model through this Marina's `/v1` as a verbalized chat classifier (`MARINA_MEMORY_RELEVANCE_GATE_MODEL`, default `marina/default`; uncalibrated); else, with the model set to `none`, the mechanical floor (an item must contain ≥ 40 % of the query's distinct terms). Items go out in batches of 12, one `noul` question each ("does memory Mn bear on answering the query?" — a memory showing the premise is false counts as bearing on it), with the head of each item (800 bytes) and of the query (1000 bytes).
4. **Policy** (`gateVerdicts`, pure). Drop only: items are kept or removed, never rewritten or reordered. A calibrated backend keeps p ≥ 0.3; an uncalibrated one gets one cut at 0.5. An item the backend left unanswered is kept. At most `maxItems` (default 8) judged items are kept, highest relevance first.
5. **Fail open.** A backend outage, a reply past the bound (`MARINA_MEMORY_RELEVANCE_GATE_TIMEOUT_MS`, default 30 s — enforced by the gate itself, even against a backend that ignores its abort signal), an incomplete reply or the daily spend cap (checked with `dailyCapRefusal` before asking) serves the ungated set with `relevance.outcome = "fail_open"` and a `reason` (`backend_unavailable`, `timeout`, `incomplete`, `spend_cap`); such a result is never cached.
   The single-model fallback asks an OpenRouter-routed model (an `openrouter/` id behind this Marina's `/v1`, or an OpenRouter base URL) not to reason: `reasoning: { enabled: false }`, and for a model whose upstream answered "reasoning is mandatory" (remembered in `reasoning-control.ts`) one retry at `effort: "low"`. A classifier call carries no tools, so the tool-calling probe that guards the disable for agents does not apply.
6. **Explicit absence.** Under `on`, when the gate applied and nothing is left (no tier failed; a missing world account is a posture, not a failure), `relevance.none` is true and every render says `NO_RELEVANT_MEMORY` ("no relevant memory found for this query; memory does not support an answer") — `renderUnifiedContext`, the `recall` text, and a `relevance` line in passthru injection — so a reader can answer unknown instead of guessing from noise.

`observe` scores everything and reports the would-be drops in `relevance.dropped` while serving exactly what `off` serves: the measurement arm. The `relevance` block carries counts, `<tier>:<id>` keys, the backend label, the threshold, calls, latency and cost — never content; the debug log line carries the same numbers. Spend is recorded where it leaves Marina: the metered decision provider (`recordSpend("decision")`) or the `/v1` passthru hop of the single-model fallback.

**Slow retrievals and the context cache** (`src/memory/context-cache.ts`). The cache's age bound (`CONTEXT_CACHE_TTL_MS`, 5 s) and the next temporal deadline (credential expiry, record validity, assistance leases) decide only whether a result is KEPT. A retrieval that outlives either (a model-backed gate takes seconds) is served once and not cached, as long as the context revision did not change while it ran. A write during retrieval is still retried, and after three such races the read refuses rather than deliver a withdrawn snapshot. `bun run test:mutation` holds this contract at 100 %.

**Index readiness and input limits.** `MemoryService.drainIndex({ timeoutMs })` waits until no index job for the configured provider is pending or running: it runs jobs itself, waits out the background worker while that holds the queue (where `runIndexJobs` alone answers 0), and waits out failure backoff; past the bound it returns `{ pending > 0, timedOut: true }`, never throws. Remote embedders cut each input to `MARINA_MEMORY_EMBEDDING_MAX_TOKENS` estimated tokens (UTF-8 bytes / 3, default 8192, `0` = none; corpora: `MARINA_CORPUS_EMBEDDING_MAX_TOKENS`) and keep the head; the index job is labelled `input_truncated` (its `error` column on a `ready` job). A provider that still rejects an input as too long (HTTP 400/413 naming tokens or context) gets it once more at half the length.

**Hybrid context search.** `MARINA_MEMORY_CONTEXT_SEARCH=lexical|hybrid` (default `lexical`; per call `search`) selects the durable `[evidence]` search mode. `hybrid` fuses the FTS5 ranking with the memory vector index (`MARINA_MEMORY_EMBEDDINGS`, the shared exact vector scan in `src/retrieval/vectors.ts`) and runs with `allow_degraded`, so a missing provider or an incomplete index answers lexically and is labelled `semantic_degraded` on the evidence tier. It stays off by default: hybrid is evidence-gated like everywhere else. The evidence search also over-fetches (2× the evidence slots) before the overlap filter, so a keyword-only hit no longer leaves the tier short when a relevant record ranked just below the cut.

**Measuring it.** The LongMemEval adapter (`benchmarks/longmemeval/`, docs/guides/longmemeval.md) exposes the same switches: `--retrieval unified|raw` (unified = this path; raw = the ungated search hits), `--mode hybrid`, and `--gate off|observe|on` with `--gate-backend auto|decisions|model|mechanical`. A gate becomes a default only on paired evidence.

## Ingest-time notes (`src/memory/ingest-notes.ts`)

Keyword retrieval over a long raw record (a conversation, an agent trajectory, a document, a tool session) has to match the question against everything in it. Ingest-time notes add a few short, self-contained statements next to the source when it is written (who did what, when, which state changed, the outcome), so a question can match a compact note, and the note leads back to its source.

**When.** `MARINA_MEMORY_INGEST_NOTES=off|on` (default `off`). With `on`, a record written or revised through the memory service (`POST /v1/memory/spaces/:space/records`, `PATCH …/records/:id`, so also `residentMemoryOperation` and `durableMemory.run`) with content of at least 2 KB, or a captured source (`POST …/sources`), gets notes. A write can decide for itself with `ingest_notes: true|false` in its body (`true` also lifts the size floor; anything but a boolean is a 400). Importers and adapters call `writeIngestNotes(repository, actor, space, { records, sources, views, writer })` directly; `views` lets a caller send the writer a compact view of a record (for example de-duplicated page text) while grounding is still checked against the stored record.

**Write path.** The source write commits and returns first; `MemoryService.scheduleIngestNotes` then runs the job in the background (one job per source set in flight; `close` aborts a call in flight and drains the rest), and the receipt says `ingest_notes: "scheduled"`. A failed note never affects the source write. `writeIngestNotes` never throws: it returns a report of counts, ids and labels (`outcome`, `reason`, `writer`, `fallback`, `chunks`, `calls`, `written`, `ungrounded`, `duplicates`), never content.

1. **Access.** The job runs as the writer, under its live credential: it must hold `memory:write` on the space (owner or writer grant) and reads the sources back through the ACL before any model call. A reader, a stranger, a revoked grant or an already forgotten source ends the job (`failed`, no call).
2. **Chunks.** The sources' text (or their views) is packed in order into chunks of 12 KB, at most 96 KB per job (beyond that the report says `truncated`), and at most 32 sources per chunk.
3. **Writer.** One chat call per chunk, with no decision layer: `MARINA_MEMORY_INGEST_NOTES_MODEL` (default `marina/default`) through this Marina's own `/v1` with the internal token, asking for at most 8 bulleted notes that copy names, numbers and dates exactly. With the model set to `none`, the mechanical extractor runs instead: each heading with its first line, final-state lines (`outcome:`, `status:`, `result:` …), each run of numbered steps as one procedure, and the last line. When the model fails, the job falls back to the extractor for the rest and the report says `fallback: writer_failed`.
4. **Grounding.** Every key token of a note (anything with a digit, capitalised names that do not start a sentence, all-caps words, quoted strings, URL, email or path-like tokens) must appear in the chunk's stored sources, by the same presence rule as the repair layer's `groundedIn`, and a third of its content words must match. Other lines are dropped and counted as `ungrounded`.
5. **Admission.** Notes do not go through admission ranking (`MARINA_MEMORY_RANKING`), which needs a decision backend. Exact duplicates are skipped instead, both within the job and against active records of the same writer in the space (the `(entity, note_type, content prefix)` dedup index). A source set already noted at the same versions (`metadata.derived_key`) is not noted again, so a replayed write or a re-run importer pays nothing.
6. **Records.** Each note is a canonical record in the source's space: `type: inference`, `tier: reflection` when a model wrote it, `type: observation`, `tier: fact` for an extract, `subject` inherited when the chunk's sources agree on one, and `metadata: { derived: "ingest-note", derived_key, derived_from, writer, chunk }`. It `depends_on` the records of its chunk (a captured source goes in `source_ids`). So `forget` of a source erases its notes through the dependency or derivation cascade (`test/memory-ingest-notes.test.ts`), revising a source stales them (stale records are excluded from retrieval by default), and the source itself is never changed.
7. **Spend.** The `/v1` passthru hop records each call against the daily cap; the job checks `dailyCapRefusal` before every call. At the cap, notes are skipped (`reason: spend_cap`, or `fallback: spend_cap` part-way), and the source write is never blocked.

**Serving.** In `buildUnifiedContext` a note in `[evidence]` carries the provenance `record <id> vN derived note of record <source>` and `meta.derived_from`. After budgeting, if budget is left and the source is not already served, the note is followed by `↳ source excerpt (record <source>): …`. These are the source's lines that share the most query terms, read under the caller's ACL; a source the caller can no longer read is skipped. `derivedSources: false` turns the excerpt off for callers that hydrate records themselves. Every surface goes through the same function, so the cross-surface parity holds.

**Measuring it.** The LongMemEval adapter writes notes per trajectory with `--ingest-notes on` (`--notes-model`, `--notes-base-url`, `--notes-api-key-env`, `--notes-max-bytes`; no model means the mechanical extractor). The adapter sends the writer a compact view of each trajectory: the episode, plus each state's URL, thought, action and only the page lines that are new since the previous state. The switch stays off by default; it becomes a default only on paired evidence.

## Learned bundles (`src/learned/`, migration 161)

`marina.learned.v1` moves what a Marina learned between instances as a signed bundle (user guide: [learned bundles](../guides/learned-bundles.md)). It is inert unless an operator exports or imports: no tick job, no read path on a database that never imported anything.

| module | role |
|---|---|
| `format.ts` | Pure: envelope and item types, `item_key` (salted with the publisher key id, stable across versions), `content_hash` (substance only: rank, tier, provenance excluded), semver, `diffItems` (added / changed / re-ranked / retired by key). |
| `sign.ts` | A dedicated Ed25519 key (`MARINA_LEARNED_SIGNING_KEY`) through `signFederationDocument(doc, { signingKey })`. Verification is only against pinned keys: `BUILTIN_PUBLISHER_KEYS` (empty until a publisher key is pinned) plus `MARINA_LEARNED_PUBLISHER_KEYS`. A signature's embedded key is never a trust anchor. |
| `scan.ts` | Export safety: `secret`, `instance`, `human-name`, `benchmark-text` (6-word shingles and word-aligned 40-character windows of local dataset caches, hashed). A failing item is dropped, never redacted. |
| `export.ts` | The allow-list readers (`listOwnedSpaceRecords` on the lessons account's `lessons:*` spaces, trust `trusted` only; `listRatifiedInstitutionalRecords`; promoted `benchmark_defaults` with numeric evidence; `listLedgerCells` with k ≥ 20; applied `world adopt` roles), tiers, slices, licence, lineage. |
| `bundle.ts` | Directory I/O, `verifyBundle` (schema → pinned signature → file digests → item hashes), signed revocation lists. |
| `import.ts` | Opt-in (`MARINA_UPSTREAM=on`); refuses unpinned, tampered, revoked, downgraded or same-generation-different-content bundles with an audit row; writes lessons and conventions into `upstream:*` spaces owned by `marina:upstream` with trust `imported`; `confirmImportedLesson`. |
| `entitlement.ts` | `marina.entitlement.v1` tokens, signed by the publisher or a listed issuer and verified offline against the same pinned keys. `EntitlementVerifier` turns a proof into a grant. `ownBundleGrant` is the operator's assertion for their own `private` pack and never unlocks a `token` slice. |
| `world.ts` | The `marina.world.v1` content profile: `world` items hold a data-only document (unknown keys refused) and `room_source` items hold inert text flagged `world.code`. Neither is ever compiled or run on import. |
| `assemble.ts` | Builds and signs a bundle from items the caller already holds (world publishers, curated packs), with the same hashing, slicing and signing as export. |
| `upstream-seed.ts` | The upstream-seed layer for default resolution (`env > local slot > family slot > upstream seed > built-in`): a seed answers only while no local `benchmark_defaults` row exists for its slot and its imported item is active. |

Access: `accessPlan` in `import.ts` writes an item only when one of its slices is `open`, or is `token` or `private` and covered by the caller's grant. `--own` covers `private` slices only. A withheld or unselected item is neither written nor retired. A grant whose token nonce the publisher revoked refuses the import.

Trust: `imported` is never served as local `trusted` and nothing an import does raises it. Lessons keep their original `resolved_at`, so the leakage rule (`visibleAt`) is unchanged. Confirmation happens only through a local, judged, `trusted` lesson that cites `upstream:<item_key>`; the imported record keeps `imported` and gains `confirmed_locally_by`.

Storage (migration 161): `learned_artifacts`, `upstream_default_seeds`, `evidence_priors` and `upstream_events` are append-only (update triggers; `append-only` in `RETENTION_POLICIES`). `learned_items` is the current state per imported item (local record, `active` / `retired` / `revoked`, `confirmed_by`). Priors are never `benchmark_runs` / `benchmark_items` rows and seeds never `benchmark_defaults` rows: local evidence stays local truth.
