# Forecasting, Signal Discovery and the Social Simulation Arena

**When to read this:** you are changing the general forecaster (`src/forecast/`), its lessons, its learned settings, a competition adapter, signal discovery (`src/arena/discovery/`) or the Social Simulation Arena entrant (`src/arena/`). `CLAUDE.md` states the invariants; this page holds the mechanics. User guides: [`docs/guides/forecasting.md`](../guides/forecasting.md), [`docs/guides/arena.md`](../guides/arena.md), [`docs/guides/futurex.md`](../guides/futurex.md).

## Signal discovery

`src/arena/discovery/`: signals are DATA in a fixed language (`signals.ts`: centre × spread, leakage-free primitives), never code. The loop (`loop.ts`) splits a family's clean resolved rounds BY TIME, shows the proposer only discovery scores (never holdout — `test/arena-discovery.test.ts` asserts it), promotes only on a holdout win over the incumbent by `promotionMargin(tried)` (grows with attempts) without losing on discovery, and records every scored attempt as an `arena-discovery` note. `discovered` forecaster = best promoted signal per family, else the nowcast.

## Forecasting any question

`src/forecast/` generalises the arena's research pipeline to any question: retrieve → mechanical citation check (`NO_FETCH_DOMAINS` honoured) → one analyst per vendor → Jev judge on verified lines → log-odds / weighted-mean aggregation. Surfaces: `bun run forecast "<q>"`, the rank-0 `forecast` command (per-entity rate limit — every call costs money), `POST /v1/forecast` (model-API auth; error code `forecast_unavailable` only when no model is available — one model runs it degraded, see docs/guides/single-model.md). Typed answers (`src/forecast/typed.ts`, `answer-types.ts`: choice / multi / number / ranking / text) add plan → bounded research rounds → optional lookups → K runs combined by type (agreement = confidence; numbers read with scale and sign, power-of-ten outliers aligned to the median; opt-in `selection: confidence` / `MARINA_FORECAST_SELECTION` takes the most self-confident run — the default changes only by a held-out win, `benchmarks/futurex/rescore-selection.ts`) → a critique that replaces the answer only when its confidence exceeds the forecast's confidence (`critiqueApplies`); evidence is frozen at a cutoff (`asOf`, else min(now, `endTime`)) and recorded; models stay operator-set; saved via migration 151. General capability only — no benchmark-specific logic in `src/forecast/`; competitions get thin adapters (FutureX: `benchmarks/futurex/` + `bun run futurex`, files as agent `Marina` under org `h2o.ai`, never sends the submission, records it in append-only `external_submissions`, migration 152 → docs/guides/futurex.md). The answer object is the audit trail — keep every stage in it. Lessons are ONE system (`src/learning`, judged, retire/supersede): every forecasting surface recalls through `forecastLessonsFor` (`MARINA_LESSONS=observe` records `observedLessons`, injects nothing), and every caller states its measurement context (leakage rule 2: a `measure` run never recalls lessons learned from the board it measures — the held-out selection in `benchmarks/forecasting/cli.ts`, DeepResearch, `POST /v1/forecast` with `x-marina-eval` (Prophet replays send `measure`); live filing (FutureX `run`, Metaculus, ForecastBench rounds) passes `live`, which lifts the rule; the FutureX clean backtest recalls only its own in-run pool and the arena's `evaluate` a scratch store, so neither can reach the shared pool), the `forecast` command and `POST /v1/forecast` share one builder (`src/forecast/surface.ts`), an outcome is never visible before it was known (FutureX: end time + `SETTLEMENT_MARGIN_MS`), invalidating a ledger run retires the lessons citing `bench:<id>`, and backtests share one knowledge-bound rule (`benchmarks/forecasting/knowledge.ts`: one release table, one margin, floating aliases refused). Arena mechanisms, all opt-in (`src/forecast/adjust.ts`, `prior.ts`, `recalibration.ts`, `skeptic.ts`, `routing.ts`): prior shrink, recalibration and formation routing learn ONLY from resolved history visible at the cutoff (`visibleRecords`: resolved ≤ cutoff, never the question itself; `MARINA_FORECAST_HISTORY` stores numbers and option-label hashes, never text), and a learned setting replaces its default only on a held-out win by the margin; shrinkage (prior and the `skeptic` formation) moves only toward an INFORMATIVE prior, never the uniform default. → docs/guides/forecasting.md

## Social Simulation Arena

Marina can be a signed participant in the MIT Social Simulation Arena (`src/arena/`, docs/guides/arena.md). Env-only and OFF by default (`MARINA_ARENA_ENTRANT`, `MARINA_ARENA_KEY_FILE` mode 0600 or refused); filing is an operator act (`bun run arena`, hourly `arena-autopilot` tick job at phase 1500) — the in-world `arena` command is read-only. `protocol.ts` is a byte-exact port of the arena's `signed_forecasts.py` (golden vector in `test/arena.test.ts` — never change it without re-deriving it from the arena's code). The baseline keeps persistence's mean and picks sd per series (RMS or median-based) only when its own history beats the arena's fixed sd 1.5 by ≥ 5 % on the MEAN OF PER-ROUND SKILL — the leaderboard's metric, never total CRPS (a wide spread wins spiky totals and loses most weeks); otherwise exact persistence. `MARINA_ARENA_FORECASTER=model:<provider/model>` shrinks a model's answer toward the baseline; `crew:<m>[,<m>,<m>]` runs statistician/analyst/skeptic roles (one vendor each) with deterministic aggregation (the skeptic only shrinks) and per-series lesson notes (`arena-crew`, type `lesson`) written only after a round is published. `bun run arena evaluate` scores forecasters on resolved rounds (lock order, no outcome before its release) before any switch. `nowcast` reads the arena's Civiqs daily snapshots — only those FETCHED at or before the lock (Civiqs revises nightly) — and Wikipedia daily lists PUBLISHED before it (≥ 2 days before the lock day; final once published, archive partly backfilled). Profile/ranking scoring (`score-shapes.ts`) is a byte-faithful port of the arena's energy score (sha256 point set, Acklam quantile) and RBO; keep it matching `test/arena-score-shapes.test.ts`. `research:` = brief → retrieve → mechanical citation verification → analysts (use other sources for CHANGES, never levels; the benchmark history is authoritative) → Jev judge on verified lines only; web research is evaluated prospectively in shadow (`arena_shadow`, migration 128), never backtested against already revealed outcomes. `arena_submissions` (migration 127) is append-only; the autopilot files each round once; an operator may replace it before lock with `--replace`; a transport failure re-sends the SAME signed request within 240 s.

Arena filing traces (migration 154) live in `arena_submissions.detail`, separate from the signed request; keep inputs, origin/projection decisions, strategy fingerprint, evidence and fallbacks. Sign at completion and recheck the lock margin after forecasting. Horizon policies may be scoped by `MARINA_ARENA_NOWCAST_SERIES`; `arena shadow horizons` compares all five policies on shared frozen inputs. Research may use `+research@closed-book` with explicitly enabled structured lookups; FRED changes are verified against the frozen vintage payload, never a later HTML revision.

Arena experiments: `shadow horizons --weekly-anchor` adds aged daily-slope projections from authoritative weekly levels, without enabling them in submissions. `shadow compare` records start / Delphi / FRED / calibrated scalar candidates with a shared input hash; use `shadow paired-score` for matched comparisons, retaining failed/incomplete batches. Frozen data views memoize failures and isolate mutations. Final-forecast uncertainty calibration is shadow-only, estimator/family/unit-bound, chronological and gated on later outcomes; never train model uncertainty on persistence errors. `arena audit` checks source identity, timing and history comparability. Trends archive fallback requires an exact basket and one eligible complete snapshot; never splice rescaled vintages or change its denominator.

`arena:portfolio` is an explicit shadow-only adapter over the existing Score executor: parallel formations, uncertainty-preserving aggregation and recursive refinement share one frozen input set and one `WorkBudget`. Preserve the original forecast anchor at every layer. Never silently turn budget exhaustion into a successful formation fallback. `task-routing.ts` accepts only time-safe paired evidence; keep native metrics/cohorts separate and cross-benchmark transfers labelled as hypotheses. Latest failed attempts remain in qualification. Plans and selector advice never promote themselves into live arena routes.
