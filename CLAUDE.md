# Marina — Claude Code Conventions

This file keeps only what a contributor must follow to make a correct change: build commands, code style, architecture rules, the invariants of each subsystem, and the key-file map. **Deep dives: [docs/architecture/](docs/architecture/README.md)** — design, history, measurements, and per-feature walkthroughs. Every subsystem section below ends with a pointer to its long-form page.

## Build & Test
```bash
bun run start          # Start server
bun run test           # Run all backend tests (parallel workers; `test:serial` for one process)
bun run typecheck      # TypeScript strict check
bun run lint           # Biome lint
bun run format         # Biome auto-format (run before committing)
bun run test:fast      # pre-commit loop: 138 engine-free files, ~10 s parallel (scripts/test-fast.ts --check reports drift; --serial opts out)
bun run test:shard I N # time-balanced shard I of N from test/timing.json (CI runs 3); regenerate timings per docs/guides/testing.md
bun run test:coverage  # full suite + coverage (text + coverage/lcov.info); opt-in, never in PR CI
bun run check:coverage # per-directory line coverage from lcov (--strict gates on MARINA_COVERAGE_MIN_LINES, default 75)
bun run check:versions # every package.json must match the root version
bun run check:overrides # audit root `overrides` (--strict to gate, --offline without registry)
bun run clean          # Reset database and scratch files
cd dashboard && bun run test  # Frontend tests (vitest)
```
Single Bun workspace: one root `bun install` covers `dashboard`, `site`, `marina-desktop`, `examples/*`, `src/sdk` (extensions/* are excluded on purpose — native deps, own lockfiles). Isolated linker: declare every import in the member's `package.json`; transitive deps are not resolvable. Tests: no real sleeps ≥ 500 ms — poll with `until()` from `test/helpers.ts`; a new empty `catch {}` fails `test/lint-no-empty-catch.test.ts` (opt out with `// allow-empty-catch: <reason>`); `lean-agent-adapter.ts` logs through `Logger`, never `console`. No server code under `src/**` may use `console.*` either (`test/net-logging.test.ts`; excepted: the `src/sdk/` client package, the Logger sinks, `import-process.ts`'s stdout result line, and the boot banner in `src/main.ts`) — log through a module `Logger` with the module's category (`ws`, `mcp`, `telnet`, `discord`, `telegram`, `feed`, `main`). `test/docs-contract.test.ts` additionally asserts the POSITIVE contract: every safety gate is in `docs/architecture/civic-substrate.md`, every builtin resolves to `src/engine/commands/` and is documented, migration versions are contiguous, every architecture page is linked, every `MARINA_*` in `config/environment.reference` is read and every `MARINA_*` read in `src/`/`scripts/`/`worlds/` is in the reference or `ENV_VARS_OUTSIDE_SERVER_CATALOG`, `.env.example` ⊆ reference, and `docs/reference/environment.md` is freshly generated — fix the doc or the named allowlist, never the assertion. Coverage is opt-in and non-blocking; bun's own `coverageThreshold` is per-file and unusable as a repo floor, so the floor lives in `scripts/check-coverage.ts` (see docs/guides/testing.md).


WebChat is a composition root: `ChatInputBar` owns drafts/history/login, `ChatMessageList` owns transcript/timeline rendering, `ChatStatusOverlay` owns inspection views, and `chat-state-reducer.ts` maps perceptions to transitions without transport side effects. Preserve the shared command and context paths when changing these boundaries.

`bun run test:mutation` gates cache/admission contracts; `bun run check:model` checks the bounded MCP session specification in `specs/`. Context p99 CI compares the same workload against base/candidate code (see docs/guides/testing.md).

## Code Style
- **Documentation placement**: all research, plans, strategy, competitive analysis, internal audits and qualification reports belong in the private `marina-internal` repository. Public documentation should contain user guides and reference material. Reusable source code, tests and qualification tools can remain public; save their internal reports outside this repository. Archive existing research before replacing its public copy with a documentation pointer; do not rewrite Git history as part of routine documentation cleanup.
- **Formatter**: Biome — line width 100, indent 2 spaces
- **Imports**: alphabetical by path (biome organizeImports)
- **Types**: branded `EntityId`, `RoomId` — cast in tests: `"e_1" as EntityId`
- **Entity properties**: use `KnownProperties` interface — typed optional fields for rank, quest state, benchmarks, etc.
- **Errors**: use `getErrorMessage()` for extraction, `tryLog()` for non-critical DB ops
- **DB table**: `groups_` not `groups` (SQL keyword)
- **Memory tiers** (migration 37): every note has `tier ENUM('fact','reflection','skill','core','process')`. `recall*` helpers default to fact-like tiers; `process` is excluded unless `includeProcess: true`. `[compaction]`-prefixed notes auto-infer to `process`. `createNote` dedups on exact `(entity, note_type, content)` within fact-like tiers through `numeric_notes` so native revisions participate in deduplication. Per-entity `process` cap = `PROCESS_TIER_QUOTA` (500), evicted on write when over cap.
- **FTS5**: add insert/update/delete triggers when creating FTS tables
- **Tests**: use helpers from `test/helpers.ts` (MockConnection, stripAnsi, cleanupDb). `createTestEngine()` in `test/engine-fixture.ts` owns an isolated in-memory world; always await `dispose()`. Use disk storage for WAL/reopen tests. Scope profile, rate-limit bypass and selected environment overrides with `using state = scopeProcessState(...)` from `test/process-state.ts`; restore prior state, not assumed defaults. Keep scopes serial or nested within each worker; an engine fixture does not isolate process-wide state. Property tests support `FC_SEED`, `FC_RUNS`, `FC_PATH`; see docs/guides/testing.md.
- **Dashboard animations**: motion (`motion/react`) — use `<AnimatePresence>` for mount/exit, `motion.*` for declarative anims, `useMotionValue` + `useTransform` for realtime-driven values without React re-renders, `layoutId` for shared element transitions. See `dashboard/src/components/AnimatedNumber.tsx` for the count-up pattern.

## Architecture Rules
- Commands: one file per command in `src/engine/commands/`, register in `src/engine/command-registry.ts` → `registerBuiltinCommands()`
- **Argument conventions** (`src/engine/parse-input.ts`, 2026-09-22): one modifier grammar — `parseModifiers(tokens, spec)` accepts `key:value` (canonical, shown first in usage), `key=value`, `--key value`, `--key=value`; a standalone `--` ends modifier parsing (`splitOnTerminator`). Durations go through `parseDuration` in `format-duration.ts` (`s m h d w mo`; `market` passes `{ minUnit: "h" }` to keep its documented `mo`-months / no-minutes semantics). Subcommand verbs normalize through `canonicalSub(sub, allowed, { noAlias? })` with families `list/ls`, `show/info/view`, `delete/remove/rm` — pass `noAlias` for commands whose bare form takes free text (`note` exempts `rm`/`remove`). `unknownSubcommand(name, sub, usage)` is the shared default-branch reply. Legacy spellings (`--kind X`, `--ttl=30s`, `formation=f -- goal`, `!pN`, `importance 7`, `confidence 0.9 source URL`) all still parse.
- **`code` command layout**: `src/engine/commands/code.ts` (~670 lines) is the entry — `CommandDef`, modal routing, LAYER-0 telnet refusal, no-code-root refusal, the imperative `code.exec` gate, and a `SUBCOMMANDS: Record<string, SubcommandHandler>` dispatch table (80 keys, aliases share handlers, `Object.hasOwn`-guarded); bodies live in `src/engine/commands/code/{shared,profiles,workspace,artifacts,stream,crew,session,driver,spawn,exec,files,sandbox,project,service,task-run}.ts` (strict DAG; `shared` is the root; no `code/*` imports `code.ts`). `code.ts` re-exports `codeCommand`, `isLoopbackConnection`, `CodeDeps`. Security ordering stays top-to-bottom in the entry file.
- Migrations: append to `FORWARD_MIGRATIONS` in `src/persistence/schema.ts` (re-exported as `MIGRATIONS` by `database.ts`), never modify existing migrations. Fresh databases install the generated schema-137 baseline atomically; immutable pre-baseline SQL lives in `schema-history.ts` for existing-database upgrades. Verify baseline generation with `bun run schema:check`.
- **Row retention** (`src/engine/retention.ts`, hourly tick phase 2100, `runRetentionPass`): declarative `RETENTION_POLICIES` per table class — add every prunable table there; `chronicle`, `entity_standing`, `memory_resolutions`, `economic_events` are `append-only` and are never pruned (an override cannot re-enable it). `MARINA_RETENTION_OVERRIDES="table=30d,table2=0"` (0 = never). Missing tables/columns are skipped, not errors. → docs/architecture/persistence.md
- **Durable keys (migrations 109, 117, 118)**: ledgers and membership tables are keyed by the durable world account `users.id`, not the transient entity id; `MarinaDB` delegates resolve `durableEntityKey()` on write and project back to the LIVE entity id on read (`liveEntityIdSql`), so callers keep passing entity ids (ids with no account pass through unchanged — tests can still use `"e_1"`). Migration 119 closes the last two (`board_posts.author_id`, `macros.author_id`) — no entity-keyed column is still transient. `approveSubmission`, `deleteNote`, and `deleteUser` (cascades standing/competence/witness rows) are transactional. → docs/architecture/persistence.md
- **Command phase**: commands run through a per-entity promise chain (one entity strictly FIFO, entities interleave) under `COMMAND_PHASE_BUDGET_MS` (150 ms); a throw before a handler's own try lands on the tick error path, never as an unhandled rejection. Room command wrappers RETURN the handler's promise. Every ingress (telnet, Discord, Telegram, MCP, WebSocket, dashboard, auto-bootstrap, `look`/`brief` housekeeping, challenge re-runs) goes through `engine.dispatchCommand()` (admission + FIFO; resolves `false` on capacity); `processCommand()` executes NOW and is only for work already inside the entity's slot — `dispatchCommand` detects that slot (AsyncLocalStorage) and runs inline, so macro/`batch` expansion never waits on itself. A rejected async handler is a failure (no quest progress, failed activity/usage, no `command` event). Macros expand in-slot, bounded by `MAX_MACRO_DEPTH` (8), cycle detection and `MAX_MACRO_EXPANSIONS` (100), one rate-limit token per expanded command. Async tick jobs never overlap themselves and, with `engine.trackBackground()` work (evolve trials/replication), are drained by `engine.shutdown()` before the DB closes (bounded by `BACKGROUND_DRAIN_TIMEOUT_MS`). → docs/architecture/persistence.md
- **Migration 118** rekeys `groups_.leader_id` / `tasks.creator_id`; **migration 119** rekeys `board_posts.author_id` / `macros.author_id` (`BOARD_POST_COLUMNS` / `MACRO_COLUMNS` project the live id back; `macro` lookups resolve the durable key) — none left transient. **Migration 120** adds `agent_configs.thinking_level` (NULL = unset) so `agent spawn … thinking:<level>` / `agent config <name> thinking <level>` survive the boot-time respawn. `note conflicts` never pairs a note with its own durable twin; retired records' source excerpts are not served in `[evidence]` (`servableSourceIds`). → docs/architecture/persistence.md
- DB modules: query logic split into `src/persistence/db-notes.ts`, `db-entities.ts`, `db-tasks.ts`, `db-channels.ts`, `db-agents.ts` — MarinaDB delegates to standalone functions
- **Store interfaces**: `src/persistence/interfaces/` has one explicit interface per `db-*.ts` domain (`NotesStore`, `TasksStore`, … 51 in all); `MarinaDB implements MarinaStores` and is a thin facade (constructor, migrations, `durableEntityKey()`, one-line delegates — no inline SQL). Adding a delegate means: query in the module, one-line delegate on the facade, method added to the interface AND its `*_STORE_METHODS` tuple — `ExactKeys` and `test/persistence-interfaces.test.ts` (prototype-reflection drift check) fail until all agree. Consumers may type dependencies as a store slice instead of `MarinaDB`. → docs/architecture/persistence.md
- Command discovery: put `category`, `help`, and structured `usage` on `CommandDef`; `command-manifest.ts` generates help, the agent roster, dashboard forms, and MCP discovery. New world commands need no separate MCP schema. `capabilities { command, syntax, expose: true }` publishes a focused typed tool from those same fields; `invoke` executes any declared form. Both revalidate the live form inside the session command queue.
- MCP modules: `mcp-server.ts` owns transport/auth/lifecycle; `mcp-session.ts` owns the rate-limited execution queue and context delivery; `mcp-world-tools.ts` generates participation tools; `mcp-named-tools.ts` holds frozen compatibility contracts; `mcp-memory-tools.ts` holds the portable service bridge. New commands use CommandDef, not another named schema. Use `runCmd()` / `cmdTool()` for execution. Existing named tools preserve their parameter contracts. Automatic context uses an explicit task or the resident's own saved goal, rebuilds with current access, and never turns an enrichment failure into a failed world action.
- MCP tool categories: bootstrap (login/auth), cognition (think/memory/next/brief/quest), world, coordination, canvas (canvas), building, escape hatch (command/batch), session
- Engine boundaries: `AuthCoordinator` owns login/reconnect, rank restoration and eviction; `CommandPhaseCoordinator` owns modal routing, rank/gate checks, handler execution and usage/quest accounting; `CommandCoordinator` owns admission/FIFO/drain. Hosts are explicit interfaces, not Engine references. `ConnectionManager`, `EventLog`, `BriefManager`, `RoomTickCoordinator` and `TickScheduler` own the other extracted lifecycles.
- Room handlers get `RoomContext`, built-in commands get `CommandContext` (extends with mcp/http/notes/memory/pool)
- `minRank` on `CommandDef` is the permission gate — don't add custom rank checks in handlers
- Command queue: per-entity round-robin processing (fair-share scheduling)
- Tick budget: `RoomTickCoordinator` limits the synchronous room phase to 200ms; pending async handlers never overlap themselves and are drained before database shutdown.
- Non-critical DB operations should be wrapped in `tryLog()` or `tryLogAsync()`

## Civic Substrate — Standing, Rank, and Safety Gates
- `standing` is the only contribution score (`src/agent/standing.ts`; exponential decay, 60-day half-life, floor at 0 — no negative scores). Rank 0–4 is derived from standing thresholds 5 / 15 / 40 / 100 and is *descriptive*; above rank 4 standing does NOT auto-promote — capability is gated by per-operation **safety gates** (`src/engine/safety-gates.ts`, 14 gates), each requiring sufficient standing AND an unsupervised `entity_competence` row. Operators bootstrap via `safetyGates.grant(db, entityId, gateId)` from world seeds — no rank shortcut. `applyRankProgression()` is a pure threshold lookup, no metric scoring.
- All enforcement sites call `checkGateForExecution` + `recordGateExecution` (never bare `checkGate` — the site lint test enforces this). `MARINA_AUTONOMY=guarded|earned|open` is env-only by design — never settable in-world; `open` never passes `OPEN_POSTURE_CORE` (`key.manage`, `admin.destructive`, `shell.exec`, `code.exec.unrestricted`, `world.code`), and `open`+public+passwordless is a fatal boot error. Self-witnessing/self-attestation is always refused. `code.exec.unrestricted` is NEVER in `RANK_GATES` — not even a sovereign gets it from rank. Self-improvement is by succession (`src/engine/role-guard.ts`): no one edits/deletes/reloads the role they run on (nor `trait delete` inside it, nor `agent config <self> role`) — refused in every profile; they `role create <role>-v2` (rank 3, no safety gate) and `agent spawn` an improved iteration; changing an EXISTING role/trait takes `role.edit`. The loop (Phases 1–4): `evolve trial` (child/parallel world only, held-out split, Agresti–Caffo interval) → `evolve decide` → `evolve replicate` / `evolve adoption` (both behind `earnedWin`: interval > 0 AND fishing margin) → parent `world adopt` (pending → approve by someone else, `role.edit` for `into:`, rollback) — `src/engine/evolution-trial.ts`, `src/world/adoption.ts`.
- Trust profile (`src/engine/trust-profile.ts`, `MARINA_PROFILE=local|shared|public`): `isLocalProfile()` drives performance defaults; `isLocalUngated()` (local **and** `MARINA_AUTONOMY` not explicitly `guarded`) drives permissions. In-process default before `main.ts` resolves is `shared`, so tests keep exercising gates (opt in with `setTrustProfile("local")` + `resetTrustProfileForTests()`). Never off in any profile: exec-decision audit, cognitive ledger, memory receipts, trusted/unverified labels, untrusted framing, `assertTrustProfileSafe`.
- Imperative gate sites (the router handles `CommandDef.gate`, see next bullet): `agent.spawn`, `code.exec`, `role.edit` (`checkRoleEdit`), `shell.exec` for `run raw` and `connect add … stdio` (`shellExecRefusal` in `commands/run.ts`), and `code.exec.unrestricted` (the headless exec approver — the one allowlisted bare-`checkGate` site). A room command that shadows a builtin runs under its own (empty) definition, never the builtin's `minRank`/gate (`CommandRouter.resolveCommand`). Exec approver (`src/coding/exec-approver.ts`): the `code` allowlist is the default; an `ExecApprover` is attached per-call to `LocalWorkspace.run`, never global; LAYER 0 in `code.ts` (before the `code.exec` gate check) refuses host exec entirely over telnet; every approve/deny writes an `exec_decision` artifact + event.
- `CommandDef.gate` is checked by the router INSTEAD of `minRank` in every posture — the gate is the single authority (`{ minRank: 5, gate: "<id>" }`); inline subcommand rank floors go through `rankFloorRefusal` (`src/engine/rank-floor.ts`: passes under local/`open`, otherwise refuses + raises a challenge; `{ core: true }` for a floor guarding a path into the core — `rank` set, `shell allow|deny` — which `open` does not lift) — never a bare `getRank(…) < N`; `gate grant|revoke|list` passes gates on without escalation. The current command and its armed challenge pass are scoped per execution (`runCommandScope`, AsyncLocalStorage), so nested or interleaved commands never clear an outer approval.
- **Challenges, not walls** (`src/engine/challenges.ts`): a rank/gate refusal or a decision-gate `ask` notifies the requester's creator + admins with a token and returns AT ONCE — nothing ever waits on a person (no tool call, command or tick blocks); `challenge approve <token> [once|always]` re-runs the held input via a single-use pass (`src/engine/gate-context.ts`, `mode: "approved"`). Approvers must hold the authority themselves (admin, or creator holding rank + gate); self/child answers refused; `always` = grant (core gates: admin only). Answers are labels (`challenge_outcomes`, migration 139); `MARINA_CHALLENGE_JUDGE=observe|on` — the judge auto-approves only classes it has EARNED (≥ 25 approved allow calls, Wilson LB ≥ 0.85, every 10th audited), never core, never `always`/deny. → docs/architecture/civic-substrate.md
- Flywheel sandbox: Marina owns identity, policy, approvals, Code Mode, artifacts, audit; Flywheel owns isolated execution. Never silently fall back from requested sandbox execution to host execution or imply host/guest file coherence.
→ docs/architecture/civic-substrate.md

## Chronicle — Canonical Record of the Marina
Append-only civic history (`chronicle` table, `src/persistence/db-chronicle.ts`). `event` entries are engine-emitted and immutable; a `correction` supersedes a prior narrative/digest and the original is never touched (`chronicle correct` refuses `event` entries). Write commands are Chronicler-only (`properties.role === "chronicler"` or the entity's agent config role is `chronicler` — i.e. an agent spawned/configured on the `chronicler` role); `chronicle record` requires ≥1 ref. Citation flows standing (`chronicled`, idempotent via `ref=chronicle:<id>`; needs the `resolveEntityIdByName` dep). → docs/architecture/chronicle.md (design note: docs/chronicle.md)

## Worlds and Room Agents
World definitions in `worlds/` export a `WorldDefinition`; `MARINA_WORLD` selects one (default `default`). `WorldDefinition.seed?(db)` runs once on first boot and must be idempotent. Room agents spawn lazily in room `onEnter` via `ctx.spawnRoomAgent()` — never on tick — use model `marina/default` (the local `/v1/chat/completions` endpoint) and authenticate with the auto-generated internal token (no `MARINA_OPEN_API` needed); with no upstream API keys rooms fall back to static entities. Seeded/saved agents respawn on boot when `AGENT_AUTORESPAWN` is unset only under the `local` profile with a usable provider (`src/engine/auto-respawn.ts`); explicit `true`/`false` wins. → docs/architecture/worlds.md

## Agent Cognitive Architecture
Agents are autonomous from birth, not assistants ("You think, therefore you are here"; "Write for the minds that come after you"); they learn the world through quests and exploration, not prompt injection, and every turn either acts in the world or rests deliberately (`memory set rest <why>`). The harness OFFERS loop instruments rather than imposing rules — rest, `channel_sends`, `focus_persistent`, crew-responder `autonomy full` (`src/agent/loop-preferences.ts`), 75 % warnings before per-run caps; the reference monitor blocks policy language only on consequential calls with untrusted context. System and continuation prompts (`src/agent/prompts/lean-system.ts`, `src/agent/lean-agent-adapter.ts`) stay code-driven by design — the role section is the editable surface (traits/roles at rank 3; a role may replace OPERATING LOOP / HOW TO BE / EVERY TURN only under `earned`/`open` or local-ungated — AUTHORITY AND TRUST never; propagate via `agent config <name> role <r>` or `role reload <name>`; `saveTrait`/`saveRole` record history only when the serialized definition changes). Role metadata *informs* — it never controls; PRISM task gating (`filterTraitsByTask`) is conservative: no inferred category or no declared scope ⇒ trait kept, `domains` alone never suppresses, `activation: ["always"]` is never gated out, and no shared seed trait is task-gated. Prompt budget: system prompt ≤ `LEAN_SYSTEM_PROMPT_BYTE_CAP`, continuation prompt uses `continuationPromptBudgetBytes` (6000–16000 bytes by effective window, or `MARINA_CONTINUATION_BUDGET_BYTES`) with mandatory sections first and overflow events re-queued, not dropped; the `marina/default` proxy model reserves `DEFAULT_CLOUD_MAX_TOKENS`, NOT `localOutputBudget`. `InterruptibleWaiter` wakes only the cycle-delay sleep — rate-limit backoffs intentionally stay on the non-wakeable `sleep()`. All cognitive features are platform commands accessible to any agent (internal, MCP, WebSocket, telnet). → docs/architecture/agent-cognition.md
- **pi-agent-core ≥ 0.87 (2026-09-24)**: the system prompt and tool declarations are `system` messages INSIDE the transcript (`agent.state.systemPrompt` is a read-only replay). Change the prompt only via `setSystemPrompt` / `replaceSystemPrompt` (swaps the leading message in place — one base prompt, byte-stable); `createContextManager` never compacts, summarizes or drops `system` messages and returns the original array when unchanged; the continuity journal skips them; the per-prompt turn cap is `finishTurn` (not the removed `shouldStopAfterTurn`).
- **Thinking + tool ordering (2026-09-22)**: `thinkingLevel` resolves explicit → crew responder `off` → `MARINA_AGENT_THINKING` (default `off`); thinking on ⇒ `temperature`/`top_p` omitted for Anthropic. World-mutating tools are stamped `executionMode: "sequential"`; read-only tools stay parallel (`MARINA_TOOL_EXECUTION`). → docs/architecture/agent-cognition.md

## Memory Architecture — Canonical Records and Compatibility (read before touching memory code)
- **One canonical record history**: fact/reflection/skill memory is stored as versioned records in the durable repository (`src/persistence/db-memory-service.ts`). Numeric commands and `/mem/*` are synchronous adapters (`db-memory-numeric.ts`), never a second writable store. Numeric `notes` rows retain address/owner/pool metadata with empty content; `numeric_notes` is a read-only view of the canonical version. `memory_note_projections.version = NULL` follows current; superseded numeric addresses pin historical versions. Process/core journals and `memory kv` keep their distinct semantics.
- `trusted` is strict everywhere: it never silently falls back. One retrieval surface — `buildUnifiedContext` (`src/memory/unified-context.ts`), five fixed-order tiers within a byte budget; same fixture ⇒ same tiers on every surface (continuation §4, `recall <q> all|evidence`, `GET /mem/context`, MCP `think{action:"context"}`, passthru injection — `test/unified-context.test.ts`). `servableRecord` drops `resolve` losers and historical versions from `[evidence]`.
- **New memory features write canonical records** through `residentMemoryOperation`, `CommandContext.durableMemory.run`, or the extension caller's `durableMemory.run`. `/mem/*`, `note`, and `ctx.notes.add` are deprecated for new integrations; existing numeric IDs, tiers and pool semantics remain supported. Read-only compatibility identity/provenance helpers live in `legacy-projection.ts`; readers must not import the replay worker.
- **Atomic numeric writes**: create/correct/delete/source/verify/link/consolidate commit through the canonical repository in the same SQLite transaction. No write outbox, asynchronous bridge or retry worker remains. A failed canonical write fails and rolls back the numeric operation. Canonical versions use `db-note-storage.ts`; ordinary writers use `db-notes.ts`. Never write content into a bound numeric handle or bypass the canonical repository.
- **Upgrade and access** (migration 138): convert existing fact-like notes, provenance, verdicts, links and pending retirement intents before dropping the historical outbox; failure rolls back the schema and data conversion together. Numeric IDs, canonical IDs/history, owner/pool ACLs and explicit erasure remain intact. Source URLs cannot establish identity. Accountless server namespaces have separate system owners, never automatically claimed by a later human account. `isServiceMemoryNote` fences physical version IDs; numeric handles are owner/pool-scoped. `note delete` retires; durable `forget` erases. New text clears prior verification. Institutional publication is explicit independent content, never a private write binding.
- Continuity contract (`src/agent/durable-memory.ts`): every completed message is journaled before the loop advances; a failed archive aborts compaction (`ContextPersistenceError`) rather than dropping history. `resolve` losers get `valid_time` closed and stay readable — never deleted; every resolution is an append-only audit row; recency ordering breaks ties by write order (`currentWriteOrder`), never by `version` or UUID. Writer standing weights SHARED retrieval only — an entity's own notes are NEVER weighted by its own standing; adopted summaries inherit the LOWEST authority of their inputs. Dispatch debounce stamps are durable (`core_memory` owner `memory:dispatch`, keyed by entity NAME). Retrieval is lexical by default; hybrid/embeddings are OFF and evidence-gated. `MARINA_DB_DURABILITY` defaults to `full`, except `normal` under the `local` trust profile. `memory kv` is the canonical home of core key-value beliefs.
→ docs/architecture/memory.md

## Orchestration Patterns
All 10 patterns are convention-based pool notes discovered via `recall`, not engine constraints (`src/world/templates/orchestration.ts`; activated via `project <name> orchestrate <pattern>`; "NSED" is the legacy name for Deliberation — accepted, never advertised). Formation mediators post at most one `[formation-mediator]` line per event. → docs/architecture/orchestration.md

## Dashboard, Canvas, and Memory Observability
Every mutation at the DB write site emits one `EngineEvent` (`note_created`, `note_link_created`, `feed_event`, `canvas_edge_created`, …) that dashboard stores subscribe to. Canvas intent data lives in the node's `data` JSON as `{ intent: { prompt, status, … } }` — no schema changes. `memory_job` / `memory_service_event` broadcasts carry no content (no task/answer/citations); content is always fetched per-principal over REST, scoped server-side by `memoryObserverScope`; job cancel runs through the REQUESTER's resident binding and refuses the dev-open sentinel. GlassPanel section headers deliberately do NOT use the `title` prop (it is the react-grid-layout drag handle). ## Resolvers, Watchers, Calibration, TabH2O
A resolver (`src/resolvers/types.ts`) is pure: reads external state, returns a typed `Sample`, never mutates engine state, never emits events; all five entry points converge on the same `resolve()`. `resolved`/`changed` samples land in tier `fact`; `no-change`/`error` land in `process`. Watch specs are notes in the shared `watches` pool — no new table. Calibration finders register via `registerCalibrationFinder()` (`src/resolvers/calibration.ts`); new prediction methods close their own loops with their own finder. `position` invariants are enforced at the data layer, not via prompt (bankroll > 0; no self-hedge on a ticker; single position ≤ bankroll cap; daily-loss floor on close-realized losses); live trading needs `MARINA_TRADING_ENABLED=true` + venue credentials, paper is the default. → docs/architecture/resolvers.md

## Harness Decisions
Cheap per-step judgement calls (`src/decisions/`): a decision backend answers `noul` / `choice` / `score` questions with numbers only; PURE policies in `policy.ts` turn them into verdicts (gate fails CLOSED, router fails OPEN to the powerful tier, verifier accepts on outage). Backends are pluggable — `decisions-api` (Jev family / OpenJev), `typesafe` (TypeSafe's `/v1/systemone`) or `chat-classifier` (any chat model) — and every reply passes `normalizeAnswers`; HTTP answers go out via `toWireAnswers` in TypeSafe's complete shape so `langchain-typesafe` can point `TYPESAFE_BASE_URL` at Marina (`/v1/systemone` alias). OFF by default (`MARINA_DECISIONS`, `MARINA_DECISION_GATE`); set in the env or by an OPERATOR at runtime (`src/decisions/settings.ts`: `admin decisions set …` / Admin → Ops → Decisions → Settings; a person needs rank 5 + `admin.destructive`; an AGENT needs the earned `decisions.configure` gate — never admin.destructive alone, never self-witnessed, passed under `open` — via `decision settings set …`; a boot env var wins and locks the setting; base URLs, paths and API keys are env-only; every change audited). The pi tool gate runs AFTER `mediateToolCall` and only for `mutate`/`consequential` risk; it sends the redacted tool call plus the agent's operator-set intent and trust LABELS (`MARINA_DECISION_GATE_CONTEXT`, adds the `unauthorized` question), never the transcript, and can only restrict. `model:route` resolves once at spawn (persisted, never mid-history); `MARINA_DECISION_VERIFY` bounces a weak `task submit` at most once (advisory — approval still decides; under `earned`/`open` posture `on` acts as `observe` and never bounces). Providers declare `calibrated`; a chat-classifier backend gets `UNCALIBRATED_GATE_POLICY` (one cut at 0.5, positives go to the owner, never a fine threshold). `POST /v1/decisions` serves any harness; `agent_decision` events carry the numbers, never arguments. Agents reach for the same primitive themselves — `decision check` (self-verify a draft) / `decision choose` / `decision qualify` (the labeled cases in `src/decisions/decision-cases.json` against the world's own backend only, rate limited) / `decision agreement` (judge opinions in `judge_observations` vs creators' verdicts, per `<kind>:<model>`; `MARINA_DECISION_VERIFY=observe` records without acting; an outage is opinion `none`, never a pass) — advisory only, never blocking or rewarding; cited `note:N`/`task:N`/`chronicle:N` become `grounded` evidence (`src/decisions/evidence.ts`, access = the citer's). → docs/architecture/decisions.md

## Signal discovery
`src/arena/discovery/`: signals are DATA in a fixed language (`signals.ts`: centre × spread, leakage-free primitives), never code. The loop (`loop.ts`) splits a family's clean resolved rounds BY TIME, shows the proposer only discovery scores (never holdout — `test/arena-discovery.test.ts` asserts it), promotes only on a holdout win over the incumbent by `promotionMargin(tried)` (grows with attempts) without losing on discovery, and records every scored attempt as an `arena-discovery` note. `discovered` forecaster = best promoted signal per family, else the nowcast.

## Forecasting any question
`src/forecast/` generalises the arena's research pipeline to any question: retrieve → mechanical citation check (`NO_FETCH_DOMAINS` honoured) → one analyst per vendor → Jev judge on verified lines → log-odds / weighted-mean aggregation. Surfaces: `bun run forecast "<q>"`, the rank-0 `forecast` command (per-entity rate limit — every call costs money), `POST /v1/forecast` (model-API auth; error code `forecast_unavailable` without `OPENROUTER_API_KEY`). The answer object is the audit trail — keep every stage in it. → docs/guides/forecasting.md

## Social Simulation Arena
Marina can be a signed participant in the MIT Social Simulation Arena (`src/arena/`, docs/guides/arena.md). Env-only and OFF by default (`MARINA_ARENA_ENTRANT`, `MARINA_ARENA_KEY_FILE` mode 0600 or refused); filing is an operator act (`bun run arena`, hourly `arena-autopilot` tick job at phase 1500) — the in-world `arena` command is read-only. `protocol.ts` is a byte-exact port of the arena's `signed_forecasts.py` (golden vector in `test/arena.test.ts` — never change it without re-deriving it from the arena's code). The baseline keeps persistence's mean and picks sd per series (RMS or median-based) only when its own history beats the arena's fixed sd 1.5 by ≥ 5 % on the MEAN OF PER-ROUND SKILL — the leaderboard's metric, never total CRPS (a wide spread wins spiky totals and loses most weeks); otherwise exact persistence. `MARINA_ARENA_FORECASTER=model:<provider/model>` shrinks a model's answer toward the baseline; `crew:<m>[,<m>,<m>]` runs statistician/analyst/skeptic roles (one vendor each) with deterministic aggregation (the skeptic only shrinks) and per-series lesson notes (`arena-crew`, type `lesson`) written only after a round is published. `bun run arena evaluate` scores forecasters on resolved rounds (lock order, no outcome before its release) before any switch. `nowcast` reads the arena's Civiqs daily snapshots — only those FETCHED at or before the lock (Civiqs revises nightly) — and Wikipedia daily lists PUBLISHED before it (≥ 2 days before the lock day; final once published, archive partly backfilled). Profile/ranking scoring (`score-shapes.ts`) is a byte-faithful port of the arena's energy score (sha256 point set, Acklam quantile) and RBO; keep it matching `test/arena-score-shapes.test.ts`. `research:` = brief → retrieve → mechanical citation verification → analysts (use other sources for CHANGES, never levels; the benchmark history is authoritative) → Jev judge on verified lines only; web research is measured in SHADOW only (`arena_shadow`, migration 128), never backtested. `arena_submissions` (migration 127) is append-only; a round with an accepted forecast is never re-filed; a transport failure re-sends the SAME signed request within 240 s.

## Execution Traces & Adaptive Routing
Every model-API request mints `{runId, traceId, spanId}` (`requestTrace()`), emits `model_request_lifecycle` events, and returns the id in `x-request-id` (the id for `trace show`); agent events carry the optional trace fields on the `EngineEvent` union; `projectTraces` (`src/engine/trace-projection.ts`) is the single span-tree projection for every consumer. `trace_judgments` (migration 71) is append-only. ## Security & API
- **Daily spend cap (`src/engine/spend-ledger.ts`, migration 131 `spend_daily`)**: every upstream dollar is recorded ONCE where it leaves Marina — `/v1` passthru `finish("completed")`, an agent turn's OWN provider cost (never the proxy header), the metered decision provider (`providerFromConfig`), `modelComplete` / the web retriever. An agent turn on a model pi-ai cannot price uses the Marina default-model list price (`src/agent/provider-cost.ts`), else the provider's reported `usage.cost`. `MARINA_DAILY_SPEND_CAP_USD` (UTC day, process = world; default 50, `0`/`off` = uncapped, junk never lifts it) refuses `/v1` (429 `spend_cap_reached`), decisions (`spend_cap`), forecasts, priced media jobs (source `media`, migration 142), and pauses agents; child worlds get min(`MARINA_CHILD_DAILY_SPEND_CAP_USD` default 50, parent cap). A new spend site must call `recordSpend` + `dailyCapRefusal`.
- HTTP endpoints require `MODEL_API_KEYS` / `MEM_API_KEYS` or explicit `MARINA_OPEN_API=true` — dev-only, never enable in production; the `OPEN_API_ENTITY_ID` sentinel is read-only (`refuseOpenApiWrite()`, 403 on asset/canvas writes) EXCEPT under the `local` trust profile, where the loopback dev operator IS the sentinel and Canvas writes stay open (the Playwright canvas suite depends on this). All endpoints are rate-limited; every per-IP limiter goes through `clientIp(req, peer)` (socket peer unless `MARINA_TRUST_PROXY=true`), named limiters live in `HTTP_RATE_LIMITS` (`src/net/http-utils.ts`). Outbound fetches go through `src/net/url-guard.ts` (SSRF: private IPs, IPv6 loopback, link-local, cloud metadata, IPv4-mapped IPv6). Assets: MIME allowlist + magic-byte check, `nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`. MCP transport: bearer required when `MODEL_API_KEYS`/`MARINA_AUTH` is set or the bind is non-loopback; `quoteArg` REJECTS whitespace/control chars in interpolated params (the tokenizer has no quote grammar); the `flywheel` tool routes through `runCmd` so gates apply. Login limits (`MARINA_MAX_LOGINS`, `MARINA_LOGIN_ATTEMPTS_PER_MIN`) are enforced centrally in `engine.login()`/`reconnect()`; internal room/crew agents use the internal token and are exempt.
- `GATEWAY_SECRET` authenticates only the gateway *handshake* — it does **not** fence bridged-channel participation or cross-instance tells; a hard federation boundary also needs `MARINA_AUTH=better-auth` without open login. External auth is OFF by default; when off: no import, no routes, no schema effect; admins by verified email, not name. Dashboard broadcasts strip sensitive data (connectionId, raw command input).
→ docs/architecture/security.md

## Environment Variables

The canonical reference is **[`config/environment.reference`](config/environment.reference)** — the complete annotated server catalog, updated alongside code. `environmentCatalog()` (`src/config/environment.ts`) parses it for the dashboard settings editor (`src/net/dashboard-api/keys.ts`), `scripts/generate-environment-reference.ts` renders `docs/reference/environment.md` from it (`bun run docs:api`; CI checks with `--check`), and `test/docs-contract.test.ts` holds both directions. Tags in a block: `@protected` (dashboard never writes it; unions with the hard-coded `PROTECTED_ENV_KEYS`), `@internal` (hidden from the editor), `@restart` (never reported as hot-reloaded). `.env.example` is only a short commented starter and must stay a subset. Script/CI knobs live in `docs/guides/testing.md` / `release-qualification.md`, SDK example knobs in `src/sdk/examples/.env.example`. A new server variable goes in the reference in the same change. The handful below is the *load-bearing subset for understanding world shape*; if anything below conflicts with the reference, the reference wins.

- `MARINA_WORLD` — which world definition to load (`default` / `showcase` / `commons` / `research` / `markets` / `prediction-lab` / `craft` / `evolve` / `personal` / `demos` / `deep-research` / `red-team` / `due-diligence` / `data-investigation` / `empty`). Forecasting, `arena` and `market`/`position` are global commands in every world; never switch worlds (and split the `DB_PATH` ledger) for arena work.
- `MARINA_COMPAT` — comma-separated compat-profile allow-list, or `none` to disable. Default: all registered profiles (e.g. the `assistant` alias) surface in `/v1/models`.
- `MARINA_NAME` — instance name, scopes tour dismissal + seen flags per-world.
- `MARINA_ROOM_AGENTS` — `false` suppresses all room-agent auto-spawn. Use for cost-controlled demos or explicit-only populations.
- `MARINA_TRADING_ENABLED` — `true` allows live Kalshi/Polymarket order placement; paper trading is the default. Live needs `KALSHI_API_KEY` / `KALSHI_API_SECRET` (Polymarket still gated on EIP-712 signing).
- `MODEL_API_KEYS` — comma-separated Bearer tokens for `/v1/*` and Ollama-compat routes (or `MARINA_OPEN_API=true` for dev). Without either, model API rejects.
- `MEM_API_KEYS` — comma-separated `secret:agent` pairs for the Managed Memory REST endpoint at `/mem`.
- `GATEWAY_SECRET` — pre-shared key for peer Marina federation.
- `STANDING_HALF_LIFE_DAYS` — tunable, default 60. Standing decay shorter = faster reputation churn.
- `TABH2O_API_KEY` / `TABH2O_ENDPOINT` — H2O.ai's hosted tabular foundation model; endpoint override for self-hosted deployments.
