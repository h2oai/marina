# Marina — Claude Code Conventions

This file keeps only what a contributor must follow to make a correct change: build commands, code style, architecture rules, the invariants of each subsystem, and the key-file map. **Deep dives: [docs/architecture/](docs/architecture/README.md)** — design, history, measurements, and per-feature walkthroughs. Every subsystem section below ends with a pointer to its long-form page.

## Build & Test
```bash
bun run start          # Start server
bun run test           # Run all backend tests (parallel workers; `test:serial` for one process)
bun run typecheck      # TypeScript strict check
bun run lint           # Biome lint
bun run format         # Biome auto-format (run before committing)
bun run test:fast      # pre-commit loop: 139 engine-free files, ~10 s parallel (scripts/test-fast.ts --check reports drift; --serial opts out)
bun run test:shard I N # time-balanced shard I of N from test/timing.json (CI runs 3); regenerate timings per docs/guides/testing.md
bun run test:coverage  # full suite + coverage (text + coverage/lcov.info); opt-in, never in PR CI
bun run check:coverage # per-directory line coverage from lcov (--strict gates on MARINA_COVERAGE_MIN_LINES, default 75)
bun run check:versions # every package.json must match the root version
bun run check:overrides # audit root `overrides` (--strict to gate, --offline without registry)
bun run clean          # Reset database and scratch files
cd dashboard && bun run test  # Frontend tests (vitest)
```
Single Bun workspace: one root `bun install` covers `dashboard`, `site`, `marina-desktop`, `examples/*`, `src/sdk` (extensions/* are excluded on purpose — native deps, own lockfiles). Isolated linker: declare every import in the member's `package.json`; transitive deps are not resolvable. Tests: no real sleeps ≥ 500 ms — poll with `until()` from `test/helpers.ts`; a new empty `catch {}` fails `test/lint-no-empty-catch.test.ts` (opt out with `// allow-empty-catch: <reason>`); `lean-agent-adapter.ts` logs through `Logger`, never `console`. No server code under `src/**` may use `console.*` either (`test/net-logging.test.ts`; excepted: the `src/sdk/` client package, the Logger sinks, `import-process.ts`'s stdout result line, and the boot banner in `src/main.ts`) — log through a module `Logger` with the module's category (`ws`, `mcp`, `telnet`, `discord`, `telegram`, `feed`, `main`). `test/docs-contract.test.ts` additionally asserts the POSITIVE contract: every safety gate is in `docs/architecture/civic-substrate.md`, every builtin resolves to `src/engine/commands/` and is documented, migration versions are contiguous, every architecture page is linked, every `MARINA_*` in `.env.example` is read — fix the doc or the named allowlist, never the assertion. Coverage is opt-in and non-blocking; bun's own `coverageThreshold` is per-file and unusable as a repo floor, so the floor lives in `scripts/check-coverage.ts` (see docs/guides/testing.md).


## Code Style
- **Documentation placement**: all research, plans, strategy, competitive analysis, internal audits and qualification reports belong in the private `marina-internal` repository. Public documentation should contain user guides and reference material. Reusable source code, tests and qualification tools can remain public; save their internal reports outside this repository. Archive existing research before replacing its public copy with a documentation pointer; do not rewrite Git history as part of routine documentation cleanup.
- **Formatter**: Biome — line width 100, indent 2 spaces
- **Imports**: alphabetical by path (biome organizeImports)
- **Types**: branded `EntityId`, `RoomId` — cast in tests: `"e_1" as EntityId`
- **Entity properties**: use `KnownProperties` interface — typed optional fields for rank, quest state, benchmarks, etc.
- **Errors**: use `getErrorMessage()` for extraction, `tryLog()` for non-critical DB ops
- **DB table**: `groups_` not `groups` (SQL keyword)
- **Memory tiers** (migration 37): every note has `tier ENUM('fact','reflection','skill','core','process')`. `recall*` helpers default to fact-like tiers; `process` is excluded unless `includeProcess: true`. `[compaction]`-prefixed notes auto-infer to `process`. `createNote` dedups on exact `(entity, note_type, content)` within fact-like tiers (indexed by `idx_notes_dedup`, migration 122 — keep the `substr(content, 1, 64)` predicate in the query or the lookup falls back to a scan). Per-entity `process` cap = `PROCESS_TIER_QUOTA` (500), evicted on write when over cap.
- **FTS5**: add insert/update/delete triggers when creating FTS tables
- **Tests**: use helpers from `test/helpers.ts` (MockConnection, stripAnsi, cleanupDb)
- **Dashboard animations**: motion (`motion/react`) — use `<AnimatePresence>` for mount/exit, `motion.*` for declarative anims, `useMotionValue` + `useTransform` for realtime-driven values without React re-renders, `layoutId` for shared element transitions. See `dashboard/src/components/AnimatedNumber.tsx` for the count-up pattern.

## Architecture Rules
- Commands: one file per command in `src/engine/commands/`, register in `src/engine/command-registry.ts` → `registerBuiltinCommands()`
- **Argument conventions** (`src/engine/parse-input.ts`, 2026-09-22): one modifier grammar — `parseModifiers(tokens, spec)` accepts `key:value` (canonical, shown first in usage), `key=value`, `--key value`, `--key=value`; a standalone `--` ends modifier parsing (`splitOnTerminator`). Durations go through `parseDuration` in `format-duration.ts` (`s m h d w mo`; `market` passes `{ minUnit: "h" }` to keep its documented `mo`-months / no-minutes semantics). Subcommand verbs normalize through `canonicalSub(sub, allowed, { noAlias? })` with families `list/ls`, `show/info/view`, `delete/remove/rm` — pass `noAlias` for commands whose bare form takes free text (`note` exempts `rm`/`remove`). `unknownSubcommand(name, sub, usage)` is the shared default-branch reply. Legacy spellings (`--kind X`, `--ttl=30s`, `formation=f -- goal`, `!pN`, `importance 7`, `confidence 0.9 source URL`) all still parse.
- **`code` command layout**: `src/engine/commands/code.ts` (~480 lines) is the entry — `CommandDef`, modal routing, LAYER-0 telnet refusal, no-code-root refusal, the imperative `code.exec` gate, and a `SUBCOMMANDS: Record<string, SubcommandHandler>` dispatch table (79 keys, aliases share handlers, `Object.hasOwn`-guarded); bodies live in `src/engine/commands/code/{shared,profiles,workspace,artifacts,stream,crew,session,driver,spawn,exec,files,sandbox,project,service}.ts` (strict DAG; `shared` is the root; no `code/*` imports `code.ts`). `code.ts` re-exports `codeCommand`, `isLoopbackConnection`, `CodeDeps`. Security ordering stays top-to-bottom in the entry file.
- Migrations: append to `migrations` in `src/persistence/schema.ts` (re-exported as `MIGRATIONS` by `database.ts`), never modify existing migrations
- **Row retention** (`src/engine/retention.ts`, hourly tick phase 2100, `runRetentionPass`): declarative `RETENTION_POLICIES` per table class — add every prunable table there; `chronicle`, `entity_standing`, `memory_resolutions`, `economic_events` are `append-only` and are never pruned (an override cannot re-enable it). `MARINA_RETENTION_OVERRIDES="table=30d,table2=0"` (0 = never). Missing tables/columns are skipped, not errors. → docs/architecture/persistence.md
- **Durable keys (migrations 109, 117, 118)**: ledgers and membership tables are keyed by the durable world account `users.id`, not the transient entity id; `MarinaDB` delegates resolve `durableEntityKey()` on write and project back to the LIVE entity id on read (`liveEntityIdSql`), so callers keep passing entity ids (ids with no account pass through unchanged — tests can still use `"e_1"`). Migration 119 closes the last two (`board_posts.author_id`, `macros.author_id`) — no entity-keyed column is still transient. `approveSubmission`, `deleteNote`, and `deleteUser` (cascades standing/competence/witness rows) are transactional. → docs/architecture/persistence.md
- **Command phase**: commands run through a per-entity promise chain (one entity strictly FIFO, entities interleave) under `COMMAND_PHASE_BUDGET_MS` (150 ms); a throw before a handler's own try lands on the tick error path, never as an unhandled rejection. Room command wrappers RETURN the handler's promise. → docs/architecture/persistence.md
- **Migration 118** rekeys `groups_.leader_id` / `tasks.creator_id`; **migration 119** rekeys `board_posts.author_id` / `macros.author_id` (`BOARD_POST_COLUMNS` / `MACRO_COLUMNS` project the live id back; `macro` lookups resolve the durable key) — none left transient. **Migration 120** adds `agent_configs.thinking_level` (NULL = unset) so `agent spawn … thinking:<level>` / `agent config <name> thinking <level>` survive the boot-time respawn. `note conflicts` never pairs a note with its own durable twin; retired records' source excerpts are not served in `[evidence]` (`servableSourceIds`). → docs/architecture/persistence.md
- DB modules: query logic split into `src/persistence/db-notes.ts`, `db-entities.ts`, `db-tasks.ts`, `db-channels.ts`, `db-agents.ts` — MarinaDB delegates to standalone functions
- **Store interfaces**: `src/persistence/interfaces/` has one explicit interface per `db-*.ts` domain (`NotesStore`, `TasksStore`, … 48 in all); `MarinaDB implements MarinaStores` and is a thin facade (constructor, migrations, `durableEntityKey()`, one-line delegates — no inline SQL). Adding a delegate means: query in the module, one-line delegate on the facade, method added to the interface AND its `*_STORE_METHODS` tuple — `ExactKeys` and `test/persistence-interfaces.test.ts` (prototype-reflection drift check) fail until all agree. Consumers may type dependencies as a store slice instead of `MarinaDB`. → docs/architecture/persistence.md
- MCP tools: add in `src/net/mcp-server.ts` → `createMcpServer()`, use `runCmd()` helper (rate-limited wrapper around `cmdTool()`)
- MCP tool categories: bootstrap (login/auth), cognition (think/memory/next/brief/quest), world, coordination, canvas (canvas), building, escape hatch (command/batch), session
- Engine decomposed: `ConnectionManager`, `EventLog`, `BriefManager` extracted from Engine class
- Room handlers get `RoomContext`, built-in commands get `CommandContext` (extends with mcp/http/notes/memory/pool)
- `minRank` on `CommandDef` is the permission gate — don't add custom rank checks in handlers
- Command queue: per-entity round-robin processing (fair-share scheduling)
- Tick budget: room onTick handlers must complete within 200ms total
- Non-critical DB operations should be wrapped in `tryLog()` or `tryLogAsync()`

## Civic Substrate — Standing, Rank, and Safety Gates
- `standing` is the only contribution score (`src/agent/standing.ts`; exponential decay, 60-day half-life, floor at 0 — no negative scores). Rank 0–4 is derived from standing thresholds 5 / 15 / 40 / 100 and is *descriptive*; above rank 4 standing does NOT auto-promote — capability is gated by per-operation **safety gates** (`src/engine/safety-gates.ts`, 10 gates), each requiring sufficient standing AND an unsupervised `entity_competence` row. Operators bootstrap via `safetyGates.grant(db, entityId, gateId)` from world seeds — no rank shortcut. `applyRankProgression()` is a pure threshold lookup, no metric scoring.
- All enforcement sites call `checkGateForExecution` + `recordGateExecution` (never bare `checkGate` — the site lint test enforces this). `MARINA_AUTONOMY=guarded|earned|open` is env-only by design — never settable in-world; `open` never passes `OPEN_POSTURE_CORE` (`key.manage`, `admin.destructive`, `shell.exec`, `code.exec.unrestricted`), and `open`+public+passwordless is a fatal boot error. Self-witnessing/self-attestation is always refused. `code.exec.unrestricted` is NEVER in `RANK_GATES` — not even a sovereign gets it from rank.
- Trust profile (`src/engine/trust-profile.ts`, `MARINA_PROFILE=local|shared|public`): `isLocalProfile()` drives performance defaults; `isLocalUngated()` (local **and** `MARINA_AUTONOMY` not explicitly `guarded`) drives permissions. In-process default before `main.ts` resolves is `shared`, so tests keep exercising gates (opt in with `setTrustProfile("local")` + `resetTrustProfileForTests()`). Never off in any profile: exec-decision audit, cognitive ledger, memory receipts, trusted/unverified labels, untrusted framing, `assertTrustProfileSafe`.
- `CommandDef.gate` is checked by the router after `minRank` (`{ minRank: 5, gate: "<id>" }`); `agent.spawn` and `code.exec` are the two **imperatively** enforced exceptions. Exec approver (`src/coding/exec-approver.ts`): the `code` allowlist is the default; an `ExecApprover` is attached per-call to `LocalWorkspace.run`, never global; LAYER 0 in `code.ts` (before `checkGate("code.exec")`) refuses host exec entirely over telnet; every approve/deny writes an `exec_decision` artifact + event.
- Flywheel sandbox: Marina owns identity, policy, approvals, Code Mode, artifacts, audit; Flywheel owns isolated execution. Never silently fall back from requested sandbox execution to host execution or imply host/guest file coherence.
→ docs/architecture/civic-substrate.md

## Chronicle — Canonical Record of the Marina
Append-only civic history (`chronicle` table, `src/persistence/db-chronicle.ts`). `event` entries are engine-emitted and immutable; a `correction` supersedes a prior narrative/digest and the original is never touched (`chronicle correct` refuses `event` entries). Write commands are Chronicler-only (`entity.properties.role === "chronicler"`); `chronicle record` requires ≥1 ref. Citation flows standing (`chronicled`, idempotent via `ref=chronicle:<id>`; needs the `resolveEntityIdByName` dep). → docs/architecture/chronicle.md (design note: docs/chronicle.md)

## Worlds and Room Agents
World definitions in `worlds/` export a `WorldDefinition`; `MARINA_WORLD` selects one (default `default`). `WorldDefinition.seed?(db)` runs once on first boot and must be idempotent. Room agents spawn lazily in room `onEnter` via `ctx.spawnRoomAgent()` — never on tick — use model `marina/default` (the local `/v1/chat/completions` endpoint) and authenticate with the auto-generated internal token (no `MARINA_OPEN_API` needed); with no upstream API keys rooms fall back to static entities. → docs/architecture/worlds.md

## Agent Cognitive Architecture
Agents are autonomous from birth, not assistants ("You think, therefore you are here"; "Write for the minds that come after you"); they learn the world through quests and exploration, not prompt injection, and every turn takes at least one world action. System and continuation prompts (`src/agent/prompts/lean-system.ts`, `src/agent/lean-agent-adapter.ts`) stay code-driven by design — the role section is the editable surface (traits/roles at rank 3; propagate via `agent config <name> role <r>` or `role reload <name>`; `saveTrait`/`saveRole` record history only when the serialized definition changes). Role metadata *informs* — it never controls; PRISM task gating (`filterTraitsByTask`) is conservative: no inferred category or no declared scope ⇒ trait kept, `domains` alone never suppresses, `activation: ["always"]` is never gated out, and no shared seed trait is task-gated. Prompt budget: system prompt ≤ `LEAN_SYSTEM_PROMPT_BYTE_CAP`, continuation prompt ≤ `CONTINUATION_PROMPT_BUDGET_BYTES` with mandatory sections first and overflow events re-queued, not dropped; the `marina/default` proxy model reserves `DEFAULT_CLOUD_MAX_TOKENS`, NOT `localOutputBudget`. `InterruptibleWaiter` wakes only the cycle-delay sleep — rate-limit backoffs intentionally stay on the non-wakeable `sleep()`. All cognitive features are platform commands accessible to any agent (internal, MCP, WebSocket, telnet). → docs/architecture/agent-cognition.md
- **Thinking + tool ordering (2026-09-22)**: `thinkingLevel` resolves explicit → crew responder `off` → `MARINA_AGENT_THINKING` (default `off`); thinking on ⇒ `temperature`/`top_p` omitted for Anthropic. World-mutating tools are stamped `executionMode: "sequential"`; read-only tools stay parallel (`MARINA_TOOL_EXECUTION`). → docs/architecture/agent-cognition.md

## Memory Architecture — Two Systems (read before touching memory code)
- **Legacy notes** (`notes` table, `src/persistence/db-notes.ts`; `note`/`recall`/`reflect`/`pool`/`skill`, REST `/mem/*`; owner-scoped via `src/memory/access.ts`) and the **durable memory service** (`src/memory/service.ts`, `/v1/memory`, resident `memory …` commands, `src/sdk/memory-client.ts`). Durable records live in `notes` under `entity_name = memory:<principalId>` and are hidden from legacy surfaces (`isServiceMemoryNote`); legacy notes are invisible to the service. **Do not add a third store.** World commands bind to the durable **user** (`users.id`); unknown names get `world_identity_required`.
- `trusted` is strict everywhere: it never silently falls back. One retrieval surface — `buildUnifiedContext` (`src/memory/unified-context.ts`), five fixed-order tiers within a byte budget; same fixture ⇒ same tiers on every surface (continuation §4, `recall <q> all|evidence`, `GET /mem/context`, MCP `think{action:"context"}`, passthru injection — `test/unified-context.test.ts`). `servableRecord` drops `resolve` losers and historical versions from `[evidence]`.
- Legacy verbs are adapters (`src/memory/legacy-bridge.ts`): `note` twins a durable record (`note_sources` url `marina-memory://record/<id>`, credibility 0 — a twin is a mirror, not evidence, excluded from every source-derived ranking term). Bridging is fire-and-forget so `note` replies in-tick — sequence with `awaitPendingBridges()` in tests. Plain `recall` stays synchronous (Promise only for `all|evidence`) and never does a durable round-trip on the hot path. `note delete` retires the twin with a tombstone `revise`, not space-wide `forget`.
- Continuity contract (`src/agent/durable-memory.ts`): every completed message is journaled before the loop advances; a failed archive aborts compaction (`ContextPersistenceError`) rather than dropping history. `resolve` losers get `valid_time` closed and stay readable — never deleted; every resolution is an append-only audit row; recency ordering breaks ties by write order (`currentWriteOrder`), never by `version` or UUID. Writer standing weights SHARED retrieval only — an entity's own notes are NEVER weighted by its own standing; adopted summaries inherit the LOWEST authority of their inputs. Dispatch debounce stamps are durable (`core_memory` owner `memory:dispatch`, keyed by entity NAME). Both systems are lexical by default; hybrid/embeddings are OFF and evidence-gated. `MARINA_DB_DURABILITY=full` is the world default. `memory kv` is the canonical home of core key-value beliefs.
→ docs/architecture/memory.md

## Orchestration Patterns
All 10 patterns are convention-based pool notes discovered via `recall`, not engine constraints (`src/world/templates/orchestration.ts`; activated via `project <name> orchestrate <pattern>`; "NSED" is the legacy name for Deliberation — accepted, never advertised). Crew pools are members-only: every persisted crew's `crew:<name>` pool has a group object of the same id (`memory_pools.group_id`) and the group-pool ACL in `src/memory/access.ts` plus the `gatherRetrievalContext` guard are the fence; dissolving keeps pool and notes scoped to the final roster. Formation mediators post at most one `[formation-mediator]` line per event. → docs/architecture/orchestration.md

## Dashboard, Canvas, and Memory Observability
Every mutation at the DB write site emits one `EngineEvent` (`note_created`, `note_link_created`, `feed_event`, `canvas_edge_created`, …) that dashboard stores subscribe to. Canvas intent data lives in the node's `data` JSON as `{ intent: { prompt, status, … } }` — no schema changes. `memory_job` / `memory_service_event` broadcasts carry no content (no task/answer/citations); content is always fetched per-principal over REST, scoped server-side by `memoryObserverScope`; job cancel runs through the REQUESTER's resident binding and refuses the dev-open sentinel. GlassPanel section headers deliberately do NOT use the `title` prop (it is the react-grid-layout drag handle). Dashboard animations: see Code Style. → docs/architecture/dashboard.md (user guide: docs/guides/dashboard.md)
- **Ops surface (2026-09-22)**: `GET /api/ops/overview`, `POST /api/ops/agents/:name/stop` (`src/net/ops-api.ts`, contract `ops-types.ts` re-exported type-only); Admin → Ops tab, header `HealthBadge` + `SpendChip`; `light` theme + `system` choice; every icon-only button needs an `aria-label` (a11y test enforces it); never subscribe a large component reactively to `eventFeed` — use `use-event-feed-bridge.ts`. HTML routes carry `HTML_CSP` (`script-src 'self'` + hashes; `MARINA_DASHBOARD_CSP=off` to drop). → docs/architecture/dashboard.md, security.md

## Resolvers, Watchers, Calibration, TabH2O
A resolver (`src/resolvers/types.ts`) is pure: reads external state, returns a typed `Sample`, never mutates engine state, never emits events; all five entry points converge on the same `resolve()`. `resolved`/`changed` samples land in tier `fact`; `no-change`/`error` land in `process`. Watch specs are notes in the shared `watches` pool — no new table. Calibration finders register via `registerCalibrationFinder()` (`src/resolvers/calibration.ts`); new prediction methods close their own loops with their own finder. `position` invariants are enforced at the data layer, not via prompt (bankroll > 0; no self-hedge on a ticker; single position ≤ bankroll cap; daily-loss floor on close-realized losses); live trading needs `MARINA_TRADING_ENABLED=true` + venue credentials, paper is the default. → docs/architecture/resolvers.md

## Harness Decisions
Cheap per-step judgement calls (`src/decisions/`): a decision backend answers `noul` / `choice` / `score` questions with numbers only; PURE policies in `policy.ts` turn them into verdicts (gate fails CLOSED, router fails OPEN to the powerful tier, verifier accepts on outage). Backends are pluggable — `decisions-api` (Jev family / OpenJev), `typesafe` (TypeSafe's `/v1/systemone`) or `chat-classifier` (any chat model) — and every reply passes `normalizeAnswers`; HTTP answers go out via `toWireAnswers` in TypeSafe's complete shape so `langchain-typesafe` can point `TYPESAFE_BASE_URL` at Marina (`/v1/systemone` alias). Env-only and OFF by default (`MARINA_DECISIONS`, `MARINA_DECISION_GATE`). The pi tool gate runs AFTER `mediateToolCall` and only for `mutate`/`consequential` risk; it sends the redacted tool call, never the transcript, and can only restrict. `model:route` resolves once at spawn (persisted, never mid-history); `MARINA_DECISION_VERIFY` bounces a weak `task submit` at most once (advisory — approval still decides). `POST /v1/decisions` serves any harness; `agent_decision` events carry the numbers, never arguments. → docs/architecture/decisions.md

## Execution Traces & Adaptive Routing
Every model-API request mints `{runId, traceId, spanId}` (`requestTrace()`), emits `model_request_lifecycle` events, and returns the id in `x-request-id` (the id for `trace show`); agent events carry the optional trace fields on the `EngineEvent` union; `projectTraces` (`src/engine/trace-projection.ts`) is the single span-tree projection for every consumer. `trace_judgments` (migration 71) is append-only. Adaptive routing is opt-in, falls back to least-busy on insufficient evidence, and the routing hot path skips judgment fetches by design. → docs/architecture/traces.md

## Security & API
- HTTP endpoints require `MODEL_API_KEYS` / `MEM_API_KEYS` or explicit `MARINA_OPEN_API=true` — dev-only, never enable in production; the `OPEN_API_ENTITY_ID` sentinel is read-only (`refuseOpenApiWrite()`, 403 on asset/canvas writes) EXCEPT under the `local` trust profile, where the loopback dev operator IS the sentinel and Canvas writes stay open (the Playwright canvas suite depends on this). All endpoints are rate-limited; every per-IP limiter goes through `clientIp(req, peer)` (socket peer unless `MARINA_TRUST_PROXY=true`), named limiters live in `HTTP_RATE_LIMITS` (`src/net/http-utils.ts`). Outbound fetches go through `src/net/url-guard.ts` (SSRF: private IPs, IPv6 loopback, link-local, cloud metadata, IPv4-mapped IPv6). Assets: MIME allowlist + magic-byte check, `nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`. MCP transport: bearer required when `MODEL_API_KEYS`/`MARINA_AUTH` is set or the bind is non-loopback; `quoteArg` REJECTS whitespace/control chars in interpolated params (the tokenizer has no quote grammar); the `flywheel` tool routes through `runCmd` so gates apply. Login limits (`MARINA_MAX_LOGINS`, `MARINA_LOGIN_ATTEMPTS_PER_MIN`) are enforced centrally in `engine.login()`/`reconnect()`; internal room/crew agents use the internal token and are exempt.
- `GATEWAY_SECRET` authenticates only the gateway *handshake* — it does **not** fence bridged-channel participation or cross-instance tells; a hard federation boundary also needs `MARINA_AUTH=better-auth` without open login. External auth is OFF by default; when off: no import, no routes, no schema effect; admins by verified email, not name. Dashboard broadcasts strip sensitive data (connectionId, raw command input).
→ docs/architecture/security.md

## Drop-in Compatibility (Passthru)
Compat profiles (`src/net/compat-profiles.ts`) are self-contained — they only register passthru model-id aliases on `/v1/models` (`MARINA_COMPAT` allow-list or `none`). Anthropic upstream (`src/net/model-api.ts`, `src/net/anthropic-tools.ts`): join EVERY `text` block (`anthropicTextContent`), forward EVERY `system` message in order (`anthropicSystemPrompt`), omit `temperature` for Claude 5, surface upstream 4xx bodies. Unsupported parameters (`json_object`, `n>1`, non-function tools; agents mode refuses `tools`/`n`/`response_format`) → `400 unsupported_parameter` — never a silent drop or provider fallback; every error carries a string `code` (`src/net/openai-errors.ts`). A fallback-served reply must not credit the probed provider (`servedBy`) — run `readiness providers` after adding a provider or a model generation. ACP (`src/net/acp-server.ts`): stdout is reserved for the protocol, all logs go to stderr. → docs/architecture/passthru.md
- **Responses streaming (2026-09-22)** is incremental on passthru and agents mode; `formatResponseRecord` is the single source for `response.completed` and `GET /v1/responses/:id`. Responses `tools`/`tool_choice` are translated to chat tools upstream (`responses-tools.ts`); non-function tool types → `400 unsupported_parameter`. → docs/architecture/passthru.md

## Key Files

## Environment Variables

The canonical reference is **[`.env.example`](.env.example)** — annotated, treated as authoritative, and updated alongside code. The code reads ~100+ env vars across logging, ports, rate limits, per-pattern coordinator/judge/temperature overrides, and venue credentials. The handful below is the *load-bearing subset for understanding world shape*; treat it as a hand-curated overview, not a comprehensive list. If anything below conflicts with `.env.example`, `.env.example` wins.

- `MARINA_WORLD` — which world definition to load (`default` / `commons` / `research` / `markets` / `craft` / `evolve` / `personal` / `demos` / `empty`).
- `MARINA_COMPAT` — comma-separated compat-profile allow-list, or `none` to disable. Default: all registered profiles (e.g. the `assistant` alias) surface in `/v1/models`.
- `MARINA_NAME` — instance name, scopes tour dismissal + seen flags per-world.
- `MARINA_ROOM_AGENTS` — `false` suppresses all room-agent auto-spawn. Use for cost-controlled demos or explicit-only populations.
- `MARINA_TRADING_ENABLED` — `true` allows live Kalshi/Polymarket order placement; paper trading is the default. Live needs `KALSHI_API_KEY` / `KALSHI_API_SECRET` (Polymarket still gated on EIP-712 signing).
- `MODEL_API_KEYS` — comma-separated Bearer tokens for `/v1/*` and Ollama-compat routes (or `MARINA_OPEN_API=true` for dev). Without either, model API rejects.
- `MEM_API_KEYS` — comma-separated `secret:agent` pairs for the Managed Memory REST endpoint at `/mem`.
- `GATEWAY_SECRET` — pre-shared key for peer Marina federation.
- `STANDING_HALF_LIFE_DAYS` — tunable, default 60. Standing decay shorter = faster reputation churn.
- `TABH2O_API_KEY` / `TABH2O_ENDPOINT` — H2O.ai's hosted tabular foundation model; endpoint override for self-hosted deployments.
